# Phase 9 캠퍼스망 대 가정망 실측

## 왜 했나

`roadmap.md` Phase 9 테스트 환경 표의 캠퍼스망 대 가정망이다. 소유자가 학교에서 실행을 지시했다. 이 PC 는 학교 유선 LAN 에, `mere-galaxy` 는 집 Wi-Fi 에 있었다.

## 구성

시행 방법은 [2026-11-17 첫 실측](../2026-11-17/05-phase-9-상대-없는-검증과-첫-실측.md)과 같다. 같은 빌드(커밋 `5f9f710` 의 Release 콘솔), 같은 기동 인자, 같은 시행 스크립트다. 다른 것만 적는다.

| 무엇 | 값 |
|------|-----|
| 이 PC 의 망 | 학교 유선 LAN. 휴대폰 핫스팟 Wi-Fi 에도 붙어 있었다. 기본 경로는 유선 LAN 이었다(경로 우선값 25 대 50). 두 STUN 서버가 돌려준 공인 주소는 유선 LAN 의 것이었다 |
| `mere-galaxy` 의 망 | 집 Wi-Fi, Comcast. 시작과 끝 모두 Wi-Fi 절전은 꺼져 있었다(이슈 0001). 시작 전에 껐다 |
| 기록 | git 이 무시하는 `field-test/2026-11-18/campus-home/`. 묶음의 UTC 범위는 `tools/tm-analysis/local/batches.txt` 에 있다 |

묶음 직전에 같은 두 기기로 한 번 연결해 봤다. 호스트는 `~/sangtachi-head` 빌드였고, 이 PC 는 실측 빌드에 `--no-adapter` 로 들어갔다. 7.6초에 `CONNECTED` 였다. 이 시도는 묶음 범위 밖이라 분석 도구에서 "어느 묶음에도 들지 않은 시도"로 나올 수 있다. 끝난 뒤 4초 만에 첫 시행이 시작됐다. 첫 시행은 새 소켓을 써서 다른 공인 포트를 받았다.

## 결과

아래 RTT 는 이 PC 의 로그에서 본 예비 값이다. `experiments.md` 의 숫자는 분석 도구가 테이블에서 낸 값을 쓴다.

| 환경 | 결과 | 쓴 경로 | 이 PC 의 RTT 표본 |
|------|------|---------|-------------------|
| 캠퍼스망(이 PC, 학교 유선 LAN) 대 가정망(`mere-galaxy`, Comcast) | 10/10 `CONNECTED` | 10회 모두 공인 주소 | n=57, 중앙값 21.2ms, 사분위 범위 18.0~28.6ms |

- 업로드 실패는 두 기기 모두 0 이다. 두 기기의 `telemetry_upload_failed` 와 `telemetry_queue_dropped` 카운터가 모든 시행에서 0 이다
- 두 기기 모두 시행마다 STUN 서버 둘에서 같은 공인 포트를 받았다. 학교 NAT 도 지금까지의 망처럼 목적지에 따라 매핑을 바꾸지 않았다

## 시행 스크립트의 수정

`mere-galaxy` 쪽 업로드 실패를 `grep -c telemetry.upload_failed` 로 셌다. `.` 이 아무 글자에나 맞아 카운터 줄(`telemetry_upload_failed value=0`)을 세서 시행마다 3 이 나왔다. 카운터 값은 모두 0 이었다. 스크립트는 카운터 값을 읽게 고쳤다. 2026-11-17 의 두 묶음도 `mere-galaxy` 의 카운터 값을 다시 봤다. 모두 0 이라 그 기록의 "업로드 실패 0" 은 맞다.
