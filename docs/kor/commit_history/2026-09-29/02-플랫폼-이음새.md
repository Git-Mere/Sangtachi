# 플랫폼 이식 이음새를 고정했다 (ADR 0010)

## 무엇을 했나

저장소 소유자가 "다른 OS 지원은 스트레치로 두되, 나중에 옮길 수 있게 코드 구성을 해 두자" 를
물었다. 조사해 보니 **정리된 것이 없었다.** 살아 있는 문서 넷이 "안 한다" 만 적고
(`spec.md` 제외와 스트레치 목표, `architecture.md` 12장, `roadmap.md` P4), ADR 9건 중 이식을
다룬 것이 없었다. `architecture.md` 3.1 모듈 표는 이음새를 이름으로 갖지 않았고 모듈 이름
자체가 벤더인 자리도 있었다(`adapter/wintun_adapter`).

네 가지 안(무작업 / 문서만 / 이음새 고정 / 전면 PAL)을 내고 소유자가 **이음새 고정**을 골랐다.
범위는 넓히지 않는다. 다시 쓰는 자리만 이름으로 정한다.

## 결정

[ADR 0010](../../decisions/0010-플랫폼-이식-이음새.md)이 갖는다. 규칙은 하나다.

> OS 헤더를 포함하는 클라이언트 원본은 `client/src/platform/` 아래에만 둔다.
> `client/include/` 아래에는 OS 헤더가 하나도 없다.

**이음새를 세다가 넷이 다섯이 됐다.** 소켓, 대기와 단조 시계, 가상 어댑터, 기동과 권한으로
세고 있었는데 코드를 읽고 해시를 더했다. `sha256_hex` 가 `BCryptHash` 를 부른다. 옮기려면
다른 구현이 필요하고 그것이 서드파티면 `spec.md` NFR-5 의 승인 대상이 된다. 세지 않았으면
이식 견적에서 빠졌을 자리다. 같은 조사에서 `architecture.md` 11장 외부 의존성 표에
Windows CNG 가 빠져 있던 것도 찾아 채웠다.

**헤더의 의미까지 중립으로 만들지 않았다.** `udp_socket.hpp` 는 여전히 `WSAGetLastError` 의
정수와 Win32 이벤트를 내놓는다. 이름만 중립으로 바꾸면 이식된 것처럼 보이고 실제로는 아니다.
ADR 결정 3이 그 선택과 대가를 적는다.

## 코드

| 무엇 | 자리 |
|------|------|
| 이동 (내용 무변경) | `network/wsa.cpp`, `network/udp_socket.cpp`, `hash.cpp` -> `platform/win32/` |
| 신설 | `client/include/sangtachi/platform/wait.hpp`, `client/src/platform/win32/wait.cpp` |
| 고침 | `loop.cpp`, `console.cpp` 에서 `<windows.h>` 제거. `timer.hpp` 의 무한 타임아웃을 별칭으로 |
| CMake | 비 Windows 에서 `FATAL_ERROR`. `ws2_32`/`bcrypt` 를 `if(WIN32)` 아래로 |
| 시험 | `tests/platform/wait_test.cpp` 8건 |

`wait_any` 는 `WaitForMultipleObjects` 를 감싼다. 동작 보존을 하나씩 대조했다. 타임아웃 계산과
`busy_` 빠른 길, 핸들 배열의 순서와 길이, `WAIT_FAILED` 처리와 로그 토큰(`op` 문자열 포함),
수동/자동 리셋, 인덱스 매핑, 삼키는 오류, 이벤트 소유권이다.

**도달 불가 경로 하나의 동작은 바뀌었다.** `WAIT_ABANDONED` 범위다. 앞의 `loop.cpp` 는 그것을
흘려보냈고 지금은 `Failed` 가 되어 기록하고 정리 경로로 간다. 뜻을 모르는 반환값을 정상으로
읽지 않기로 했다. 근거는 `wait.cpp` 주석에 있다.

## 도구

`tools/platformgate/` 를 신설했다. 규칙을 사람이 세지 않는다. 시험 73건, 지금 레포에서
`VERDICT: pass` 다. 판정 규칙(전처리기 미평가, 이름 목록, 대소문자, 허용 자리, 확장자)은
ADR 결정 5가 갖고, 판정하지 못하는 것은 그 도구의 README 가 표로 갖는다.

## 변이 시험

`wait.cpp` 쪽 8건 중 6건이 잡혔다. 살아남은 둘을 숨기지 않고 적는다.

- **입력 검증 가드**(빈 배열, 상한 초과)를 지워도 통과했다. OS 가 같은 오류를 돌려주기
  때문이다. 케이스가 지키는 것은 가드가 아니라 계약이다. 가드는 규칙 7 대로 남겼다
- **`busy_ ? 0 :` 를 지워도 91건이 전부 통과했다.** 이번 작업이 만든 결함이 아니라 **원래
  있던 빈자리**다. 잡는 케이스를 새로 써 봤으나 그것도 변이를 통과했다. 예산으로 멈춘 뒤에도
  `FD_READ` 가 다시 신호되어 다음 바퀴가 `busy_` 와 무관하게 깨어나기 때문이다. 아무것도
  지키지 못하는 케이스라 지웠다(`loop_test.cpp` 무변경). **대기를 주입할 수 있어야 풀린다.**
  `plan.md` 에 걸었다

`platformgate` 쪽은 19건 중 17건이 잡혔다. 살아남은 둘은 출력을 바꾸지 못하는 변이이고 그
근거를 스크립트 주석에 적었다.

## 크로스 모델 리뷰 (Codex)

렌즈를 셋으로 나눠 범위를 잘라 돌렸다. **blocker 는 게이트 렌즈에서만 나왔다.**

| 렌즈 | 범위 | blocker | warn |
|------|------|:---:|:---:|
| 동작 보존 | `client/`, `tests/` | 0 | 2 |
| 시나리오 추적 + 근거 대 주장 | `docs/`, `CLAUDE.md` | 1 | 4 |
| 판정 함수 | `tools/` | **1** | 0 |

### 반영

| 지적 | 어떻게 |
|------|--------|
| **`#/**/include <windows.h>` 와 `#include/**/<windows.h>` 를 놓친다.** 표준에서 주석은 전처리 공백이라 둘 다 유효한 포함이다 | 반영. 지시자 안쪽 전용 훑기를 넣었다. 시험 59 -> 73건. **부모가 임시 트리로 재현하고 고친 뒤 다시 확인했다** |
| 새 시험이 `wait_any` 만 보고 `EventLoop` 수준 보존은 못 잡는다 | 반영. 다만 이번 범위 밖이다. 위 변이 시험의 `busy_` 건과 같은 자리이고 `plan.md` 에 걸었다 |
| ADR 은 "원본 전부" 라는데 게이트는 `.cpp` `.hpp` 만 본다. `.h` 로 우회된다 | 반영. 결정 5에 f 행을 넣어 `SOURCE_SUFFIXES` 를 먼저 고칠 의무로 적었다 |
| "기계로 확인된다" 가 과장이다 | 반영. "확인하는 것은 목록에 있는 OS 헤더 하나다. 다시 쓸 필요가 없다는 증명은 아니다" 로 낮췄다 |
| 어댑터 파일이 생긴 뒤 ADR 과 문서를 고칠 주인이 없다 | 반영. ADR 표의 칸을 "이 결정 시점의 코드 자리" 로 바꾸고 현재 배치의 출처를 `architecture.md` 10장으로 넘겼다. `roadmap.md` Phase 6 에 항목을 걸었다 |
| `roadmap.md` 가 OS 헤더 이름 목록을 베껴 적어 도구와 어긋난다 | 반영. 목록을 지우고 도구 README 로 링크했다 (규칙 5) |

### 기각

| 지적 | 왜 |
|------|-----|
| `WAIT_ABANDONED` 를 `Failed` 로 바꾼 것은 동작 변경이다 | **기각.** 동작 변경인 것은 맞다. 도달 불가 경로이고, 뜻을 모르는 반환값을 정상으로 읽는 쪽이 더 나쁘다. 기각 사유를 `wait.cpp` 주석에 적었다 |
| 문서는 파일이 `platform/win32/` 에 있다는데 diff 는 문서만 바꾼다 | **기각.** 리뷰 입력을 `docs/` 로 좁혀 보내 코드 이동이 보이지 않았다. HEAD 를 직접 확인했다. 다만 ADR 맥락이 이동 전 이름을 적고 있어 "이 결정을 쓰기 **전**" 으로 고쳤다 |

## 이번에 확인한 것

- **렌즈를 나눈 것이 값을 했다.** 게이트의 blocker 는 앞의 두 렌즈가 보지 못한 자리에 있었다.
  `CLAUDE.md` 의 "렌즈를 줄이면 토큰이 아니라 blocker 가 준다" 와 같은 방향이다
- **리뷰 입력을 좁히면 그 대가로 거짓 blocker 가 하나 온다.** 그것을 HEAD 확인으로 걸렀다.
  범위를 자르는 선택 자체는 유지한다
- **기록이 코드보다 앞서 나갔다.** ADR 에 규칙 행 하나를 넣는 편집과 다른 편집을 한 셀에
  같이 넣었고, 뒷줄의 문법 오류가 셀 전체를 막아 **앞의 편집도 들어가지 않았다.** 그것을
  확인하지 않고 "반영" 으로 보고했고 이 기록에도 그렇게 적었다. 확정 라운드가 잡았다.
  `CLAUDE.md` 의 "한 셀에 편집과 상태 변경을 같이 넣지 않는다" 가 막으려던 것이고,
  **편집한 뒤 그 파일을 다시 읽는 것**이 빠진 단계였다
- **판정 함수는 두 번 틀렸다.** 하위 에이전트의 첫 변이 시험에서 한 번(줄 주석), 크로스 모델
  리뷰에서 한 번(지시자 안 주석)이다. 둘 다 "모른다" 가 아니라 **틀린 답**을 내는 형태였다
