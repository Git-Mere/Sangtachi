# Phase 1 빌드 뼈대와 Winsock2 초기화

**대상 커밋:** 이 커밋
**Phase:** 1 (핵심 UDP 네트워킹)

문서 작업을 멈추고 구현을 시작한 첫 커밋이다. 레포를 목표 구조로 옮기고, 빌드와 시험이
도는 상태를 만들고, `roadmap.md` Phase 1 작업 목록의 첫 항목인 Winsock2 초기화와 해제를
넣었다.

## 저장소 소유자가 정한 것

세션 중에 둘을 정했다. 둘 다 사용자의 지시다.

**1. 되돌리지 않는다.** 문서 리뷰가 끝나지 않는다는 판단에서 `control_plane.md` 신설 커밋
(`3274ef7`)으로 revert 하자는 제안이 있었다. 조사해서 반대했다. 그 사이 커밋 3건에 3차 감사
blocker 4건의 수정이 들어 있고, 그보다 결정적으로 **Phase 1 검증이 쓰는 계측기가 그 커밋들에
있다.** `3274ef7` 시점 문서에는 `rx.raw` 와 `probe200` 이 0회 등장한다. 되돌리면 지금 짜야 할
코드의 판정 기준이 없는 시점으로 간다. 사용자가 HEAD 유지로 정했고, 미완이던 중복 주장
링크화 작업만 stash 로 내렸다.

**2. Catch2 를 쓴다.** 근거는 NFR-5 가 막으려는 것이 외부 라이브러리를 감싸 제출물로 삼는
것이고 시험 라이브러리는 그 범주가 아니라는 판단이다. 이 지시에 따라 `spec.md` NFR-5 를
제품 의존성과 시험 전용 의존성으로 나눴고 [ADR 0005](../decisions/0005-시험-프레임워크-catch2.md)
를 썼다. 경고를 오류로 올리는 것(`/WX`)도 같이 정했다.

## 실측으로 정한 것

### 빌드 산출물을 레포 밖에 둔다

빌드가 `LNK1201`, `C1041`, `LNK1168` 로 깨졌다. 전부 갓 쓴 `.exe` 와 `.pdb` 의 파일 잠금이다.
레포가 파일 동기화 폴더 안에 있는 것이 의심되어 같은 빌드를 두 위치에서 돌렸다.

| 위치 | 실패 | 실패 종류 |
|------|------|-----------|
| 레포 안 (`build/Debug`) | **4 / 18** | `LNK1201` 1, `C1041` 1, `LNK1168` 2 |
| 레포 밖 (`%LOCALAPPDATA%\Hamychi\build\Debug`) | 0 / 18 | 없음 |

단측 Fisher exact `p = 0.052` 다. **통계만으로는 결론이 서지 않는다.** 함께 본 것은 실패
4건이 전부 같은 기전(파일 잠금)이고 위치와만 상관이 있다는 점이다. 옮기는 비용이 거의 0 이라
기본 위치를 레포 밖으로 정했다. `-BuildDir` 로 되돌릴 수 있다.

**잠그는 프로세스가 무엇인지는 확인하지 않았다.** 동기화 에이전트인지 백신인지 단정하지
않는다. 확인된 것은 위치와의 상관뿐이다.

### 시험 케이스 이름은 ASCII 로만 적는다

케이스 이름을 한국어로 쓴 첫 판에서 3건 전부가 `No tests ran` 으로 떨어졌다.
`catch_discover_tests` 가 케이스 이름을 CTest 에 등록하고 실행할 때 그 이름을 명령 인자로
실행 파일에 도로 넘기는데, 콘솔 코드 페이지를 거치며 깨져 어느 케이스와도 일치하지 않는다.
같은 이유로 PowerShell 스크립트가 **출력하는** 문자열도 ASCII 로 고정했다. 주석은 파일 안에
머무르므로 한국어로 둔다.

## 검증

`scripts/test.ps1` 기준 Catch2 케이스 4건, `scripts/build.ps1 -SelfTest` 기준 케이스 7건이
전부 통과한다. 그 위에 변이 시험 둘을 돌렸다.

| 변이 | 결과 |
|------|------|
| 소멸자의 `WSACleanup` 제거 | 케이스 4건 중 **1건만 `FAIL`.** 나머지 셋은 통과했다 |
| `Test-IsCmakeBuildDir` 의 마커 검사 제거 | 케이스 7건 중 **2건 `FAIL`,** 종료 코드 1 |

**첫 변이가 구멍을 드러냈다.** 처음 쓴 케이스 3건은 `WSACleanup` 을 지워도 전부 통과했다.
Winsock 참조 수가 줄지 않을 뿐 `socket()` 은 계속 성공하기 때문이다. 그래서 마지막 context 가
사라진 뒤 `socket()` 이 `WSANOTINITIALISED` 로 실패하는지 보는 케이스를 더했고, 그 케이스만
변이에서 떨어졌다. **케이스를 썼다고 검증된 것이 아니라는 규칙이 첫 커밋에서 그대로 걸렸다.**

## 크로스 모델 리뷰

Codex 로 렌즈를 나눠 네 라운드를 돌렸다. 지적 7건 전부 반영했고 기각은 없다. 4라운드는
3라운드의 수리만 잘라 다시 본 것이고 `LGTM` 이다.

### 1라운드 — 코드 렌즈 (정확성·견고성)

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | `WSAStartup` 성공 뒤 `std::string` 할당이 던지면 객체가 완성되지 않아 소멸자가 돌지 않고 Winsock 참조 수가 샌다 | **반영.** 예외를 잡는 대신 **던질 일을 없앴다.** 버전 문자열을 멤버로 들고 있지 않고 `negotiated_version()` 이 부를 때 만든다. 생성자는 `WSAStartup` 뒤에 `WORD` 대입 하나만 한다 |
| blocker | `-Fresh` 가 검증 없이 임의의 `-BuildDir` 경로를 재귀 삭제한다 | **반영.** `Test-IsCmakeBuildDir` 를 만들어 `CMakeCache.txt` 가 있을 때만 지운다. 경로 접두사 같은 배제 목록이 아니라 증거를 요구하는 허용 목록이다. 케이스 표 7건을 `-SelfTest` 로 돌릴 수 있게 뒀다 |

### 2라운드 — 문서 렌즈 (일관성)

세 지적이 같은 뿌리였다. `spec.md` 와 `architecture.md` 가 Catch2 를 "승인됨" 으로 적는데
ADR 과 `plan.md` 는 "교수 확인 대기" 로 적어 상태가 어긋났다.

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | `spec.md` 의 승인 목록과 `plan.md`·ADR 의 대기 서술이 모순이다 | **반영.** 셋을 한 번에 맞췄다. 확인 대상은 Catch2 의 승인 여부가 아니라 **NFR-5 를 두 종류로 나눈 것** 이라고 못박았다 |
| warn | `architecture.md` 의존성 표의 승인 상태가 ADR 과 어긋난다 | **반영.** 상태 칸은 `spec.md` NFR-5 를 가리키게 했다. 뉘앙스를 두 곳에 복사하지 않는다 |
| warn | ADR 의 "저장소 소유자가 승인했다" 에 그 승인이 어디 적혔는지가 없다 | **반영.** 이 기록을 가리키게 했다 |

**내가 만든 정의에 기대던 문장을 내가 안 고쳤다.** NFR-5 를 고쳐 놓고 그 정의를 쓰는 다른
문서 셋을 그대로 뒀다. `CLAUDE.md` 가 "정의를 바꿨으면 그 정의에 기대던 문장을 목록으로
만들어 하나씩 다시 읽는다" 로 적어 둔 기전이다.

### 3라운드 — 확정 (수리 렌즈 + 기록 렌즈)

전체 diff 에 렌즈 둘을 붙여 돌렸다. 앞 두 라운드의 수리가 새 결함을 만들지 않았는지와, 이
기록과 `plan.md` 가 diff 와 맞는지를 본다.

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | `-Fresh` 가 `-LiteralPath` 로 검증하고 와일드카드를 해석하는 `Remove-Item` 으로 지운다. 경로에 `[ ] * ?` 가 들면 검증한 것과 지우는 것이 달라진다 | **반영.** 삭제도 `-LiteralPath` 로 바꿨다. `-SelfTest` 의 임시 디렉터리 정리도 같이 맞췄다 |
| warn | 이 기록이 `control-server/` 와 `telemetry-server/` 를 만들었다고 적는데 git 은 빈 디렉터리를 담지 못해 diff 에 없다 | **반영.** 두 곳에 `.gitkeep` 을 넣고 이 표의 서술을 고쳤다. 더 이상 비어 있지 않은 `client/include/` 와 `scripts/` 의 `.gitkeep` 은 지웠다 |

**수리 라운드가 수리의 결함을 잡았다.** 1라운드의 blocker 를 고치며 넣은 가드가 검증과 삭제에
서로 다른 경로 해석을 쓰고 있었다.

### 4라운드 — 수리 확인

3라운드의 수리분만 잘라 다시 돌렸다. `LGTM` 이다.

## 남은 것

`docs/eng` 미러는 이 커밋에 없다. 한국어를 먼저 고치고 푸시 지시가 있을 때 만든다. 문서
게이트는 `mirror` 와 `parity` 로 막히고 `link` 는 0 건이다.

Phase 1 의 나머지는 `endpoint` 와 기동 인자, 로그와 카운터, UDP 소켓 래퍼, `[loop]` 이벤트
루프다. 순서와 이유는 `plan.md` 가 갖는다.
