## 결정

자리별 선택은 ADR 0039 가 갖는다. 소유자가 고르지 않고 이 작업이 채운 값은 아래이고 소유자가 확인했다.

- 텔레메트리 주소가 인자와 빌드 기본값 둘 다 없으면 텔레메트리를 끈다
- `instance_id` 는 `client_nonce` 와 같은 형식. 난수원 실패는 기동 실패
- 구간 RTT 표본 16개 상한과 `rtt_overflow`
- 세션 바이트를 따로 센다. `tx_bytes` 는 프로세스 범위라 호스트에서 세션에 나눌 수 없다
- 빌드 버전 문자열이 없어 `build_kind` 만 싣는다
- 서버 검사의 정수 범위, 저장 키 `<instance_id>#<attempt>` 와 `seq`, `room_known` 의 세 값
- 환경 변수와 유닛 이름, CloudWatch 이름 공간 `Sangtachi`, 지표를 60초마다 묶어 보냄

문답 중 두 결정을 기존 문서 때문에 고쳤다. 소유자가 받아들였다.

- **DynamoDB 용량.** 텔레메트리 테이블을 제어 평면과 같은 25/25 로 두기로 했으나 무료 용량이 계정 단위라 넘는 만큼 요금이 붙는다
  (`control_plane.md` 7.6). 20/20 과 5/5 로 나눴다
- **마지막 업로드 대기.** 3초로 정했으나 `concurrency.md` 7장 join 상한이 2초이고 창 닫기·로그오프는 정리 직후 OS 가 프로세스를
  끝낸다. 2초에 맞췄다

## 크로스 모델 리뷰

Codex(`gpt-6.1-sol`). 한국어 차이에 렌즈 둘을 따로 돌렸다. (1) 정합성과 끝까지 따라가기, (2) 낡은 주장, 중복, 개인정보. 고친 뒤 고친
자리만 한 번 더 돌렸다. 영어 미러는 하위 에이전트가 맞췄다.

| 지적 | 처리 |
|------|------|
| 종료 이벤트를 보면 `[telemetry]` 가 (3)이 `end` 를 넣기 전에 끝날 수 있다 | 고침. (7) 정리 완료를 기다린 뒤 큐를 비운다 |
| `Rtt`·`Jitter`·`SessionDuration` 단위가 1000배 어긋남 | 고침. 1000 으로 나눈다 |
| 늦게 온 패킷 때문에 구간 손실 차이가 음수일 수 있다(`protocol.md` 4.5) | 고침. `expected`·`accepted` 를 싣고 `LossRate` 는 `end` 합계로만 낸다 |
| 방 항목이 지워진 뒤 온 진짜 레코드 | 한계로 적음. 만료 뒤 하루를 넘긴 세션만이다 |
| 지표 모집단과 DynamoDB 모집단 | 고침. 저장 성공한 것만 지표에 넣는다. 전송 실패로 대시보드에서만 빠지는 것은 한계로 적음 |
| 정수 필드 범위와 kind 별 필수 필드가 없다 | 고침. 서버 검사 목록 |
| `seq` 빈 번호로 끝부분 유실은 안 보인다 | 고침. 보이는 누락만이라고 적음 |
| 시간 범위를 `experiments.md` 에 적으면 ADR 0001 의 날짜까지만 규칙과 충돌 | 고침. 공개하지 않는 로컬 파일에 적는다. 그래프 시간축도 시각을 숨긴다 |
| 배포 환경 표의 확인값을 목표값 20/20 으로 바꿈 | 고침. 25/25 로 두고 나누면 20/20 이라고 적음 |
| IAM 문장이 이미 권한이 있는 것처럼 읽힘 | 고침. 배포할 때 더한다 |
| 60초와 테이블 용량을 다른 문서에 다시 적음 | 고침. 소유 절을 참조한다 |

마지막으로 영어 미러와 기록을 포함한 전체 staged 차이를 한영 일치와 기록 일관성 렌즈로 돌렸다. 영어 미러의 문구 둘(ADR 0039 의 "배포물 안내" 번역, `control_plane.md` 7.6 용량 줄의 조건)을 고쳤고 그 자리만 다시 돌려 지적이 없었다.
