# Path and Line Format of the Local Record File (ADR 0016)

## Why

This is one of the Phase 4 before-start decisions, the first item of the next work in `plan.md`.
`architecture.md` chapter 9 had only contracts and no path or line format, so `spec.md` M-6 could
not be judged.

The repository owner decided the following.

| Question | Decision |
|------|------|
| Path | `records\` under the executable folder. No argument changes the path |
| File unit | A new file per process. `<UTC startup time>-<PID>.log` |
| Line format | `<name>=<value>` joined by spaces. Nine fields, fixed order, empty value `-` |
| Abort | An `ABORTED` establishment line. A `CLOSE` in which the other side reports a failure is `PEER_FAILED` |
| Open and write failure | An open failure is a startup failure. A write failure is a `WARN`, a counter, and the tunnel is kept |
| Setup time | `setup_ms` is added |

## Important Decisions

- **RTT is in microseconds.** This keeps a same-LAN RTT from becoming 0 as an integer in
  milliseconds
- **The `setup_ms` start point differs between host and player.** Measuring the host side from STUN
  mixes in the time spent waiting for someone to join. The two values are not compared with each
  other
- **`ABORTED` is an abort that ended before reaching `CONNECTED`.** The trigger is this side's
  `leave` or shutdown event, or the other side's `CLOSE` (`reason` `0x00` or `0x01`). An abort after
  reaching it is an end line `CLOSED`, even during renegotiation
- **If the other side's `CLOSE` reports a failure (`0x02` or `0x03`), it is `PEER_FAILED`.** The
  distinction that `protocol.md` 5.6 made for Phase 9 is kept in the record too. The cause code is in
  the other side's record
- **The host's pair attempt comes into being when punching starts after it is ready.** A player
  reclaimed before that has no line on the host side
- **Once a write fails, nothing more is written to that file.** Appending after a half-written line
  joins two lines
- **The line-count verdict applies only to runs that went through the whole shutdown procedure and
  had no write failure.** Any other run cannot be judged
- The exit code of a startup failure was left as "a nonzero value", the same as other startup
  failures. The 2 mentioned at the proposal stage is the value for an argument error

## Cross-Model Review

Codex. Two lenses on the Korean diff (cross-document consistency, failure handling).

| Lens | Finding | Handling |
|------|------|------|
| Consistency | blocker. There is no result for an attempt that ended by the other side's `CLOSE` before the first `CONNECTED` | Accepted. The other side's `CLOSE` was added to the triggers of `ABORTED` |
| Consistency | blocker. The host's STUN comes after `create_room`, but it was written as "failure before creating the room" | Accepted. Changed to "before the room is set up", based on `register_candidate` succeeding |
| Consistency | warn. Whether it is an attempt when a player seen by the host is reclaimed before ready was not decided | Accepted. A pair attempt comes into being at punch start, and a reclaim before that has no line |
| Consistency | warn. An abort during renegotiation falls under both the `ABORTED` row and the `CLOSED` rule | Accepted. `ABORTED` was limited to before `CONNECTED` |
| Consistency | warn. `ABORTED` mentions only `leave` and `quit` and misses window close and Ctrl+C | Accepted. Widened to every shutdown event |
| Consistency | warn. The content contract and the M-6 result set have no abort | Accepted |
| Failure handling | blocker. Writing on after a partially written line joins lines | Accepted. Nothing is written after a failure, and the reader drops a last line without LF |
| Failure handling | warn. With write failures and forced termination, the line-count verdict does not hold | Accepted. "Runs that can be judged" was defined |
| Failure handling | warn. A check for positive `rtt_us` does not catch a unit error | Accepted. Values are injected into the function that builds the line and the exact string is checked |
| Failure handling | warn. If only the executable folder is blocked, an existing `records` can still be written | Accepted. Run in a new folder that has no `records` |
| Failure handling | warn. The form of the executable path (links, Korean, long paths) was not decided | Accepted. The path the OS gives is used as is, handled as wide characters, and truncation is an open failure |
