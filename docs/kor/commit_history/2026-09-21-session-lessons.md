# 2026-09-21 세션 교훈을 CLAUDE.md 에 기록

이번 세션에서 실제로 밟은 것들을 `CLAUDE.md` 에 규칙으로 남겼다. 다음 세션이 같은 자리를
다시 밟지 않게 하는 것이 목적이다. `CLAUDE.md` 는 `docs/` 밖이라 미러 규약과 문서 게이트의
대상이 아니다.

## 새 절 둘

**`리뷰를 돌릴 때`**

| 규칙 | 근거 |
|------|------|
| 렌즈를 바꿔 여러 번 돌린다. 한 렌즈의 `LGTM` 은 깨끗하다는 뜻이 아니다 | 같은 diff 에 일반 검사는 `LGTM`, "근거를 지워 과장이 됐는가" 는 16건 |
| 지우는 diff 는 특히 그렇다 | 없어진 것은 diff 에 보이지만 없어져서 생긴 구멍은 안 보인다 |
| 리뷰어가 diff 밖을 놓칠 수 있다. "없다" 류 지적은 HEAD 를 확인한 뒤 판단한다 | 앞 커밋에서 이미 고친 것을 "이 diff 에 없다" 로 지적한 일이 두 번 |
| 틀린 지적도 빈자리를 가리킬 수 있다. 기각은 지적을 버리는 것이 아니다 | `run_punch` 에 없는 결함을 지목받았는데, 그 함수를 도는 시험이 하나도 없었다 |
| 리뷰어가 지어낸 경고는 넣지 않는다 | 없는 경고를 넣는 것은 있는 경고를 빼는 것과 같은 결함이다 |

**`코드 작업 시`**

| 규칙 | 근거 |
|------|------|
| 케이스를 썼다고 검증된 것이 아니다. 결함을 넣어 `FAIL` 하는지 본다 | "따라잡기 방지" 케이스가 그 코드를 지워도 통과했다. 판정 축이 틀렸다 |
| 리팩터로 공유 지점을 만들면 그 자리에 시험이 있는지 먼저 본다 | 시험 151건이 두 측정 함수를 하나도 덮지 않았다 |
| 측정하는 코드는 조용히 틀린다 | 크래시하지 않고 틀린 값을 낸다. 리팩터 리뷰의 렌즈는 "동작 보존" 이다 |

## 이번 작업 자체의 실패 2건

**교훈을 적으면서 그 교훈을 어겼다.**

- "리뷰어는 diff 밖을 보지 않는다" 라고 단정했다. 거짓이다. 오늘 리뷰어는 README 검토에서
  실제로 스크립트를 읽고 플래그와 종료 코드를 대조했다. **하루 종일 과장을 낮추는 작업을
  하고 새 규칙에서 똑같이 과장했다.** "놓칠 수 있다" 로 낮추고 행동 지침을 남겼다
- 기각을 적는 규칙이 이미 `문서 작업 시` 에 있는데 `리뷰를 돌릴 때` 에 같은 취지를 새로
  만들었다. **방금 인용한 규칙 5 위반이다.** 하나로 합치고 문서와 프롬프트가 각각 다른 일을
  한다는 것을 명시했다
