# 0002. Linux 정상 종료가 표준 입력에 막혔다

- 상태: 해결
- 발견: 2026-10-31
- 관련: [ADR 0035](../decisions/0035-linux-콘솔-클라이언트.md), [`../concurrency.md`](../concurrency.md) 7장 종료,
  [`../commit_history/2026-10-31/02-linux-콘솔-클라이언트.md`](../commit_history/2026-10-31/02-linux-콘솔-클라이언트.md)

## 증상

Linux 콘솔 클라이언트에 종료 신호(`SIGINT`)를 보내면 정리는 `adapter.close` 까지 끝났다. 그런데 프로세스가 끝나지 않았다. 표준 입력에
한 줄이 오거나 표준 입력이 닫혀야 끝났다. 터미널에서 Ctrl+C 를 누르면 Enter 를 칠 때까지 끝나지 않는다는 뜻이다.

`mere-galaxy` 에서 표준 입력을 파이프로 열어 둔 채 재현했다.

- 신호 뒤 스레드 둘이 남았다. 주 스레드는 `futex_do_wait`, `[console]` 은 파이프 읽기(`anon_pipe_read`)에서 멈춰 있었다
- 파이프가 닫히자 신호 23.9초 뒤에 끝났다

## 조사

| 의심한 것 | 본 것 | 판단 |
|-----------|-------|------|
| 누군가 `[console]` 을 join 한다 | `[console]` 은 떼어 둔 스레드다(`main.cpp`). 설계도 join 하지 않는다(`concurrency.md` 7장 종료) | 아니다 |
| `exit` 가 stdio 읽기와 부딪힌다 | 클라이언트 없이 작은 프로그램으로 쟀다. 다른 스레드가 표준 입력을 읽는 중에 `main` 이 반환한다. 표준 입력은 4초 동안 열린 파이프다 | 맞다. 아래 표 |

| 다른 스레드의 읽기 | 프로세스가 끝나기까지 |
|--------------------|----------------------|
| `std::getline(std::cin, line)` | 4006ms (파이프가 닫힐 때) |
| `fgets(stdin)` | 4006ms |
| `read(0)` | 308ms (`main` 의 300ms 대기 직후) |

## 원인

**확인한 것.** stdio 로 읽는 스레드가 막혀 있으면 `exit` 가 끝나지 않는다. 같은 자리를 `read(0)` 로 읽으면 끝난다. glibc 2.43
(Ubuntu 26.04)에서 봤다. Windows 에서는 이 증상을 본 적이 없다.

**추정한 것.** 막힌 stdio 읽기가 stdin 잠금을 쥔 채 남고, `exit` 가 stdio 스트림을 정리하며 그 잠금을 기다린다. 주 스레드가
`futex` 에서 기다린 것과 맞는다. glibc 원본은 보지 않았다.

## 처리

표준 입력 한 줄 읽기를 플랫폼 함수 `platform::read_stdin_line` 으로 옮겼다.

- Windows 판은 이전과 같은 `std::getline(std::cin, line)` 이다
- Linux 판은 stdio 를 거치지 않고 `read(0)` 로 읽어 줄을 나눈다. 뜻은 `std::getline` 과 같다
- 규칙은 `concurrency.md` 7장 종료의 `[console]` 항목에 적었다

정리 뒤 `std::_Exit` 로 끝내는 안은 버렸다. Windows 종료 경로까지 바꾸게 된다.

크로스 리뷰가 하나를 더 짚었다. Linux 판이 남은 바이트를 담는 정적 버퍼는 `exit` 때 소멸하는데, 떼어 둔 `[console]` 이 그때도
읽고 있을 수 있다. 그 버퍼를 소멸시키지 않게 고쳤다.

## 결과

- 시험 둘을 더했다. 줄 나누기가 `std::getline` 과 같은지, 표준 입력에서 막힌 읽기 스레드가 있어도 자식 프로세스가 끝나는지 본다.
  변이 둘(`getline` 으로 되돌림, EOF 앞에 남은 줄 버림)을 시험이 잡았다
- 실물에서 표준 입력을 열어 둔 채 `SIGINT` 로 끝냈다. `--no-adapter` 는 58ms, `sudo` 어댑터 호스트는 0.13초 만에 끝났다. 두 방향
  실측에서도 80ms, 81ms 였다
- 커밋 `573f56a`

시간 값은 그때의 측정 스크립트 출력에서 옮겼다. 출력 원본은 저장소에 남기지 않았다.
