## 규칙 6을 바로 적용했다

규칙을 추가하면서 그 규칙을 어긴 산출물을 그대로 두면 규칙이 죽는다. ADR 0002의 PowerShell
절차를 옮겼다.

| 전 | 후 |
|----|-----|
| ADR 0002 안에 30줄 PowerShell + 결과 해석표 | `unsolicited-firewall-test.ps1` (실제 스크립트) |
| — | `README.md` 12장이 실행법과 해석을 적는다 |
| — | ADR 0002는 "12장에 있다" 와 링크 2개만 |

**첫 시도는 반쪽이었다.** 처음엔 스크립트를 README로만 옮겼는데, 리뷰가 "여전히 문서에
박힌 미실행 PowerShell이고 문법 검사도 못 한다" 고 지적했다. 규칙 6이 말하는 "도구에
넣는다" 는 `.ps1` 파일을 뜻한다. 옮기면서 아래 결함들이 드러났고 같이 고쳤다.

| 결함 | 내용 |
|------|------|
| blocker | 방화벽 cmdlet 이 비종료 오류라 규칙 생성이 실패해도 측정이 돌았다. **"규칙을 넣어도 막힌다" 는 거짓 결론이 나온다.** `$ErrorActionPreference = 'Stop'` 과 생성 직후 활성화 확인 |
| 주소 검증 중복 | PowerShell 에 두 번째 구현이 있었고 `192.88.99.0/24` 같은 특수 목적 대역을 통과시켰다. `natprobe.py check-peer` 로 일원화 |
| 경쟁 | 시작할 때 그룹 규칙을 무조건 지워 동시 시행의 규칙까지 없앴다. 지우지 않고 보고 후 중단으로 |
| 결론 과대 | 한 번 `allowed` 로 바뀌면 방화벽이 원인이라고 적었다. NAT 상태와 시각도 시행마다 바뀐다. 대조/규칙 시행을 **짝수 쌍(기본 4쌍) 번갈아** 돌리고, 쌍마다 순서를 뒤집어 일관된 차이를 본다 |
| blocker (2차) | IPv6 주소를 통과시켰다. `natprobe` 소켓은 `AF_INET` 이라 무관한 규칙을 걸어 놓고 `blocked` 를 잘못 읽게 된다. `check-peer --ipv4` 추가 |
| blocker (3차) | 규칙 삭제 실패를 `-ErrorAction SilentlyContinue` 로 숨기고 다음 대조 시행을 계속했다. **남은 허용 규칙이 대조군을 오염시킨다.** 삭제 실패는 종료 오류로, 남아 있으면 전체 중단 |
| 종료 코드 | `natprobe punch` 실패를 무시하고 다음 시행으로 갔다. `$LASTEXITCODE` 검사 |
| 뮤텍스 누수 | 획득 직후 검증에서 예외가 나면 해제되지 않았다. 본문 전체를 `try/finally` 로 |
| 주소 노출 | 상대 IP를 Python 명령줄 인자로 넘겨 프로세스 목록과 감사 로그에 남았다. `check-peer --stdin` 으로 파이프. `-Peer` 매개변수도 제거해 `Read-Host` 로만 받는다 |
| 정리 안내 누락 | 삭제 실패 시 예외가 바로 튀어 잔존 확인과 수동 정리 안내가 실행되지 않았다. 잡아서 확인한 뒤 규칙 이름과 삭제 명령을 담아 중단 |
| blocker (5차) | 만든 규칙 객체의 `Enabled` 만 봤다. GPO 병합 결과가 실제 적용되는 곳은 **`ActiveStore`** 다. 적용되지 않은 규칙을 활성으로 오인하면 결론이 뒤집힌다. `ActiveStore` 에서 `Enabled`/`Action`/`Direction` 을 확인 |
| 값 불일치 | Python 은 stdin 을 `strip` 해서 검증하는데 방화벽 규칙에는 원래 문자열을 썼다. `Trim` 후 공백·줄바꿈을 거부하고 같은 값을 쓴다 |
| 인자 모호 | `check-peer` 가 위치 인자와 `--stdin` 을 동시에 받고 stdin 을 조용히 우선했다. 함께 주면 오류 |
| 순서 효과 | 늘 대조를 먼저 돌려, 매핑 워밍업 같은 시간 의존 효과가 방화벽 효과를 흉내 낼 수 있었다. 쌍마다 순서를 뒤집고 라벨에 조건을 싣는다 |
| stdin 부분 검증 | `readline()` 으로 첫 줄만 읽어 나머지 입력이 검증되지 않았다. 전부 읽고 공백·여러 줄·빈 입력을 거부 |
| blocker (7차) | 방화벽 조회에 `-ErrorAction SilentlyContinue` 를 써서 **조회 실패를 "규칙 없음" 으로 읽었다.** 남은 규칙을 못 보고 측정하거나 정리가 끝났다고 잘못 보고한다. `Get-TestRuleSafe` 로 진짜 없음만 빈 목록 처리 |
| 거부 목록 누락 | `192.0.0.9`(PCP anycast), `192.0.0.10`(NAT64 discovery) 등이 통과했다. `192.0.0.0/24` 를 통째로 거부. **완전한 IANA 검사가 아니라는 것도 함수 설명에 적었다** |
| CLI 미검증 | 함수만 시험하고 인자 처리·종료 코드·주소 노출은 확인하지 않았다. `subprocess` 로 26건 추가 |
| blocker (9차) | 규칙 삭제 후 기본 저장소만 확인했다. **적용 중인 규칙이 `ActiveStore` 에 잠깐 남아 다음 대조 시행을 오염시킬 수 있다.** 사라질 때까지 최대 5초 폴링 |
| `-Trials 1` | 뒤집힌 쌍이 없어 순서 통제가 사라지는데 해석표는 그대로 인과를 말했다. **짝수 최소 2** 로 강제, 기본 4 |
| 상대 주소 가정 | 규칙을 상대 IP 로 좁혀, 요청하지 않은 패킷의 출발지가 그 주소라고 **가정**했다. 주소 의존 NAT 이면 규칙이 안 걸리고 그 결과를 "방화벽이 원인이 아니다" 로 읽는다. **주소를 아예 빼고 포트로만 좁혔다** |

**마지막 수정이 프라이버시 문제도 같이 없앴다.** 주소를 입력받지 않으니 `Read-Host`,
`--stdin`, 트랜스크립트 노출 경로가 전부 사라졌다. 다섯 번에 걸쳐 경로를 하나씩 막다가
**입구를 없애는 쪽이 맞았다는 것을 마지막에 알았다.**

`check-peer` 는 스크립트에서 더 이상 쓰지 않는다. 독립 보조 명령으로 남기고 README 3장에
적었다. CLI 시험 26건도 유지한다. 통과 시 `ok` 를 찍던 것을 없앴다 — **종료 코드로만 답한다는
계약과 어긋났고**, 조용한 검증 명령으로 쓸 수 없었다.

**뒤집힌 blocker 가 반복해서 나왔다.** 실패를 숨기지 않게 고치면 정상 경로가 막히고, 그것을
고치면 다시 실패를 놓친다. 재발 방지 규칙 3번(정상 구현이 통과하는지부터 확인)과 4번(수정이
만드는 새 계약)을 번갈아 어긴 셈이다.

| 원래 | 수정 | 그 수정이 만든 문제 |
|------|------|---------------------|
| 조회 실패를 "규칙 없음" 으로 읽음 | 엄격하게 | **정상 "없음" 도 막아 깨끗한 상태에서 실행 불가** |
| 삭제 실패를 숨김 | 종료 오류로 | 정리 안내가 실행되지 않음 |
| 생성 확인을 `ActiveStore` 로 | | 삭제 확인과 시작 확인은 안 고침 |
| 규칙을 상대 주소로 좁힘 | 포트만으로 | 규칙이 넓어졌는데 영구성 경고를 안 적음 |
| 뮤텍스로 단일 실행 보장 | | 버려진 뮤텍스(`AbandonedMutexException`)에서 **정상 재실행이 막힘** |
| 적용 확인을 즉시 1회 | | 정책 반영 지연으로 정상 시행을 실패 처리 |
| 규칙을 포트 전용으로 | | **그 전제(모든 출발지에 열림)를 검증하지 않음.** 정책 병합으로 주소 범위가 좁혀져도 통과 |

마지막 blocker 는 `Get-TestRuleSafe` 가 예외를 **형식으로** 잡은 것이었다.
`Get-NetFirewallRule` 의 정상적인 "일치 항목 없음" 은 `CimJobException` 으로도 오는데
`CimException` 만 잡고 있어서, **깨끗한 초기 상태에서도 스크립트가 중단됐다.** 형식 대신
범주와 `CmdletizationQuery_NotFound*` 오류 ID 로 판별한다.

ADR의 본체는 **결정과 그 근거**다. 아직 하지도 않은 선택적 시험의 실행 절차가 ADR 분량의
3분의 1을 차지하고 있었다.

## 크로스 모델 리뷰

- 리뷰어: Codex (GPT). **14라운드**

**기각한 지적.**

> 시작 시 발견한 잔존 규칙의 `DisplayName` 과 `PolicyStoreSource` 를 기본 출력해 공유
> 터미널 로그에 로컬 방화벽 정책 정보가 노출될 수 있다. 상세는 선택적 진단 모드로 제한하라

**기각 사유.** 그 목록이 곧 정리 지시다. 규칙 이름을 감추면 사용자가 무엇을 지워야 하는지
알 수 없고, 그것은 4라운드에서 고친 결함("안전 장치가 사용자를 막다른 길에 둔다")을 다시
만드는 것이다. 이름은 이 스크립트가 만든 GUID 이고 사용자 데이터가 아니다. 어느 저장소에
남았는지도 삭제 명령을 고르는 데 필요하다.

**같은 라운드의 다른 노출 지적은 반영했다.** 삭제 실패 메시지의 원본 예외는 정리에 필요
없으므로 `-Verbose` 로 옮겼다. **필요한 정보와 불필요한 정보를 구분한 것이지 노출 지적을
일괄 기각한 것이 아니다.**

## 남은 것

**`unsolicited-firewall-test.ps1` 은 한 번도 실행된 적이 없다.** 이 커밋의 blocker 6건 중
**3건이 "정상 상태에서 실행 불가"** 였고(예외 형식 한정 catch, 버려진 뮤텍스,
빈 배열 언롤 + StrictMode), 전부 정적 검토로만 잡았다. 실행했으면 첫 줄에서 나왔을 것들이다.

**다음에 Windows 에서 할 일은 리뷰가 아니라 실행이다.** 관리자 PowerShell 에서
`-Trials 2` 로 한 번 돌려 보는 것이 리뷰 한 라운드보다 많은 것을 알려준다.

17라운드에서 멈췄다. 18라운드는 시작만 하고 중단했다. 남은 지적이 있을 수 있다.

규칙 4번을 세 번째로 어겼다. 이번에도 원인 서술을 낮추면서 거기 기대던 결론을 안 고쳤다.
**4번은 규칙이 없어서 어기는 것이 아니라 의존 관계를 추적하지 않아서 어긴다.** 규칙을 더
추가해서 풀 문제가 아니므로 `CLAUDE.md` 에 "리뷰 전 자기모순 검사" 를 절차로 적었다.
