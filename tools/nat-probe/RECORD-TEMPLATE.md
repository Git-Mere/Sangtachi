# NAT 실측 기록

`tools/nat-probe/natprobe.py` 실측 결과 기록 양식. 이 파일을 복사해 채운다.
파일명은 `tools/nat-probe/records/YYYY-MM-DD-nat-실측.md`를 권한다.

사용법은 [`README.md`](README.md), 요구 사항의 출처는
[`docs/kor/plan.md`](../../docs/kor/plan.md) 5장이다.

**채우지 못한 칸은 지우지 말고 `미측정` 또는 `모름`이라고 적는다.** 빈칸과 "모름"은 다르다.

## 6. 후속 결정

**안을 고르는 것과 성공 기준 개정은 한 묶음이다.** `plan.md` 5장이 못박은 조건이다.
안만 고르고 기준을 그대로 두면 blocker 20은 해소되지 않는다.

### 6.1 선택지

| 안 | 내용 | 선택 | 이유 |
|----|------|------|------|
| 해당 없음 | 현재 M-1/M-4 그대로 유지 (blocker 20 해소) | ☐ | |
| A | NAT 에뮬레이션 테스트베드 | ☐ | |
| B | 최소 릴레이를 P1로 승격. direct 실패 시 폴백 | ☐ | |
| C | 모바일 핫스팟 등 제3의 경로를 필수 시험 토폴로지에 추가 | ☐ | |

선택한 안의 대가(`plan.md` 5장 표)를 여기에 옮겨 적고 받아들일지 판단한다.

> 대가와 수용 판단:

### 6.2 재현 조건

선택한 안의 재현 조건을 적는다. 안마다 다르다.

| 안 | 재현 조건 | 충족 여부 | 증거 |
|----|-----------|-----------|------|
| A | 에뮬레이터 설정을 문서화하고 그 설정에서 3회 연속 성공 | | |
| B | direct 실패를 인위적으로 만든 뒤 폴백 경로로 3회 연속 성공 | | |
| C | 통신사, 요금제, 시각, 신호 상태를 기록하고 그 조건 아래에서 3회 연속 성공 | | |

안 C를 골랐다면 아래를 채운다. 핫스팟은 통제 대상이 아니므로 조건을 적지 않은 결과는 증거가
되지 않는다.

| 항목 | 값 |
|------|-----|
| 통신사 | |
| 요금제 | |
| 측정 시각 | |
| 신호 상태 / 대역 | |
| 조건이 바뀌면 결과가 달라질 수 있음을 기록했는가 | 예 / 아니오 |

### 6.3 성공 기준 개정안

| 대상 | 현재 문구 | 개정안 | 이유 |
|------|-----------|--------|------|
| M-1 | 서로 다른 네트워크의 Windows 머신 2대에서 클라이언트가 동작한다 | | |
| M-4 | 지원 NAT 환경에서 수동 포트 포워딩 없이 직접 UDP 연결을 수립한다 | | |
| 필수 시험 토폴로지 | (1) 동일 LAN, (2) 서로 다른 가정망 2곳 | | |
| 지원 조건 / 미지원 조건 | `spec.md` "지원 네트워크 조건" 표 | | |
