# 제어 평면 케이스 표를 시험으로 옮기고 변이 시험을 붙였다

## 왜 했나

`plan.md` 다음에 할 일 1번이고 `roadmap.md` Phase 3 작업의 첫 항목이다. `control_plane.md` 의
케이스 표 여덟 자리, 표 아홉(2.1, 3.3, 4.4, 4.5, 4.6 둘, 5.1, 6.4, 7.4)을 `control-server/tests/` 로 옮기고,
표가 판정하는 순수한 부분을 구현하고, 표마다 변이 시험을 붙였다. 서버 코드(`store.py`,
`ops.dispatch`, 수락 루프)보다 먼저다.

## 저장소 소유자가 정한 것

| 무엇 | 결정 | 기록 |
|------|------|------|
| Python 시험 실행기 | pytest. 시험 전용 의존성으로 승인 | ADR 0014, `spec.md` NFR-5 |
| DynamoDB local 을 띄우는 법 | Docker 컨테이너 | ADR 0014, `roadmap.md` Phase 3 |

에이전트가 내놓은 안은 `unittest` 와 jar 였다. 둘 다 버린 이유는 ADR 0014 에 있다.

## 어떻게 나눠 했나

디렉터가 뼈대(`constants.py`, `errors.py`, `conftest.py`, 변이 실행기 `tests/mutate.py`)를 먼저
쓰고, 작업자 셋에게 표를 나눠 맡겼다. 작업자는 같은 모델이고 서로 다른 파일만 만졌다. 문서는
디렉터만 고쳤다.

| 작업자 | 표 | 파일 |
|--------|----|------|
| worker-http | 3.3 HTTP 부분집합, 6.4 속도 제한, 7.2 의 파싱 뒤 | `server.py`, `test_http.py`, `test_rate_limit.py` |
| worker-ids | 2.1 `room_id`, 4.4 위생, 7.4 시계 | `ids.py`, `candidates.py`, `clock.py` 와 그 시험 |
| worker-ops | 5.1 방, 4.5 원소의 필드 집합, 4.6 두 표 | `ops.py`(순수한 부분), 그 시험 |

**저장소가 있어야 도는 행 8건은 옮기기만 하고 건너뛴다.** 4.6 확인 경합 표 6행 전부와 서버 회수
표의 2행이다. 저장소를 흉내 내지 않았다. `pytest.mark.store` 와 skip 이 같이 붙고, 다른 이유의 skip
은 `conftest.py` 가 수집 단계에서 멈춘다.

## 작업자가 찾은 문서 빈자리

작업자 셋이 32건을 냈다. 코드에서 정하지 않고 디렉터가 하나씩 정해 문서에 먼저 적었다.

| 절 | 정한 것 |
|----|---------|
| 2.1 | ASCII 검사가 대문자 변환보다 먼저다. `ſ`(U+017F) 가 대문자로 `S` 가 된다 |
| 2.3, 2.4 | 요청의 `peer_token`, `client_nonce` 도 소문자 16진수 32자만 받는다. 위반은 `bad_request` |
| 3.1, 3.3 | 요청 줄 문법, 표의 헤더 다섯, 헤더 줄 문법(콜론 앞 공백과 콜론 없는 줄은 거부), 헤더 크기를 세는 범위, 요청 줄이 상한 안에서 안 끝나면 `431`, JSON 중복 키와 `NaN` 거부, `Expect`·`Upgrade`·`Authorization`·`Content-Encoding` 은 무시, 본문 도중 EOF 는 응답 없이 닫고 카운터 없음 |
| 4.4 | 처리 순서(형 검사 -> 위생 -> 중복 제거). 중복이면 먼저 온 원소. 모르는 키는 버림. 서버가 거부하는 대역은 10.1 목록 그대로 |
| 4.6 | 서버 회수의 판정 순서 표와 건너뛰는 사유 셋 |
| 6.3 | `PAIR#` 의 `lo`·`hi` 는 수의 순서. 저장소의 숫자는 `store.py` 가 `int` 로 바꾼다. 속성이 없거나 형이 다르면 `internal`. 없는 `candidates` 는 빈 목록 |
| 6.4 | 보충 기준 시각은 6초씩 나아간다. 표가 찼을 때 훑어 지운다. 토큰은 0 아래로 가지 않는다 |
| 7.1 | 모듈 표에 `errors.py`, `constants.py`. 옥텟 파싱을 ASCII 숫자와 전체 일치로. "연산 넷" 을 다섯으로 |
| 7.2 | 시간 초과는 요청 읽기에만. `ops.dispatch` 의 계약. 의사 코드를 그 계약대로 |
| 7.4 | `boot_id` 파일이 비었거나 읽을 수 없으면 없는 것과 같다 |

정하지 않고 `plan.md` 문서 부채로 넘긴 것이 둘이다. 후보 위생의 `0.0.0.0/8` 나머지와 `240.0.0.0/4`,
그리고 헤더 이름 가운데 공백이다.

## 옮긴 것과 지운 것

`control_plane.md` 에서 표를 빼고 그 자리에 파일 링크를 두었다. **표 칸에만 있던 규칙은 산문으로
남겼다.**

| 절 | 표가 간 곳 | 산문으로 남긴 것 |
|----|------------|------------------|
| 2.1 | `test_room_id.py` `ROOM_ID_CASES` | 앞뒤 공백을 지우지 않는다, 문자열이 아니거나 없으면 `bad_request` |
| 3.3 | `test_http.py` `CASES` | 상한을 넘는 `Content-Length` 는 본문을 읽지 않고 `413` |
| 4.4 | `test_candidates.py` `CANDIDATE_CASES` | 후보 목록은 루프백을 거부한다, 9개는 요청 전체 거부, 중복은 `rejected` 에 세지 않는다 |
| 4.5 | `test_get_peers.py` `FIELD_SETS` | 두 필드 집합 |
| 4.6 확인 경합 | `test_host_report.py` `CONFIRM_RACE` | 마지막 행이 잡는 결함 |
| 4.6 서버 회수 | `test_host_report.py` `RECLAIM_CASES` | 회수된 피어의 같은 nonce 는 새 참가다 |
| 5.1 만료 판정 | `test_room_state.py` `EXPIRY` | 경계는 만료 쪽, 필드가 없거나 정수가 아니면 `internal` |
| 6.4 | `test_rate_limit.py` `CASES` | 12번 행이 뜻하는 것 |
| 7.4 | `test_clock.py` `CLOCK_CASES` | 계산 경로 넷. 재부팅 뒤 오차 상한이 보장되지 않는다는 것 |

**지운 것은 하나다.** 6.4 의 "14번이 60초가 아니라 70초인 이유" 문단이다. 시험 설계의 근거라
`test_rate_limit.py` 의 그 행 `note` 로 옮겼다. 5.1 의 상태 정의 표는 정의라서 문서에 남겼다.

문서의 행 참조도 고쳤다. 1.2 와 6.4 의 "12번" 은 `row-12` 로, 7.4 의 "케이스 표의 마지막 행" 은
"계산 경로의 마지막 항목" 으로, 9장과 `roadmap.md` 의 "옮긴 뒤에는" 은 지금 상태로 바꿨다.

## 변이 실행기

`tests/mutate.py` 가 `controlplane/` 을 임시 폴더에 복사해 한 곳을 고치고, `CP_SRC` 로 넘겨 pytest
를 새 프로세스로 돌린다. 변이마다 떨어져야 할 행을 `kills` 에 적고, 그 행이 시험 본문에서 `FAILED`
일 때만 `KILLED` 다. 판정 넷의 기본값은 판정 불가(`ERROR`)다.

- `conftest.py` 가 실제로 import 된 `controlplane` 이 `CP_SRC` 아래인지 확인한다. 원본이 대신
  읽히면 모든 변이가 살아남은 것처럼 보인다
- 변이 전에 원본으로 같은 시험을 돌린다. 원본이 떨어지면 판정하지 않는다
- 원본에서 `old` 가 정확히 한 번 나오지 않으면 그 변이는 `ERROR` 다. 코드가 바뀌어 낡은 변이가
  조용히 통과하지 않게 한다

**처음 돌렸을 때 살아남은 변이가 있었다.** worker-http 의 첫 결과는 61/64 였다. 한 행은 시험 축이
틀렸고(표지 본문이 JSON 이 아니라 배열 경로를 지나지 않았다), 한 행은 아무것도 지키지 않아
처리 코드와 같이 뺐다. worker-ids 는 2.1 의 전각 행만으로는 ASCII 검사가 지켜지지 않는 것을
변이로 찾아 `ſ` 행을 더했다.

## 크로스 모델 리뷰

Codex. 렌즈를 둘씩 묶고 지적마다 렌즈 이름을 붙이게 했다. 입력은 렌즈가 보는 파일로 잘랐다.

**3번 호출이 한 번 실패했다.** 프롬프트의 백틱을 셸이 명령 치환으로 실행해 `control_plane.md` 전문이
인자로 들어갔고 `Argument list too long` 으로 끝났다. 산출물이 없었다. 프롬프트를 셸 인용으로 감싸
다시 돌렸다.

### 1. HTTP·속도 제한: spec-conformance + security

두 렌즈 모두 `none`.

### 2. 나머지 모듈과 실행기: spec-conformance + harness-soundness (warn 3)

| # | 렌즈 | 지적 | 처리 |
|---|------|------|------|
| 1 | harness | 준비 단계 `ERROR` 를 kill 로 센다. 픽스처가 터지면 변이를 돌리지 않고도 `KILLED` | 반영. `FAILED` 만 센다. kills 의 행이 `ERROR` 면 판정이 `ERROR` |
| 2 | harness | 빈 표는 기본값으로 건너뛴 시험이 되어 통과한다. `store` 행만 건너뛰는지 확인하지 않는다 | 반영. `empty_parameter_set_mark = fail_at_collect`, `store` 표시 없는 skip 은 수집 실패 |
| 3 | harness | 변이 파일이 하나도 없으면 0/0 으로 `pass` | 반영. 변이가 없으면 오류 |

### 3. 문서: removal-gap + consistency (warn 4)

| # | 렌즈 | 지적 | 처리 |
|---|------|------|------|
| 1 | removal-gap | 4.4 거부 정책이 지운 표의 "결과" 열을 가리킨다 | 반영. `CANDIDATE_CASES` 의 `result` 필드 |
| 2 | consistency | 7.2 의사 코드가 `result.error` 를 읽는데 계약은 dict 반환과 예외다 | 반영. 의사 코드를 계약대로. 그러면서 파싱 오류(`OpError`)를 받는 줄도 빠져 있던 것을 디렉터가 찾아 더했다 |
| 3 | consistency | 6.3 "속성이 없으면 `internal`" 이 `candidates` 가 없는 joined 피어와 어긋난다 | 반영. 없는 `candidates` 는 빈 목록이라는 예외 |
| 4 | consistency | 4.6 이 `peer.reclaim_skipped` 를 카운터처럼 말한다 | 반영. "7.5 의 로그 줄" 로. 절 제목 "로그와 카운터" 를 붙인 것이 오해를 불렀다 |

### 4. HTTP·속도 제한: scenario-trace + test-strength (warn 5)

1번 라운드가 깨끗했으므로 렌즈를 바꿔 다시 돌렸다. 바이트 열 추적은 `none` 이었고 시험 강도에서
다섯이 나왔다. 코드 결함은 아니었고 전부 시험 행과 변이를 더해 반영했다.

| # | 지적 | 더한 행 |
|---|------|---------|
| 1 | 모든 행이 요청을 한 번에 넣는다. 두 번째 read 에서 미완 헤더를 거부하는 구현이 통과한다 | `STREAM_CASES` `split-pieces` |
| 2 | read 마다 시간 제한을 다시 거는 구현이 통과한다 | `drip-past-total-timeout` |
| 3 | 본문 도중 EOF 를 `400` 으로 답하는 구현이 통과한다 | `eof-mid-body` |
| 4 | 표가 찼을 때 첫 항목만 지우는 구현이 통과한다 | `table-full-sweep-drops-all` |
| 5 | 예산 검사를 파싱 앞에 둔 구현이 통과한다 | `parse-error-before-budget` |

시간에 기대는 두 행을 다섯 번 이어 돌려 다섯 번 통과했다.
