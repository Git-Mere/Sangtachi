# Phase 7 착수 전 결정 (ADR 0029)

## 왜 했나

`plan.md` 다음 할 일이 Phase 7 이었다. 착수 전에 문서와 코드를 대조해 정하지 않은 자리와 지금 코드와 부딪치는 자리를
뽑아 저장소 소유자에게 선택지와 함께 보였다. 소유자는 방화벽 규칙을 클라이언트가 만들고 지우지 않는 안(B)을 골랐고,
이미 있는 규칙은 최소한의 검증을 거쳐 쓰라고 했다. 검증 설계는 따로 보고해 승인을 받았다. 나머지 자리는 권장안을 골랐다.
결정과 버린 대안은 ADR 0029 다. 이 커밋은 클라이언트 코드를 바꾸지 않는다. 문서, 문서 게이트의 예정 목록과 이름 모양, 실측 스크립트만 바꾼다. 구현은 다음 커밋들이다.

## 중요한 결정

결정과 버린 대안은 ADR 0029 다. 이 기록에는 그 밖의 판단만 적는다.

- **규칙이 어댑터 재생성을 견디는지 먼저 쟀다.** B 는 한 번 만든 규칙이 다음 실행의 어댑터에도 걸려야 성립한다. 걸리지 않으면
  검증의 인터페이스 검사가 두 번째 실행부터 늘 떨어진다. 그래서 문서를 쓰기 전에 쟀다. 결과는 아래 확인한 사실이다
- **`protocol.md` 8.5 케이스 표의 "검사 6번으로 간다" 를 카운터 이름으로 바꿨다.** 검사가 하나 늘어 번호가 밀린다. 같은 절이
  "검사 번호를 인용하지 않는다" 고 정했는데 표 안에서 번호를 썼다
- **`10.100.0.255` 를 유니캐스트가 아닌 쪽으로 옮겼다.** 가상 대역의 브로드캐스트 주소다. 이전에는 범위 밖 행에 함께 들어
  `tx_drop_no_route` 였다
- **응답기 범위의 위쪽 끝을 255 미만으로 적었다.** 255 는 브로드캐스트라 유니캐스트 검사가 맡는다
- **새 카운터 다섯을 docgate 의 예정 목록에 넣었다.** 문서에는 있고 코드에는 아직 없다. 구현하면서 뺀다. 빼지 않으면 게이트가
  떨어진다. `tx_bytes` 따위는 처음에 게이트가 카운터로 읽는 이름 모양이 아니었다. 리뷰 지적으로 모양에 `_bytes`, `_datagrams` 끝을
  더했다. 살아 있는 문서의 코드 스팬 가운데 그 끝을 가진 것은 이 넷뿐이다
- **캡처 대조의 필터를 5-튜플에서 로컬 포트로 바꿨다.** 카운터가 상대와 타입을 가리지 않으므로 캡처도 가리지 않아야 같다

## 확인한 사실

관리자 셸에서 `C:\me\build\fw-binding-probe.ps1` 을 돌렸다. Windows 10.0.26300, PowerShell 7.6.7 이다. 처음에는 한 번
쓰는 실측이라 레포 밖에 두었다. 리뷰가 재현할 수 없다고 지적해 `tools/winprereq/Probe-FirewallRuleBinding.ps1` 로 넣었다. 넣은
판은 경로를 인자로 받고, 아래에서 실패한 마지막 역조회를 뺐다. 마지막 리뷰 뒤에는 이 실행이 만든 규칙만 지우게 고쳤다.
측정 결과를 바꾸는 차이는 없다. 제품 빌드 클라이언트를
방 없이 띄워 어댑터를 세우고, `New-NetFirewallRule -InterfaceAlias Sangtachi` 로 규칙 둘(그룹 `SangtachiProbe`)을 만든 뒤,
클라이언트를 `quit` 하고 다시 띄웠다.

| 시점 | `InterfaceAlias` | 레지스트리 규칙 원문의 인터페이스 |
|------|------------------|-----------------------------------|
| 만든 직후 (어댑터 있음) | `Sangtachi` | `IF={E2085BB3-83CE-4597-8DD3-68795CCFD00A}` |
| `quit` 뒤 (어댑터 없음) | `e2085bb3-83ce-4597-8dd3-68795ccfd00a` | 같다 |
| 다시 띄운 뒤 (어댑터 다시 섬) | `Sangtachi` | 같다 |

- 세 시점 모두 규칙은 켜져 있었다. 클라이언트 종료 코드는 0 이었다
- 어댑터의 ifIndex 는 두 실행 모두 64 였다
- 마지막의 별칭 역조회는 `Get-NetFirewallInterfaceFilter` 에 `-InterfaceAlias` 매개변수가 없어 실패했다. 스크립트 실수다.
  `finally` 가 두 번째 클라이언트를 끝내고 규칙을 지웠다(남은 규칙 0). 뒤에 어댑터가 남지 않은 것도 확인했다
- 규칙이 실제로 트래픽을 통과시키는지는 보지 않았다. 상대 기기가 있어야 한다

## 검증

- `python tools/docgate/docgate.py` 통과. 첫 실행은 `tx_drop_not_unicast` 가 문서에만 있다고 떨어졌고 예정 목록에 넣어 통과했다
- `cd tools/docgate && python -m unittest test_docgate` 139건 통과. 이름 모양을 넓힌 뒤에도 같다
- 장면 셋을 문서로 따라갔다. 운영체제가 보낸 `224.0.0.251` 은 어댑터 읽기, 송신 측 검증의 유니캐스트 검사를 지나
  `tx_drop_not_unicast` 다. 플레이어의 `ping 10.100.0.1` 은 라우팅, `DATA`, 상대의 8.4 와 주입, 2절 ICMP 규칙을 지난다.
  시험 빌드의 `ping 10.100.0.9` 는 응답기가 답하고 라우팅으로 가지 않는다

## 크로스 모델 리뷰

Codex 로 staged diff 를 두 번 보였다. 한 번은 기동, 잡음 패킷, 시험 빌드 `ping`, 캡처 대조의 네 장면을 따라가며 계약과 다른
문서·코드와의 모순을 보게 했다. 한 번은 한국어와 영어의 뜻 일치와 저장소 전체의 낡은 서술을 보게 했다. 지적은 일곱이고 모두
`warn` 이다. 두 리뷰가 같이 낸 하나를 합쳐 여섯이다. 모두 반영했다.

| # | 지적 | 처리 |
|---|------|------|
| 1 | ADR 의 응답기 범위가 255 를 빼지 않아 `concurrency.md` 와 다르다 (두 리뷰 모두, 미러 포함) | 반영. 두 ADR 에 255 미만을 더했다 |
| 2 | 15절 사용성 비교가 아직 어댑터 프로필 설정을 사람의 부담으로 적는다 (미러 포함) | 반영. 클라이언트가 만드는 서버 포트 예외와 Java 규칙 확인으로 고쳤다 |
| 3 | 새 바이트·데이터그램 카운터 넷이 코드에도 예정 목록에도 없고 게이트의 이름 모양에 들지 않아 구현 여부를 놓친다 | 반영. 예정 목록에 넣고 모양에 `_bytes`, `_datagrams` 끝을 더했다 |
| 4 | 검증이 그룹을 보지 않는데 지우는 명령은 그룹으로 지운다. 그룹이 바뀐 규칙은 검증을 지나거나 지워지지 않고 기동을 계속 막는다 | 반영. 그룹 검사를 더하고, `ERROR` 줄은 그 규칙을 이름으로 지우는 명령을 싣는다 |
| 5 | 캡처 유실 0 이 `recvfrom` 카운터와의 일치를 보장하지 않는다. 소켓 버퍼 유실과 `WSAEMSGSIZE` 는 캡처에만 있다. 측정 경계도 없다 | 반영. 수신 쪽 유효 구간에 운영체제 UDP 수신 오류 통계를 더하고, 생성 크기가 `WSAEMSGSIZE` 를 만들지 않음을 적었다. 측정 경계는 정할 근거가 없어 "아직 비어 있다" 행으로 두었다. 대조 절차를 쓸 때 정한다 |
| 6 | GUID 실측이 결론만 있고 재현할 절차와 출력이 없다 | 반영. 절차를 `tools/winprereq/` 에 넣고, 문서와 ADR 이 그것을 가리킨다. 출력은 위 확인한 사실의 표다 |

| # | 지적 | 처리 |
