# Phase 4 3차 I: 호스트의 `ROSTER` 송신과 시점

## 왜 했나

Phase 4 3차의 마지막 조각이다. 착수 전 결정은 ADR 0023 이 정했다. 이것으로 3차(G, H, I)가 끝났다.

## 중요한 결정

**문서 공백 하나를 문서에 먼저 적었다.** `ROSTER` 를 어디로 보내는지가 10.4 에도 5.7 에도 없었다. `DATA`, `KEEPALIVE`, `PING`
과 같이 우리가 먼저 보내는 주기 송신이므로 같은 규칙에 넣었다.

**문서 규칙과 어긋나지 않는 작은 것은 코드가 정했다.** `roster_publisher.hpp` 의 "이 코드가 정한 것" 표에 근거와 함께 있다.

- 계기(상태 전이, `set_peers`)는 표시만 하고 같은 바퀴의 타이머 자리에서 보낸다. 수신 처리 안에서 다시 보내지 않는다
- 한 바퀴 안의 여러 변화는 한 번으로 묶는다. `generation` 은 1 오르고 한 장이 나간다. 멤버가 나갔다 같은 바퀴에 돌아와 내용이 그대로
  보여도 변화로 세고, 떠난 세션의 타이머는 그 자리에서 지운다
- 명부에 없는 세션이 `CONNECTED` 에 들어가면 내용이 그대로이므로 그 세션에만 1회 보낸다(11장 "진입 즉시 1회")
- 타이머 이름은 `roster.period.<peer_id>`, `roster.resend.<peer_id>` 다
- 멤버가 다섯을 넘으면 보내지 않는다(`encode_roster` 가 거절한다)

## 크로스 모델 리뷰

Codex 를 렌즈 둘(계약과 정확성, 시험 충분성과 기록)로 따로 돌렸다.

| 지적 | 처리 |
|------|------|
| blocker. 같은 수신 묶음 안에서 `CONNECTED` 를 떠났다 돌아오면 표시 하나로 묶여 변화, 타이머 취소, 진입 송신이 빠진다 | 반영. 이탈 때 그 세션의 타이머를 바로 지우고, 멤버면 변화로 센다. 시험과 변이 |
| blocker. `start` 가 직전 명부를 비워 두어 첫 바퀴 전에 받은 멤버가 `generation` 0 이 된다 | 반영. `start` 가 호스트 혼자인 0 번 명부를 정한다. 시험 |
| warn. 새 변경이 진행 중인 재송을 대체하는지 보지 않는다 | 반영 |
| warn. 변경이 모든 `CONNECTED` 세션에 가는지 보지 않는다 | 반영 |
| warn. 이름 변경 뒤의 내용을 보지 않는다 | 반영 |
| warn. 타이머 마감을 보지 않는다 | 반영. 재송 마감을 본다 |
| warn. 걸린 타이머가 있을 때 방을 떠나고 다시 세우는 경우가 없다 | 반영 |
| warn. `timer.tick` 의 `elapsed_ms` 를 보지 않는다 | 반영. 늦게 돈 바퀴를 포함한다 |
| warn. 학습 전 `ROSTER` 의 후보 전체 송신을 보지 않는다 | 반영 |
| warn. 둘째로 받아들인 명부의 줄, 버린 명부의 무출력을 보지 않는다 | 반영 |
| warn. 헤더가 `roster` 줄을 "유휴 갱신과 학습 뒤" 에 낸다고 적었는데 그 순서를 보는 시험이 없다 | 헤더를 고쳤다. 그 순서는 문서의 계약이 아니다 |

수정 확인 리뷰는 `LGTM - no blockers` 였다.
