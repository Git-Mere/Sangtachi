# Phase 9 상대 없이 하는 검증과 첫 실측 두 환경

## 왜 했나

`roadmap.md` Phase 9 검증 가운데 다른 사람이 필요 없는 것을 먼저 돌렸다. 소유자가 실행을 승인했다. 실측은 소유자가 정한 대로 `mere-galaxy` 와 이 PC 로 동일 LAN 과 가정망 대 모바일 핫스팟을 돌렸다.

## 구성

| 무엇 | 값 |
|------|-----|
| 빌드 | 둘 다 커밋 `5f9f710` 의 Release 콘솔 빌드. `SANGTACHI_TEST_BUILD` 는 끔(`build_kind` 가 `release`). 이 PC 는 정적 CRT, 관리자 매니페스트 없음 |
| 기동 | `--no-adapter --server <Elastic IP> --telemetry <Elastic IP>`. 연결 수립과 세션 값은 가상 어댑터가 필요 없고 관리자 권한 없이 돌기 때문이다 |
| 역할 | `mere-galaxy` 가 호스트, 이 PC 가 플레이어. 시행마다 같다 |
| 시행 | 둘을 새로 띄우고, 연결되면 30초 유지하고 `quit` 으로 끝낸 뒤 60초 쉰다(`roadmap.md` 통계 설계의 시행 사이 50초보다 길다) |
| 기록 | 시행마다의 표준 출력, 로그, 요약은 git 이 무시하는 `field-test/2026-11-17/` 에 있다. 묶음의 UTC 범위는 `tools/tm-analysis/local/batches.txt` 에 있다 |

## 결과: 상대 없이 하는 검증

| 검증 | 결과 |
|------|------|
| 포트 8001 (`windows-prereq.md` 6절의 두 판정) | 인스턴스 안 `ss -ltnp4` 가 모든 IPv4 주소의 8001 에서 듣는다. 이 PC 의 `Test-NetConnection` 이 `TcpTestSucceeded : True` |
| 텔레메트리 서비스만 중지 (분리 4) | `verify.py` 의 방 생성, 참가 넷, 후보 등록, 확인, 회수가 `VERDICT: pass` |
| 제어 서버만 중지 (분리 2) | 시험 레코드 셋(살아 있는 방, 없는 방, 방 없음)이 모두 `ok` 로 받아졌다 |
| 두 서비스를 함께 약 613초 중지(21:58:25~22:08:38 UTC) (NFR-3) | 동일 LAN 의 터널이 끊기지 않았다. 두 쪽 모두 `CONNECTED` 뒤의 상태 전이는 끝에 `quit` 으로 닫은 것 하나뿐이고 `TUNNEL_DROPPED` 가 없다. RTT 표본은 PC 122, `mere-galaxy` 123 으로 연결된 약 630초에 5초 주기로 기대되는 약 126 과 맞는다. 로그 줄에 시각이 없어 표본 사이 간격은 직접 보지 못했다. 호스트의 제어 평면 호출 실패 121, 업로드 실패 쪽마다 10 은 중지 동안의 것이다 |
| 통제된 실패 (1) 아웃바운드 UDP 차단 | `mere-galaxy` 에서 그 사용자의 UDP 를 DNS(53)만 빼고 막고 플레이어로 참가했다. `FAIL STUN_DISCOVERY_FAILED`. 업로드 실패 0. 규칙은 지웠고 240초 뒤 지우는 안전장치도 걸었다 |
| 통제된 실패 (2) 응답 없는 엔드포인트 | 제어 평면 API 로 가짜 호스트를 만들고 RFC 5737 문서용 주소 하나를 후보로 등록했다. 이 PC 가 참가하자 `FAIL HOLE_PUNCH_TIMEOUT`. 업로드 실패 0 |
| 큐가 가득 찬 경우 | 클라이언트 단위 시험 `uploader: a full queue drops the new record and counts it` 가 맡는다. 실제 실행으로는 다시 보지 않았다 |

## 결과: 실측

아래 RTT 는 이 PC 의 로그에서 본 예비 값이다. `experiments.md` 의 숫자는 분석 도구가 테이블에서 낸 값을 쓴다.

| 환경 | 결과 | 쓴 경로 | 이 PC 의 RTT 표본 |
|------|------|---------|-------------------|
| 동일 LAN (집 Wi-Fi 둘, 공인 IP 같음) | 10/10 `CONNECTED` | 10회 모두 사설 주소 | n=59, 중앙값 12.5ms, 사분위 범위 10.2~17.5ms |
| 가정망(이 PC) 대 모바일 핫스팟(`mere-galaxy`, T-Mobile) | 10/10 `CONNECTED` | 10회 모두 공인 주소 | n=58, 중앙값 111.0ms, 사분위 범위 95.4~132.9ms |

- 업로드 실패는 두 환경, 두 기기 모두 0 이다
- 핫스팟에 붙이자 `mere-galaxy` 의 Wi-Fi 절전이 다시 켜져 있었다. 끄고 돌렸다(이슈 0001)

## 확인하지 못한 것
