# 0019. 매핑 수명은 별도 도구로 잰다

- 상태: 채택
- 날짜: 2026-10-08
- 관련: [`../roadmap.md`](../roadmap.md) Phase 4, [`../protocol.md`](../protocol.md) 7장·11장, [`../control_plane.md`](../control_plane.md) 1.1, [`../windows-prereq.md`](../windows-prereq.md) 2절, [ADR 0002](0002-리바인딩-복구-미보장.md)

## 맥락

`protocol.md` 11장의 `KEEPALIVE` 15초와 유휴 타임아웃 50초는 초기값이고 매핑 수명 실측으로 조정한다.
처음 계획은 클라이언트를 유휴로 둔 뒤 EC2 가 클라이언트의 공인 엔드포인트로 UDP probe 를 보내는
것이었다. 클라이언트는 EC2 에 UDP 를 보낸 적이 없으므로 그 probe 는 요청하지 않은 인바운드이고,
`windows-prereq.md` 2절과 `protocol.md` 10.4 의 실측은 그런 인바운드가 전부 막힌다고 말한다. 도착 0 을
"만료" 와 "필터가 닫힘" 으로 가를 수 없다. `roadmap.md` Phase 4 는 이것을 착수 전에 다시 정하라고 했다.

## 결정

저장소 소유자가 별도 도구 쪽을 골랐고 나머지는 그 안에서 정했다.

**1. 클라이언트가 아니라 `tools/nat-lifetime` 의 별도 도구로 잰다.** 클라이언트 쪽과 EC2 쪽이 같은
파일이고 표준 라이브러리만 쓴다.

**2. 클라이언트가 먼저 응답기로 보내고, 응답기는 그 IP:포트에서 요청받은 시간 뒤에 한 번 답한다.**
요청하지 않은 인바운드가 아니다.

**3. 유휴 전에 6초 동안 1초 간격으로 요청과 ACK 를 주고받는다.** 살아 있는 터널처럼 양방향 흐름을 만든다.

**4. 지연값마다 소켓을 따로 열어 병렬로 잰다.** 소켓마다 늦은 답은 하나다.

**5. 가장 짧은 지연이 대조군이다.** 그것이 오지 않으면 판정 불가다.

**6. 응답기는 측정할 때만 EC2 에서 띄우고, 보안 그룹은 측정 기기의 `/32` 로만 잠시 연다.**

**7. `KEEPALIVE` 간격은 `간격 × 3 < 잰 수명의 최솟값` 을 지킨다.** 연속 두 번의 손실을 견딘다. 첫 측정(한
가정의 Wi-Fi, `[58, 60)` 초)에서 15초는 45초라 지킨다. 그래서 15초와 50초를 그대로 둔다. 규칙은
`protocol.md` 11장이 갖는다.

절차, 와이어 형식, 판정 표는 [`tools/nat-lifetime/README.md`](../../../tools/nat-lifetime/README.md) 가 갖는다.

## 대안

**대안 1. Sangtachi 클라이언트의 소켓으로 잰다.**
버렸다. 실제 제품 경로를 잰다는 장점이 있다. 대가는 터널이 Phase 4 구현물이라 착수 전에 돌릴 수 없다는
것, 그리고 probe 가 `protocol.md` 7장 분류를 지나도록 형식을 새로 정해야 한다는 것이다. 재는 대상은
우리 코드가 아니라 NAT 이다.

**대안 2. 한 소켓에서 한 번 보내고 여러 시각에 답을 받는다.**
버렸다. 한 번에 끝난다. 대가는 들어온 패킷이 타이머를 갱신하는 NAT(RFC 4787 REQ-6 이 허용)에서 수명을
길게 재는 것이다.

**대안 3. 데우지 않는다.**
버렸다. 단순하다. 대가는 응답을 본 흐름에 더 긴 타임아웃을 주는 NAT 에서 짧게 재는 것이다. Linux
conntrack 의 기본값은 30초와 120초다.

**대안 4. 한 소켓에서 지연을 차례로 늘린다.**
버렸다. 매핑 하나를 계속 쓴다. 대가는 시간이 지연의 합만큼 걸리는 것이다.

**대안 5. 간격을 수명의 절반 아래로 둔다.**
버렸다. 단순하다. 대가는 연속 손실을 한 번만 견딘다는 것이다. 수명이 60초 근처인 망에서 연속 두 번 손실이면 끊긴다.

## 결과

**얻는 것.**

- Phase 4 구현 전에 잴 수 있다
- 대조군이 "경로가 열린다" 를 시행마다 보여 준다. 도착 0 을 수명 0 으로 오판하지 않는다

**치르는 것.**

- 클라이언트의 소켓이 아니다. 같은 NAT 이어도 우리 프로세스의 호스트 방화벽 상태는 재지 않는다
- 상대가 EC2 하나다. 목적지마다 타이머가 다른 NAT 이면 피어 간 경로와 다를 수 있다
- 측정할 때마다 사람이 보안 그룹을 열고 닫는다
