# 시험 실행을 기본, `-Full`, `-Slow` 로 나눈다

## 왜 했나

저장소 소유자가 `scripts/test.ps1` 이 너무 오래 걸린다고 했다. 한 번에 11~12분이었다. 먼저 시험마다 무엇을 판정하는지,
단위 시험과 겹치는지, 시간이 어디서 드는지 조사했다. 소유자는 조사 보고의 권고를 모두 승인했다.

- 시간의 93% 가 `session-check`(493초)와 `lobby-check`(158초)였다. 둘 다 프로토콜 타이머를 실제 시간으로 기다린다
- 지울 시험은 찾지 못했다. 두 스크립트의 장면 다수가 `roadmap.md` 항목을 끝에서 끝까지 판정하는 유일한 자리다
- ctest 665건에도 버려진 기능의 시험이나 중복은 없었다

## 무엇을 바꿨나

- `departed-now` 의 정기 `host_report` 대기는 남겼다. 즉시 보고와 정기 보고를 가르는 판정이다
- `loop-alive` 는 기본 실행에 남겼다. `[loop]` 정지 판정의 유일한 끝에서 끝까지 자리다
- 빌드 폴더 `C:\me\build\test\Debug\.ninja_deps` 가 깨져 변경이 없어도 33단계를 다시 지었다. 소유자 승인으로 지웠다. 레포 밖이다. 그 뒤 두 번째 빌드는 2.0초이고 `ninja: no work to do` 다

## 작업 중에 생긴 일

- 작업 도중 계정 한도로 모델이 바뀌며 하위 작업자 둘이 보고 없이 끝났다. 남은 차이를 직접 다시 읽었다. `lobby-check.ps1` 의 `host-report-rate` 에 작업자가 변이 확인용으로 넣은 `leave` 와 `mutation:` 확인이 되돌려지지 않고 남아 있었다. 지웠다. 그대로 두면 그 장면은 늘 실패했다. 위 검증은 지운 뒤에 처음부터 다시 돌렸다
- 재개 직후 `-Full` 이 실패했다. Docker Desktop 이 꺼져 DynamoDB local 이 없었다. 하네스가 그렇게 말하고 실패했다. 띄운 뒤 다시 돌렸다
