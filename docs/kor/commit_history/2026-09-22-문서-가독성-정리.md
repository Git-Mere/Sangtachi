# 살아 있는 문서 7개의 가독성 정리

## 무엇을 했나

리뷰 라운드를 여러 번 거치면서 살아 있는 문서가 사람이 읽기 어려워졌다. 규칙 여섯 개를
정하고 `docs/kor` 의 문서 일곱에 적용했다. 기록 폴더(`audit-history/`, `commit_history/`,
`decisions/`)는 대상이 아니다.

| 규칙 | 내용 |
|------|------|
| R1 | 규칙과 근거를 층위로 나눈다. 한두 문장이면 `> **왜.**` 블록, 문단 단위면 장 끝의 근거 절 |
| R2 | 한 절 안에서 같은 문서는 첫 등장만 링크한다. 두 번째부터는 평문 |
| R3 | 번호 참조에 그 절의 실제 헤딩 제목을 붙인다. 괄호 인용(`(9.3)`)은 대상이 아니다 |
| R4 | 볼드는 문단당 하나. 문단 첫머리의 식별자 라벨은 세지 않는다 |
| R5 | 경과 서술을 지운다. 현재 사양이 섞여 있으면 사양만 남긴다 |
| R6 | 기준, 절차, 근거, 반례를 한 불릿에 담지 않는다 |

## 검증

셀 수 있는 것은 스크립트가 했다. 리뷰어에게 맡기지 않았다.

- 계측기: 링크 중복, 볼드 과다 블록, 이름 없는 번호 참조, 긴 줄을 센다
- 내용 보존 검사: `HEAD` 판과 비교해 사라진 코드 스팬, 식별자, 수치, 링크 경로를 낸다.
  **변이 시험으로 한계를 확인했다.** 코드 스팬이 든 문단 삭제와 수치 1건 삭제는 잡았고,
  코드·수치·식별자가 없는 산문 문장의 삭제는 **못 잡았다.** 그래서 이것을 내용 보존의
  판정으로 쓰지 않았다
- `docgate.py`: `link` findings 0건. `mirror` 와 `parity` 는 영어 미러가 밀려 정상이다
- 이동 대장: 문서마다 옮기거나 지운 것을 표로 남겼다. 표 행 합계 294건. 레포 밖에 둔다

## 크로스 모델 리뷰

렌즈 셋을 따로 돌렸다. 묶지 않았다.

| 렌즈 | 입력 | 결과 |
|------|------|------|
| 구멍과 과장 | 문서별 diff 6건 | 전부 `LGTM` |
| 시나리오 추적 | `protocol.md` + `architecture.md` + `control_plane.md` 본문 | `LGTM` |
| 사람이 읽기 좋아졌는가 | `spec.md` + `roadmap.md` + `control_plane.md` 본문 | **blocker 1, warn 4, nit 1** |

**구멍 렌즈 여섯과 시나리오 렌즈가 전부 `LGTM` 인 같은 변경에서 가독성 렌즈가 blocker 를
냈다.** 한 렌즈의 `LGTM` 은 깨끗하다는 뜻이 아니라는 것이 다시 확인됐다. 렌즈를 이번 작업의
목적에 맞춘 것이 차이를 만들었다.

## 이번에 겪은 것

- **하위 에이전트가 계획만 세우고 편집을 파일에 쓰지 않는 일이 반복됐다.** `roadmap.md` 담당이
  네 번, `architecture.md` 담당이 한 번이다. 편집을 메모리에 모았다가 마지막에 쓰려다 그
  전에 턴이 끝났다. "절 하나를 고칠 때마다 바로 파일에 쓰고 `git diff --stat` 으로 확인하라"
  고 지시한 뒤에 진척이 났다
- **같은 파일을 하위 에이전트와 내가 동시에 고쳤다.** 담당이 그것을 알아채고 보고했다.
  그쪽은 파일 전체를 읽고 다시 쓰는 방식이라 타이밍이 나빴으면 내 편집이 사라졌다.
  결과는 무사했으나 확인은 손으로 했다
- **계측기가 두 번 틀렸다.** 처음에는 IP 주소(`10.100.0.1`)와 버전 번호(`Python 3.11`)를
  죽은 절 참조로 잡았고, 조사 판정이 `2.5 가상 IP 풀` 의 "가" 를 조사로 읽었다. 둘 다 고쳤고,
  판정할 수 없는 항목은 참고 목록으로 내렸다
- **내용 보존 검사도 한 번 잘못 만들었다.** 줄바꿈된 코드 스팬을 이으려고 문서 전체를 한
  줄로 합쳐 오탐 44건이 났다. 문단 단위로 잇도록 고쳤다
