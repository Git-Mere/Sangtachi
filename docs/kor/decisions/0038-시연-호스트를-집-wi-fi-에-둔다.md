# 0038. 시연 호스트를 소유자의 집 Wi-Fi 에 둔다

- 상태: 채택
- 날짜: 2026-11-02
- 관련: [ADR 0034](0034-phase-8-착수-전-결정.md), [ADR 0037](0037-시연-전-확인을-리허설-한-번으로.md), [`../roadmap.md`](../roadmap.md) Phase 8 작업, [`../experiments.md`](../experiments.md) 3.2·3.3

## 맥락

[ADR 0034](0034-phase-8-착수-전-결정.md) 는 시연 망을 "호스트는 학교에서 소유자의 휴대폰 핫스팟, 플레이어는 집 Wi-Fi" 로 정했다.
2026-11-02 리허설은 그 망 쌍으로 했다. 호스트는 Linux 기기 `G` 였고 Minecraft 서버도 `G` 에 있다(`experiments.md` 3.3).

리허설 날 두 가지를 봤다.

- 학교 유선 LAN 에서는 Tailscale 제어 서버에 닿지 않아 다른 기기를 원격으로 다룰 수 없었다
- 핫스팟을 들고 자리를 뜨자 호스트가 끊겨 방을 다시 만들어야 했다

## 결정

저장소 소유자의 결정이다.

| 자리 | 고른 것 |
|------|---------|
| 호스트 | `G`. 소유자의 집 Wi-Fi 에 두고 Linux 콘솔 호스트와 Minecraft 서버를 띄운다 |
| 소유자 | Windows 기기 `A` 의 GUI 로 학교에서 휴대폰 핫스팟에 붙어 참가한다. 휴대폰의 Wi-Fi 는 끈다 |
| 시연 플레이어 | 자기 집 Wi-Fi 에서 GUI 로 참가한다 |
| 다른 플레이어 | 소유자의 친구가 할 수 있으면 자기 집 Wi-Fi 에서 GUI 로 참가한다 |

[ADR 0037](0037-시연-전-확인을-리허설-한-번으로.md) 의 리허설 규칙은 그대로다. 망 쌍이 바뀌었으므로 2026-11-02 리허설은 이 시연 망을
덮지 않는다. 시연 전에 새 망 쌍으로 다시 한 번 한다.

## 대안

**대안 1. ADR 0034 의 시연 망을 그대로 둔다.** 버렸다. 호스트가 휴대폰에 묶여 있어 휴대폰이 멀어지면 시연이 끊긴다.

**대안 2. 소유자의 `A` 를 학교 유선 LAN 에 붙인다.** 버렸다. 그 망에서는 Tailscale 이 막혀 집의 `G` 를 다시 띄울 수 없다. 집 Wi-Fi 와
학교 유선 LAN 사이 연결은 잰 적이 없다.

**대안 3. `A` 를 GUI 호스트로 하고 Minecraft 를 "LAN 에 열기" 로 연다.** 버렸다. 리허설한 호스트와 서버를 그대로 쓰는 편을 골랐다.

## 결과

- 호스트와 소유자 사이는 집 Wi-Fi 와 휴대폰 핫스팟이다. 3.2 와 같은 두 망이고 호스트 쪽만 바뀌었다
- 호스트와 시연 플레이어 사이, 호스트와 친구 사이는 아직 잰 적이 없는 망 쌍이다. 리허설이 그것을 본다
- `G` 는 사람 없이 집에서 돈다. 잠들지 않게 하고 Wi-Fi 절전을 끈 채 둔다. 방은 호스트가 살아 있는 동안 열려 있다([`../control_plane.md`](../control_plane.md) 5.1)
- 시연의 호스트가 콘솔이므로 시연은 `spec.md` T-7 의 GUI 만의 흐름을 채우지 않는다
