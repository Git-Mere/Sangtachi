# 0008. 스타 토폴로지와 GUI 의 후속 결정 아홉

- 상태: 채택
- 날짜: 2026-09-28
- 관련: [ADR 0006](0006-무중계-스타-토폴로지.md), [ADR 0007](0007-gui-핵심-범위-qt.md), [`../protocol.md`](../protocol.md) 5장·8.5·10.2·14장, [`../control_plane.md`](../control_plane.md) 2.4·2.5·4.3·4.4·4.5, [`../concurrency.md`](../concurrency.md) 7장, [`../architecture.md`](../architecture.md) 3.5·8장·9장, [`../spec.md`](../spec.md) FR-13·FR-15

## 맥락

[ADR 0006](0006-무중계-스타-토폴로지.md)이 토폴로지만 정하고 일곱 항목을 "이 ADR 이 정하지
않는 것" 으로 남겼다. [ADR 0007](0007-gui-핵심-범위-qt.md)이 GUI 의 범위와 등급과 툴킷만
정하고 넷을 남겼다. 두 목록은 겹친다. 멤버의 연결 상태를 무엇이 나르는가는 양쪽에 같은
질문으로 들어 있다.

남은 항목들은 서로 묶여 있어서 따로 정할 수 없었다. 가상 IP 자리를 회수할지는 재참가를
남길지에 달려 있고, 재참가를 남길지는 호스트가 사라졌을 때 프로세스가 무엇을 하는지에
달려 있다. 그래서 저장소 소유자가 아홉을 한 번에 정했다.

**이 문서는 그 판단의 기록이다.** 값과 규칙의 출처는 살아 있는 문서다. 아래 결정을 실제로
집행하는 문장은 `protocol.md`, `control_plane.md`, `concurrency.md`, `architecture.md`,
`spec.md` 가 갖는다.

## 결정

### 1. 호스트가 사라지면 플레이어는 방에서 나가고 프로세스는 로비로 간다

터널 쪽 결과는 ADR 0006 결정 4 가 이미 정했다. 호스트의 세션이 끝나면 그 방의 모든 터널이
끝난다. 이 결정이 더하는 것은 그 뒤다. 플레이어는 제어 평면의 방에서도 나가고, 프로세스는
죽지 않고 방을 고르는 상태로 돌아간다.

`concurrency.md` 7장 종료의 아래 문장을 뒤집는다.

> **종료 상태에 도달하면 프로세스도 끝난다.** 세션이 `FAILED`나 `CLOSED`가 되면 (...)
> 최소 범위의 세션은 하나이므로 그 세션이 끝나면 프로세스가 할 일이 없다.

ADR 0006 결정 6 이 요구한 일반화를 그대로 쓴다. 규칙은 세션 목록으로 적는다. 목록이 비면
로비로 간다. 플레이어는 목록이 1개인 경우다.

### 2. 준비 완료와 `punch_delay_ms` 를 쌍 단위로 옮긴다

지금은 방 단위다. `control_plane.md` 4.5 `get_peers` 가 "준비 완료의 정의는
`ROOM.ready_at_wall_ms` 의 존재다" 로 적고, `protocol.md` 14장 계약 3 이
"`punch_delay_ms` 는 두 번째 등록 완료 시 방 단위로 한 번 확정" 으로 적는다.

쌍 단위로 옮긴다. 호스트와 플레이어 한 쌍의 후보가 모두 등록되면 그 쌍이 준비 완료다.
다른 쌍의 상태를 보지 않는다.

**늦은 참가를 허용한다.** ADR 0006 이 미결로 둔 항목이고, 이 결정의 결과다. 늦게 켠
플레이어는 자기 쌍만 준비되면 펀치한다. 이미 붙어 있는 세션은 영향을 받지 않는다.

### 3. 송신 검사는 목적지로 세션을 고른 뒤 상태를 본다

ADR 0006 결정 3 이 문제를 지적하고 순서는 정하지 않았다. `protocol.md` 8.5 송신 측 검증의
현재 1번이 "상태가 `CONNECTED`" 인데, 세션이 여럿이면 목적지로 세션을 고르기 전에는 그
상태가 어느 세션의 것인지 정해지지 않는다.

새 순서는 여섯이다.

| # | 검사 | 실패 카운터 |
|---|------|-------------|
| 1 | 길이 >= 20 | `tx_drop_short` |
| 2 | IP 버전 니블 == 4 | `tx_drop_not_ipv4` |
| 3 | 길이 <= `MAX_INNER` | `tx_drop_oversize` |
| 4 | 출발지 IP == 자신의 가상 IP | `tx_drop_bad_src` |
| 5 | 목적지 IP 로 세션을 고른다. 없으면 실패 | `tx_drop_no_route` |
| 6 | 고른 세션이 `CONNECTED` | `tx_drop_not_connected` |

길이 검사가 맨 앞인 이유는 지금 표와 같다. 출발지와 목적지는 오프셋 12~20 에 있으므로
20바이트 하한을 확인하기 전에 읽으면 버퍼 밖을 읽는다.

**라우팅 표는 6칸 고정 배열이다.** 인덱스는 목적지 가상 IP 의 마지막 옥텟(0~5)이고 값은
세션이다. 조회는 두 단계다. 먼저 목적지가 가상 대역 안인지 보고, 그다음 칸을 읽는다. 대역
밖, 브로드캐스트, 멀티캐스트는 첫 단계에서 걸린다.

- 자기 자신의 칸은 비워 둔다. 자기 가상 IP 로 보낸 패킷은 경로가 없다
- 플레이어의 표는 호스트 칸 하나만 찬다. 다른 플레이어 칸이 비어 있는 것이 ADR 0006 결정 2 를
  집행하는 자리다
- 표의 소유자는 `[loop]` 스레드다. 세션이 생기고 사라질 때만 바뀐다

> **왜.** 가상 IP 풀이 `10.100.0.1` 부터 `10.100.0.5` 로 고정이므로(ADR 0006 결정 5) 해시맵이
> 필요 없다. 고정 배열은 할당이 없고 조회 시간이 일정하다.

`tx_drop_no_route` 는 전역 카운터다. 세션을 고르지 못한 경우라 귀속시킬 세션이 없다.

### 4. 방 명부와 연결 상태는 호스트가 터널로 보낸다

ADR 0006 과 0007 의 같은 질문에 대한 답이다. 새 터널 메시지 타입을 하나 만들고, 호스트가
각 플레이어에게 방 명부와 각 멤버의 연결 상태를 보낸다.

근거는 진실의 출처다. ADR 0006 이 적은 그대로 호스트는 모든 세션을 직접 가지므로 누가 붙어
있는지를 원래 안다. 제어 평면이 아는 것은 `joined` 와 `registered` 뿐이고 둘 다 연결 여부가
아니다(`control_plane.md` 5.3 피어).

**제어 평면을 확장하지 않는다.** 별도의 서비스 서버도 만들지 않는다. 계정, 친구 목록, 방
목록, 프레즌스는 이 프로젝트의 범위가 아니다.

이 결정이 `spec.md` FR-15 의 셋째 동작과 T-7 의 마지막 조건을 판정 가능하게 만든다.

### 5. 나간 피어의 가상 IP 자리를 회수한다

`control_plane.md` 2.5 가상 IP 풀의 아래 규칙을 뒤집는다.

> **방 살아 있는 동안에는 회수하지 않는다.** 피어가 나가도 자리는 그 피어 것이다.
> 재참가(4.3)가 같은 주소를 돌려줘야 하기 때문이다.

그 규칙의 근거가 재참가였고, 결정 6 이 재참가를 없앤다. 근거가 사라지므로 규칙도 바뀐다.
회수한 자리에는 새 참가가 들어올 수 있다.

### 6. 재참가를 제거한다

`control_plane.md` 4.3 `join_room` 의 두 형식 중 재참가를 없앤다. 대상은 넷이다.

| 대상 | 어디 |
|------|------|
| `join_room` 재참가 형식과 그에 딸린 서술 | `control_plane.md` 4.3 |
| 계약 7 (재참가한 피어에게 같은 `peer_id` 와 가상 IP) | `protocol.md` 14장 |
| `--rejoin` 인자와 `REJOIN` 표준 출력 줄 | `architecture.md` 3.5 기동 입력, `client/src/args.cpp` |
| 재참가가 후보를 지운 뒤의 "준비 완료인데 상대 후보가 0개" 구간 | `control_plane.md` 4.5 |

**`peer_token` 은 남는다.** `get_peers` 와 `register_candidate` 가 그것으로 인증한다. 없어지는
것은 재시작을 건너 살아남는 증명이다.

**프로세스가 죽으면 그 피어는 자리를 잃는다.** 다시 들어오려면 새 참가이고 가상 IP 가 바뀐다.
플레이어는 호스트의 `10.100.0.1` 로만 접속하므로 게임 쪽 영향이 작다. 호스트가 재시작하면
방이 없어지고 방 코드를 다시 나눈다. 결정 1 과 같은 방향이다.

### 7. 회수의 방아쇠는 호스트다

호스트가 세션이 끊긴 것을 제어 평면에 알린다. 그 호출이 그 피어의 항목과 가상 IP 선점을
지운다. 새 연산이 하나 는다.

근거는 결정 4 와 같다. 끊김을 아는 것은 호스트이고, 제어 평면은 자기가 모르는 사실을
저장하지 않는다.

### 8. 콘솔 빌드도 로비로 돌아간다

결정 1 을 빌드로 가르지 않는다. 콘솔 빌드도 세션이 없으면 종료하지 않고 방을 만들거나
방 코드를 입력하는 상태로 돌아간다.

**프로세스 수명과 세션 수명이 분리된다.** 이 결정의 파급이 가장 크다. `concurrency.md` 7장
종료가 "자동 재시도를 정하면 이 줄을 다시 본다" 로 예고한 자리이고, 여기서 그 줄을 다시 본다.

### 9. 실패는 코드와 사람 말을 함께 보여 준다

`spec.md` FR-13 의 실패 코드를 그대로 내고, 그 옆에 사람이 읽는 문장을 함께 낸다. 둘 중
하나만 내지 않는다.

> **왜.** 코드만 내면 사용자가 무엇을 해야 할지 모르고, 문장만 내면 사용자가 보고한 내용을
> `architecture.md` 8장 실패 진단의 분류와 맞출 수 없다.

## 이 ADR 이 정하지 않는 것

정하는 자리는 살아 있는 문서이고 시점은 [`../roadmap.md`](../roadmap.md) 가 갖는다.

| 항목 | 정하는 문서 |
|------|-------------|
| 결정 4 의 터널 메시지 와이어 레이아웃, 송신 시점, 크기 상한, 수신 검증 | `protocol.md` 5장과 8장 |
| 결정 7 의 연산 이름, 인증 방법, 경합 규칙, 호스트가 나갈 때의 방 처리 | `control_plane.md` 4장 |
| 결정 8 의 로비가 받는 입력. 콘솔 어휘와 CLI 인자의 관계 | `architecture.md` 3.5 기동 입력 |
| `client_nonce` 의 범위. 지금 규칙은 한 기동에 한 값이고(`control_plane.md` 2.4) 로비 복귀는 한 기동에 여러 번 참가한다 | `control_plane.md` 2.4 |
| 로비로 돌아갈 때 소켓과 STUN 결과를 재사용하는가 | `protocol.md` 6장, 10.1, 13장 |
| 방이 바뀔 때 어댑터 주소를 다시 설정하는 절차 | `concurrency.md` 3장, Phase 6 |
| 결정 9 의 문장 목록과 그 문장을 어디에 두는가 | `architecture.md` 8장 |
| GUI 스레드 모델과 GUI 기동 입력 경로 | ADR 0007 이 남긴 미결. Phase 8 |

**결정 6 이 `protocol.md` 14장의 계약을 여덟에서 일곱으로 줄인다.** 번호를 다시 매길지는 그
문서가 정한다.

## 대안

**대안 1. 멤버 상태를 제어 평면이 나른다.**
버렸다. 피어들이 연결 상태를 계속 보고해야 하고, 그러면 제어 평면이 데이터 평면 상태의 낡은
사본을 갖는다. 연결이 성립한 뒤에도 폴링이 계속 돈다. 얻는 것은 터널 프로토콜을 건드리지
않는 것이었다.

**대안 2. 멤버 상태를 만들지 않는다.**
버렸다. `spec.md` FR-15 의 셋째 동작과 T-7 의 마지막 조건을 판정할 수 없다. ADR 0007 이
최소 GUI 를 핵심 범위로 올린 것과 어긋난다.

**대안 3. 재참가를 남긴다.**
버렸다. 남기면 가상 IP 자리를 회수할 수 없다(`control_plane.md` 2.5). 결정 5 와 함께 설
수 없는 대안이다. 얻는 것은 프로세스가 죽어도 같은 자리로 돌아오는 것이었고, 그 가치는
호스트가 사라지면 방이 끝나는 구조(ADR 0006 결정 4)에서 작다.

**대안 4. 회수를 피어 항목의 TTL 로 한다.**
버렸다. 연산이 늘지 않는 것이 장점이었다. 대가는 연결이 성립한 뒤에도 각 피어가 제어 평면을
주기적으로 두드려야 하는 것이고, 만료 시간만큼 자리가 늦게 비는 것이다.

**대안 5. 콘솔 빌드는 종료한다.**
버렸다. 저장소 소유자의 결정이다. 장점은 `concurrency.md` 7장을 거의 그대로 두는 것이었다.
대가는 콘솔과 GUI 의 수명 규칙이 둘로 갈리는 것이고, ADR 0006 결정 6 이 규칙을 한 벌로
적으라고 한 것과 어긋난다.

## 결과

**얻는 것.**

- ADR 0006 의 미결 일곱 중 여섯과 ADR 0007 의 미결 넷 중 둘이 닫힌다. 남은 것은 GUI 스레드
  모델과 GUI 기동 입력 경로이고 둘 다 Phase 8 이다
- 문서가 줄어드는 자리가 있다. 재참가 제거가 `join_room` 의 두 형식, `unauthorized` 사유
  하나, 후보 삭제 서술, `get_peers` 의 후보 0개 구간을 함께 없앤다
- 늦은 참가가 별도 장치 없이 성립한다. 쌍 단위 준비 완료의 결과다
- 규칙이 한 벌로 남는다. 종료, 송신 검사 순서, 로비 복귀가 호스트용과 플레이어용으로,
  콘솔용과 GUI 용으로 갈리지 않는다

**치르는 것.**

- **프로세스 수명과 세션 수명이 분리된다.** 기동 입력, `client_nonce` 범위, 소켓과 STUN 결과의
  재사용, 어댑터 주소 재설정, 종료 코드의 뜻이 모두 이 분리에 걸린다. 위 "이 ADR 이 정하지
  않는 것" 의 절반이 여기서 나왔다
- 터널 프로토콜에 메시지 타입이 하나 늘고 그만큼 수신 검증과 시험이 는다
- 제어 평면에 연산이 하나 는다. 그 연산은 호출자가 호스트인지 확인해야 한다
- 프로세스가 죽은 피어는 같은 가상 IP 로 돌아오지 못한다
- 라우팅 표가 대역과 풀 크기에 묶인다. 대역을 바꾸면(Phase 6 의 대체 대역 항목) 표의 인덱스
  규칙도 같이 본다

**확인하지 못한 것.**

- 호스트가 종료할 때 `CLOSE` 최대 4개와 어댑터 정리가 `CTRL_CLOSE_EVENT` 의 3초 유예에
  드는가. ADR 0006 이 남긴 항목이고 정하는 것이 아니라 재는 것이다
- 로비 복귀가 NAT 매핑에 무엇을 하는가. 같은 소켓을 유지하면 매핑이 유지될 것으로 보이지만
  측정하지 않았다
- 5인 동시 참가에서 쌍 단위 준비 완료의 경합 거동. 지금 케이스 표는 2자 기준이다
  (`control_plane.md` 4.4)
