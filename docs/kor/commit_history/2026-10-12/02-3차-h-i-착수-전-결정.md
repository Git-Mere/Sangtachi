# 3차 H·I 착수 전 결정 (ADR 0023)

## 왜 했나

3차 H 와 I 를 시작하기 전에 문서가 정하지 않은 자리가 일곱 있었다. 선택지와 추천을 저장소 소유자에게 정리해 보였고 소유자가
추천을 모두 받았다. 구현 전에 문서를 먼저 고친다(`CLAUDE.md`).

## 무엇을 바꿨나

| 결정 | 자리 |
|------|------|
| 훅 칸은 core 에 두고 제품 빌드는 비워 둔다. 시험 전용 코드(`data.tx`, `data.rx`, 에코 응답기)는 시험 빌드 CMake 옵션 안에만 | `concurrency.md` 3장, `roadmap.md` Phase 4 `DATA` 왕복 |
| `send <n> [size] [to]`. `to` 는 목적지 가상 IP, `CONNECTED` 세션이 하나일 때만 생략 | `roadmap.md` Phase 4 콘솔 명령, Phase 5 크기 표의 단서 |
| M-5 비교는 시험 빌드 로그 `data.tx`/`data.rx` 의 `len`, `sha256` 대조 | `architecture.md` 9장 고정 이벤트 표, `roadmap.md` Phase 4 `DATA` 왕복 |
| `generation` 은 방을 세울 때 0, 호스트에 하나 | `protocol.md` 5.7 |
| `CONNECTED` 진입의 즉시 송신과 명부 변경의 즉시 송신은 같은 한 번 | `protocol.md` 5.7, 11장 타이머 표 |
| 명부가 바뀐 것은 실을 내용이 바뀐 것 | `protocol.md` 5.7 |
| 플레이어는 받아들인 명부마다 `roster` 로그 줄 | `protocol.md` 5.7, `architecture.md` 9장 고정 이벤트 표 |
| ADR | `decisions/0023` |
| 결정이 닫은 두 행을 지우고, I 는 멤버 목록 입력까지이며 `host_report` 연결은 4차 J 라고 적었다 | `plan.md` |

## 크로스 모델 리뷰

Codex 에 문서 일관성 렌즈(새 규칙과 어긋나는 살아 있는 문장, 미러 차이, 기록이 뒷받침되지 않는 주장)로 돌렸다.

| 지적 | 처리 |
|------|------|
| warn. "길이를 포함해 byte-for-byte 비교" 가 남아 새 `len`·`sha256` 비교와 어긋난다 | 반영. 비교하는 값이 길이와 바이트열 전체의 `sha256` 이라고 고쳤다. `concurrency.md` 3장 표와 Phase 4 레이아웃 근거의 같은 말도 고쳤다 |
| warn. `data.tx` 를 훅에 붙는 코드로 적었다. 그것은 송신 측이다 | 반영. 시험 전용 코드를 송신 측 `data.tx` 와 훅에 붙는 `data.rx`·에코 응답기로 나눠 적었다. `roadmap.md`, ADR, 이 기록 |

수정 확인 리뷰는 사소한 지적 하나(영어 기록의 시제)만 냈고 반영했다.
