# 0027. Phase 6 구현 결정

- 상태: 채택
- 날짜: 2026-10-15
- 관련: [`../architecture.md`](../architecture.md) 3.5·7장, [`../concurrency.md`](../concurrency.md) 2·3·5장, [`../windows-prereq.md`](../windows-prereq.md) 1·3·4·7·8·9절, [`../roadmap.md`](../roadmap.md) Phase 6·7, [ADR 0026](0026-phase-6-착수-전-결정.md)

## 맥락

Phase 6 을 구현하려고 보니 문서가 정하지 않은 자리가 여럿이었다. 저장소 소유자는 Phase 6 을 끝까지 하라고 했고, 아래는 구현하면서
정한 것이다. 소유자에게 사후에 보고했다.

- 어댑터는 관리자 권한이 있어야 만들 수 있다. 그런데 `scripts/test.ps1` 의 같은 기기 시험은 관리자 권한 없이 여러 프로세스를
  띄우고, 한 기기에서 어댑터는 하나만 만들 수 있다
- `windows-prereq.md` 3절은 어댑터의 GUID 를 "상태 파일" 에 기록한다고만 적었다. 파일의 자리와 형식이 없다
- 어댑터를 언제 만들고 주소를 언제 붙이는지, 기동 검사의 순서와 실패의 거동이 흩어져 있거나 없었다
- 7절 서브넷 충돌의 판정은 스크립트에 있는데, 클라이언트가 그것을 어떻게 쓰는지가 없었다
- 4절 분류의 "클라이언트(실행 시 확인)" 이 무엇을 보는지가 없었다
- `concurrency.md` 3장 `drain_wintun` 의 "그 외 오류" 가 올리는 카운터 이름이 없었다
- Phase 6 의 읽기 경로가 Phase 7 의 라우팅과 어디서 갈리는지가 없었다

## 결정

| 자리 | 고른 것 |
|------|---------|
| 어댑터 없는 실행 | 기동 인자 `--no-adapter`. 두 빌드 모두 받는다. 기본은 어댑터를 만든다. 같은 기기 시험 스크립트가 모두 붙인다 |
| 어댑터의 기록 | 이름, 터널 형식, GUID 를 코드 상수로 둔다(`client/include/sangtachi/adapter.hpp`). 상태 파일을 두지 않는다. 터널 형식은 `Wintun` 이다. 서브넷 충돌 스크립트가 설명이 Wintun 인 어댑터만 자기 것으로 빼기 때문이다 |
| 어댑터 수명 | 프로세스와 같이 산다. 주소는 `create_room`, `join_room` 성공 응답에서 붙이고 방을 떠날 때 뗀다. 표는 `architecture.md` 7장 |
| 기동 검사 | 관리자 권한, 서브넷 충돌, DLL 해시 순서다. 하나라도 어긋나면 기동 실패(종료 코드 2)다 |
| 서브넷 충돌 | 실행 파일 옆의 `Test-SubnetOverlap.ps1` 을 `System32` 의 Windows PowerShell 로 부르고 종료 코드로 판정한다. 환경에서 `PSModulePath` 를 빼고, 물려주는 핸들을 표준 입출력 둘로 좁히고, 30초 상한을 둔다 |
| 실행 시 확인 | `wintun.dll` 을 실행 파일 폴더에서만 불러오고, 부르기 전에 SHA-256 을 기대값과 비교한다. 기대값은 `cmake/Wintun.cmake` 에서 생성한 헤더로 온다 |
| 주소 설정 | `/24` 로 붙이고, DAD 를 끄고, on-link 경로가 없을 때만 만든다. `Preferred` 를 10초까지 기다린다. 실패하면 `ERROR` 한 줄과 종료다 |
| 어댑터 수신의 그 밖의 오류 | 카운터 `rx_err_adapter` |
| Phase 6 의 읽기 경로 | 읽은 패킷은 `adapter_rx` 로 센 뒤 시험 빌드의 ICMP 응답기에만 넘긴다. 제품 빌드는 버린다. 라우팅과 `DATA` 의 주입은 Phase 7 이다 |
| 방화벽 규칙 | Phase 7 작업으로 옮긴다. Phase 6 검증의 ping 은 이 기기가 보낸 요청에 대한 응답이라 들어오는 규칙이 필요 없다 |
| 관리자 검증 | `scripts/adapter-check.ps1`. 관리자 권한이 필요해 `scripts/test.ps1` 에 넣지 않는다 |

## 대안

**어댑터 없는 실행.** 관리자가 아니면 어댑터 없이 계속 도는 안을 버렸다. `windows-prereq.md` 1절이 "시작 전에 막는다" 고 정했고,
권한 문제가 조용히 지나가면 터널이 살아 있는 척한다. 시험 빌드에서만 어댑터를 끄는 안도 버렸다. Phase 6 검증의 ICMP 응답기가 시험
빌드에 있으므로 시험 빌드도 어댑터를 만들어야 한다. 어댑터를 켜는 쪽을 스위치로 두는 안(`--adapter`)은 제품의 기본이 어댑터 없는
것이 되어 버렸다.

**어댑터의 기록.** 무작위 GUID 를 상태 파일에 적는 안을 버렸다. 파일의 자리, 형식, 유실 처리가 새로 생긴다. 상수는 잃을 수
없다. 같은 GUID 를 쓰는 남의 어댑터는 일부러 만들지 않는 한 없다.

**어댑터 수명.** 첫 방에서 어댑터를 만드는 안을 버렸다. 관리자 권한과 서브넷 충돌을 방을 세운 뒤에야 알게 된다.
`concurrency.md` 7장 로비가 이미 "어댑터 세션은 유지한다" 고 적었다.

**서브넷 충돌.** 판정을 C++ 로 옮기는 안을 버렸다. 85건의 케이스 표가 두 벌이 된다. 스크립트의 출력을 판정에 쓰는 안도 버렸다.
출력은 콘솔 코드 페이지라 이름이 깨질 수 있다. 판정은 종료 코드이고 출력은 `ERROR` 줄의 진단으로만 쓴다.

**실행 시 확인.** 실행 때 서명을 다시 보는 안을 버렸다. `WinVerifyTrust` 호출이 늘지만, 해시가 같으면 빌드가 판정한 그 파일이다.

**주소 설정.** DAD 를 켜 두고 `Preferred` 를 기다리는 안을 버렸다. 점대점 터널이라 물어볼 상대가 없고, 그동안 `[loop]` 가 막힌다.
주소 설정을 `[control]` 로 옮기는 안도 버렸다. 방마다 한 번이고 DAD 를 끄면 기다림이 거의 없다.

**터널 형식.** 처음에는 `Sangtachi` 로 두었다. 관리자 확인에서 어댑터 설명이 `Sangtachi Tunnel` 이 되어 서브넷 충돌 스크립트가
살아 있는 자기 어댑터를 빼지 않았다(`not-wintun`). 스크립트의 조건을 넓히는 안을 버렸다. 그 조건은 이름을 흉내 낸 남의
어댑터를 거르는 장치 가운데 하나다.

**Phase 6 의 읽기 경로.** 읽은 패킷을 바로 터널에 잇는 안을 버렸다. `roadmap.md` 가 그것을 Phase 7 작업으로 두었고, 두 기기 없이
검증할 수 없다.

## 결과

**얻는 것.**

- 같은 기기 시험이 관리자 권한 없이 그대로 돈다
- 어댑터를 가리는 값이 하나라 서브넷 검사, 후보 수집의 제외, 잔존 정리가 같은 값을 쓴다
- 빌드와 실행이 같은 기대값 파일 하나를 본다

**치르는 것.**

- 어댑터를 쓰는 실행은 관리자 권한이 필요하고, 한 기기에 하나만 돈다
- 기동이 PowerShell 한 번만큼 느려진다
- 어댑터 검증은 사람이 관리자 셸에서 돌려야 한다
