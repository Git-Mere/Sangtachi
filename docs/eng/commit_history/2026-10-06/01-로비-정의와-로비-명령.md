# Redefined the Lobby as Room Membership, and Made the Server Reclaim the Seat of a Participant Who Left Without Candidates

## Why

Among the `roadmap.md` Phase 3 before-start items, one could be finished with documents alone. It
covers the input the lobby takes, the `FAIL` line, and the process behaviour after an attempt fails.
ADR 0008 decision 8 fixed "the console build also returns to the lobby" and handed "the relation
between the console vocabulary and the CLI arguments" to `architecture.md` 3.5, but that text was
missing.

In the same work the "Next to do" table of `plan.md` was fixed. Item 1, the eng mirror (`bfd2b54`),
and item 2, the Phase 2 audit (`baa1374`), were already done but were still listed.

## What the Repository Owner Decided

The agent proposed options and the owner chose the recommended option every time. It was asked in
two batches.

| What was asked | What was decided |
|----------------|------------------|
| Lobby commands | `host`, `join <room code>`. `WARN` if already in a room or a request is pending |
| Relation between the CLI and the lobby commands | A CLI role is a lobby command right after startup. A role is not required |
| After an attempt fails | Emit a `FAIL` line and go to the lobby. The exit code does not carry the attempt result |
| `[console]` from Phase 6 on | It stays in the console build. Only `--peer` and `raw` go away |
| Definition of the lobby | Room membership, not the session list. The host stays after creating the room even with no sessions |
| `leave` during a pending request | Abort the attempt and discard the late response. Until that response, `host` / `join` are not accepted |
| STUN when joining again from the lobby | Run it again. Whether to skip it stays open until measured |
| The seat of a participant who left without candidates (raised by review round 1) | The server reclaims it. Only peers whose candidates are empty and whose grace has passed. ADR 0012 |
| `room_full` right after someone leaves a full room (raised by the owner) | The host sends `host_report` as soon as a session ends. ADR 0012 decision 6 |

**The scope of seat reclamation was settled in two exchanges with the owner.** The owner first asked
about "making the server the manager of the room". The agent recommended a narrow scope, pointing
out that the server cannot see tunnel liveness, and the owner chose that. Moving all reclamation to
the server would make connected peers keep signalling the server, and a control plane outage would
reclaim the seats of live peers.

**Growing the virtual IP pool to `10.100.0.10` was proposed by the owner and dropped after review.**
The pool size is the room capacity, so growing it either breaks the 5-person limit or, if capacity
is counted separately, produces the same `room_full`. The reason is ADR 0012 alternative 5.

**The lobby definition is a hole found while reading the documents before asking.** `concurrency.md`
chapter 7 and ADR 0008 decision 1 wrote the lobby as "the state where the session list is empty".
The host has no sessions right after creating the room and after the last player leaves, so by that
definition it abandons the room. Because this narrows a decision, ADR 0011 was newly written and
ADR 0008 was not changed.

**Console input from Phase 6 on also disagreed between documents.** `concurrency.md` chapter 1
wrote `[console]` as Phase 1~5 scaffolding, while ADR 0008 decision 8 said the console build from
Phase 6 on also goes to the lobby. At that point there is no thread to take commands.

**Code behaviour was not changed.** Rejecting role-less `--room` was hung on Phase 3 work. The
current code and `cli-check.ps1` accept it.

**One defect that predates this diff was fixed along with it.** The lease renewal of `host_report`
updated every item of the first `Query` unconditionally, so it revived `PEER#` and `VIP#` items
reclaimed by the same request as items holding only `ttl`. It also hit the host's `departed`
reclamation. It was changed to a conditional update per item and taken out of the transaction (ADR
0012 decision 7).

**The English mirror was not made.** Per `CLAUDE.md`, it is made when a push is instructed. The gate
is blocked only by `mirror` and `parity`, and `link` is 0.

## Scenario Tracing

Per rule 1, these were followed end to end.

| Scenario | Result |
|----------|--------|
| Host CLI startup, player connects, player `leave`, rejoin, host `leave` then `host` | Without the host stay rule, the room disappeared the moment the player left. The starting point of ADR 0011 |
| `host` while an attempt is in progress | Nothing said whether "in the lobby" starts at the moment a command is taken. It is now fixed that taking a lobby command leaves the lobby |
| Player hole punching fails | `roadmap.md` Phase 4 verification still said "the process exits normally". Fixed |
