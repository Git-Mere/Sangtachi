# Issue History

겪은 이슈와 그 처리를 `NNNN-제목.md` 형식으로 남깁니다. 번호는 기록한 순서입니다. 날짜별 폴더를 두지 않습니다.

각 문서 구성: 증상 / 조사 / 원인 / 처리 / 결과.

- **언제 쓰는가.** 원인을 찾는 데 조사가 필요했던 결함이나 환경 문제다. 바로 고친 오타나 단순 실수는 쓰지 않습니다
- **이슈 하나에 문서 하나.** 여러 커밋에 걸친 이슈도 한 문서로 씁니다. 각 커밋의 기록은 [`commit_history/`](../commit_history/README.md) 가
  갖고, 이 문서는 그 커밋을 가리킵니다
- **조사에는 버린 가설도 적습니다.** 무엇을 의심했고 무엇으로 아니라고 봤는지입니다. 결정 기록의 "대안" 에 해당합니다
- **원인은 확인한 것과 추정한 것을 나눠 적습니다.** 재현이나 전후 비교로 보인 것만 확인이라고 씁니다
- **상태** 는 셋 중 하나입니다
  - 해결: 원인을 고쳤다
  - 우회: 원인은 그대로 두고 증상을 피했다. 코드 밖의 환경 문제가 보통 여기입니다
  - 미해결: 원인을 모르거나 아직 고치지 않았다
- **닫힌 이슈는 고치지 않습니다.** 같은 증상이 다시 나오면 새 번호로 쓰고 앞 번호를 가리킵니다. 미해결이나 우회인 문서는 상태와 결과를
  갱신할 수 있습니다
- 남은 일은 [`plan.md`](../plan.md) 가 갖습니다. 이 문서에는 남은 일을 옮겨 적지 않고, `plan.md` 가 이슈 번호를 가리킵니다
