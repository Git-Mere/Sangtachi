# 0011. 로비는 세션 목록이 아니라 방 소속으로 정한다

- 상태: 채택
- 날짜: 2026-10-06
- 관련: [ADR 0008](0008-스타-토폴로지-후속-결정.md) 결정 1·8, [`../concurrency.md`](../concurrency.md) 1장·7장·8장, [`../architecture.md`](../architecture.md) 3.5, [`../control_plane.md`](../control_plane.md) 8.4, [`../roadmap.md`](../roadmap.md) Phase 3·4

## 맥락

ADR 0008 결정 1 은 로비를 세션 목록으로 적었다. "목록이 비면 로비로 간다. 플레이어는 목록이
1개인 경우다." `concurrency.md` 7장 로비도 같은 정의를 받아 "세션 목록이 빈 상태" 로 적었다.

**플레이어에게는 맞고 호스트에게는 맞지 않는다.** 호스트의 세션 목록이 비는 순간이 둘 있다.

| 순간 | 그 정의대로면 |
|------|---------------|
| 방을 막 세웠고 아직 아무도 붙지 않았다 | 호스트는 이미 로비에 있다 |
| 마지막 플레이어가 나갔다 | 호스트가 로비로 가고 `host_report` 가 멈춰 방이 사라진다 |

둘 다 ADR 0008 의 다른 결정과 어긋난다. 늦은 참가(결정 2)와 자리 회수(결정 5)는 플레이어가
드나드는 동안 방이 살아 있다는 것을 전제한다.

이 구멍은 Phase 3 착수 전 항목인 "로비가 받는 입력" 을 정하다가 드러났다. 로비 명령 `host` 와
`join` 을 "방에 있으면 받지 않는다" 로 적으려면 "방에 있다" 가 세션 수와 따로 정의돼 있어야
한다.

## 결정

저장소 소유자가 아래를 정했다.

**1. 로비는 프로세스가 방에 속하지 않은 상태다.** 세션 목록으로 정하지 않는다.

**2. 호스트는 방을 세운 뒤에는 세션 목록이 비어도 방에 남는다.** 방을 떠나는 것은 `leave` 와
`quit` 뿐이다. 방을 세운 시점은 `register_candidate` 가 성공한 때다. 그 전의 실패는 플레이어와
같이 로비로 간다.

**3. 플레이어는 지금과 같다.** 호스트와의 세션이 끝나거나 시도가 실패하면 로비로 간다.

**4. 로비에서는 콘솔 명령 `host` 와 `join <방 코드>` 로 다시 방에 들어간다.** CLI 의 역할
인자는 기동 직후에 그 명령을 한 번 친 것과 같다. 역할 인자는 필수가 아니게 된다.

**5. 시도가 실패하면 `FAIL` 줄을 내고 프로세스는 끝나지 않는다.** 종료 코드는 시도의 결과를
담지 않는다.

**6. `[console]` 스레드는 콘솔 빌드에서 Phase 6 이후에도 남는다.** 결정 4 의 명령을 받을 자리가
그것뿐이다. Phase 6 에서 사라지는 것은 시험용 `--peer` 와 `raw` 다.

**7. `leave` 가 미결 제어 요청을 가진 시도를 중단하면 그 응답은 버린다.** 그 응답이 오기 전에는
다음 시도의 `host` 와 `join` 을 받지 않는다.

**8. 로비에서 다시 참가하면 STUN 을 다시 돌린다.** 건너뛸지는 실측 전까지 정하지 않는다.

ADR 0008 은 고치지 않는다. 결정 1 의 "목록이 비면 로비로 간다" 는 이 ADR 이 좁힌다.

## 이 ADR 이 정하지 않는 것

시점은 [`../roadmap.md`](../roadmap.md) 가 갖는다.

| 항목 | 시점 |
|------|------|
| 방을 세운 뒤 `host_report` 가 확정 오류를 받았을 때 호스트가 방에 남는가 | Phase 3 착수 전 |
| 호스트 쪽 쌍 실패의 `FAIL` 줄이 어느 플레이어의 것인지 담는가 | Phase 4 착수 전 |
| `leave` 가 중단한 시도를 로컬 기록 파일에 어떻게 적는가 | Phase 4 착수 전. 줄 형식과 같이 |
| GUI 빌드의 스레드 구성 | Phase 8 착수 전. ADR 0007 의 미결 |

## 대안

**대안 1. 세션 목록 정의를 두고 호스트만 예외로 적는다.**
버렸다. 결과는 같지만 "로비 = 목록이 빔" 이라는 정의가 호스트에게 거짓인 채로 남는다. 그
정의에 기대 문장을 쓰는 사람이 예외를 놓친다.

**대안 2. 호스트도 마지막 플레이어가 나가면 로비로 간다.**
버렸다. 늦은 참가와 자리 회수가 쓸모없어진다. 플레이어 한 명이 잠깐 나갔다 들어오려 해도
방 코드를 다시 받아야 한다.

**대안 3. 시도가 실패하면 프로세스를 끝낸다.**
버렸다. 장점은 스크립트가 종료 코드로 판정할 수 있다는 것이었다. 대가는 ADR 0008 결정 8 을
되돌리는 것이고, 실패와 `leave` 가 서로 다른 수명 규칙을 갖게 된다.

**대안 4. 응답에 시도 번호를 붙여 중단된 시도의 응답을 가른다.**
버렸다. `[control]` 이 갖는 상태가 늘고 큐 항목 형식이 바뀐다. 미결 요청이 한 번에 하나라는
기존 규칙만으로 같은 결과를 얻는다. 대가는 `leave` 직후 다음 `host` / `join` 이 최대 요청 한 건의
상한만큼 거부되는 것이다.

## 결과

**얻는 것.**

- 로비 정의가 호스트와 플레이어 모두에게 참이다
- CLI 와 콘솔이 같은 경로로 방에 들어간다. 실패 뒤의 규칙이 한 벌이다
- 콘솔 빌드가 Phase 6 이후에도 로비에서 쓸 수 있다

**치르는 것.**

- `[console]` 이 스캐폴딩이 아니게 되어 콘솔 빌드에 계속 남는다
- 역할 없는 `--room` 이 Phase 3 부터 기동 실패가 된다. 지금 코드는 받는다
- 위 "정하지 않는 것" 의 셋이 Phase 3 과 4 의 착수 전 항목으로 늘었다
- 로비 재참가가 후보 없이 떠난 참가자의 자리를 쌓는 구멍을 드러냈다. 그 회수는
  [ADR 0012](0012-후보-없는-참가자는-서버가-회수한다.md) 가 정했다
