# 0013. 서버에서 방이 끝난 호스트는 남은 세션이 끝나면 로비로 간다

- 상태: 채택
- 날짜: 2026-10-06
- 관련: [ADR 0011](0011-로비는-방-소속으로-정한다.md) 결정 2, [ADR 0009](0009-방-호스트-임대.md), [`../control_plane.md`](../control_plane.md) 4.1·4.6·5.1·6.4·8.3, [`../protocol.md`](../protocol.md) 11장, [`../concurrency.md`](../concurrency.md) 7장, [`../roadmap.md`](../roadmap.md) Phase 3·4

## 맥락

ADR 0011 결정 2 는 방을 세운 호스트가 `leave` 와 `quit` 로만 방을 떠난다고 정했다. 그리고
"방을 세운 뒤 `host_report` 가 확정 오류를 받았을 때 호스트가 방에 남는가" 를 Phase 3 착수 전
항목으로 남겼다.

두 규칙이 그 자리에서 어긋났다. `control_plane.md` 8.3 은 확정 오류를 곧바로
`CONTROL_PLANE_EXCHANGE_FAILED` 로 끝낸다. 5.1 은 임대가 끊겨도 이미 수립된 터널은 그대로 간다고
정한다. 앞의 것을 따르면 터널이 있는 방이 실패로 끝나고, 뒤의 것만 따르면 서버에서는 죽었는데
호스트는 남아 있는 방이 생긴다. 아무도 들어올 수 없는 방이다.

## 결정

저장소 소유자가 아래를 정했다.

**1. 방이 서버에서 끝났다는 응답이면 멈추고 기다린다.** `room_expired`, `room_not_found`,
`unauthorized`, `bad_request` 다. 호스트는 `FAIL CONTROL_PLANE_EXCHANGE_FAILED` 줄을 한 번 내고
`host_report` 를 멈춘다. 이미 있는 세션은 그대로 둔다.

**2. 남은 세션이 모두 끝나면 로비로 간다.** 세션이 없으면 바로 간다. ADR 0011 결정 2 의 "방을
떠나는 것은 `leave` 와 `quit` 뿐" 에 이 계기를 더한다.

**3. `rate_limited` 는 다음 주기에 다시 부른다.** `FAIL` 을 내지 않는다. 같은 공인 IP 의 다른
출발지가 예산을 태운 경우 방은 살아 있다. 이어지는 동안 임대가 만료되면, 예산이 차서 처리되는
첫 요청이 `room_expired` 나 `room_not_found` 를 받아 결정 1 로 간다.

**4. 일시 오류는 지금처럼 다음 주기가 재시도다.**

ADR 0011 은 고치지 않는다. 결정 2 를 이 ADR 이 넓힌다.

## 대안

**대안 1. 확정 오류면 호스트가 바로 로비로 가면서 세션을 닫는다.**
버렸다. 제어 평면의 상태 때문에 터널이 끊긴다. `spec.md` NFR-3 에 어긋난다.

**대안 2. 확정 오류에도 `host_report` 를 계속 부른다.**
버렸다. 만료된 방은 되살릴 수 없다(`control_plane.md` 5.1). 앞의 세 오류는 출발지의 속도 제한
예산을 깎으므로(6.4) 같은 공인 IP 의 다른 사용자를 막는다.

**대안 3. `rate_limited` 도 결정 1 로 다룬다.**
버렸다. 8.3 의 일반 규칙과 같아지는 장점이 있다. 대가는 남의 틀린 방 코드 때문에 살아 있는 방이
임대 만료로 죽는 것이다. 캠퍼스망처럼 공인 IP 를 나눠 쓰는 곳에서 일어난다.

## 결과

**얻는 것.**

- 서버에서 끝난 방에 호스트가 무한히 남지 않는다
- 이미 연결된 플레이어는 방이 끝나도 계속 논다

**치르는 것.**

- `host_report` 가 8.3 의 일반 오류 규칙에서 빠진 예외가 된다
- 로비로 가는 계기가 하나 늘어 다섯이 된다
