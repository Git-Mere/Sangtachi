# 2026-09-21 영어 미러 맞추기와 plan.md 한국어 전용화

한국어가 앞서 있던 커밋 4건의 영어 미러를 만들었다. `plan.md` 는 한국어만 두기로 하고
`docgate.py` 에 그 예외를 넣었다. **문서 게이트가 다시 통과한다.**

## 변경

| 무엇 | 내용 |
|------|------|
| `docs/eng` 전체 | `spec.md`, `roadmap.md`, `protocol.md`, `architecture.md`, `windows-prereq.md` 갱신. `design-audit.md` 를 `audit-history/` 로 이동. 커밋 기록 4건 신규 |

| 낡은 참조 | `plan.md` 의 옛 절 번호를 가리키던 12곳을 살아 있는 곳으로 다시 걸었다 |

## 결정

**1. `plan.md` 는 한국어만 둔다.**

다음 세션 인수인계 문서라 번역해 둘 이유가 없다. 번역이 늦으면 낡은 상태를 두 곳에 두게 되고,
그것이 미러 규약이 막으려던 바로 그 문제다.

**2. 예외는 "없어도 된다" 이지 "있어도 된다" 가 아니다.**

`KOR_ONLY` 는 미러 짝이 **없는 것만** 봐준다. `docs/eng` 에 같은 문서가 **생기면 막는다.**
느슨하게 두면 나중에 누가 번역본을 만들어 두고 한쪽만 갱신한다. 판정을 바꾸기 전에 케이스
표를 먼저 썼다 (규칙 7).

| 케이스 | 기대 |
|--------|------|
| `KOR_ONLY` 에 있고 영어 짝이 없다 | 통과 |
| 목록에 없는 문서에 영어 짝이 없다 | 실패 |
| `KOR_ONLY` 문서가 영어 쪽에도 있다 | 실패 |
| `docs/kor/sub/plan.md` 처럼 깊이가 다르다 | 실패. 이름이 아니라 전체 경로로 본다 |

**3. 낡은 참조는 살아 있는 곳으로, 기록은 그대로.**

`plan.md` 를 번호 없는 문서로 다시 쓰면서 "`plan.md` 5장" 을 가리키던 참조가 12곳 죽었다.
ADR 0001 본문(kor/eng), `tools/nat-probe/README.md` 5곳, `RECORD-TEMPLATE.md` 6곳이다. 전부
설계 감사 후속 5번이나 ADR 0001 로 다시 걸었다. **`tools/nat-probe/records/` 의 실측 기록과
`commit_history/` 는 얼린 기록이라 두었다.**

## 이번에 배운 것

**번역 렌즈로는 아무것도 안 나왔는데 판정 가능성 렌즈에서 blocker 가 나왔다.** 번역은 정확했다.
틀린 것은 원문이었고 영어로 정확히 복사됐을 뿐이다. 미러 작업의 리뷰는 번역만 보면 안 된다.

**구조를 바꾸면 그것을 가리키는 모든 곳을 `grep` 으로 찾아야 한다.** `plan.md` 를 다시 쓰면서
죽인 참조가 12곳인데 리뷰어가 본 것은 diff 안의 1곳뿐이었다. 리뷰어는 diff 밖을 보지 않는다.
