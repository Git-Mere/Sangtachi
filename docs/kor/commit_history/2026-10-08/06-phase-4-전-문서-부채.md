# Phase 4 세션 구현 전의 문서 부채 여섯 (ADR 0020)

## 왜 했나

`plan.md` 문서 부채 가운데 결정을 기다리던 여섯이다. 선택지와 장단점을 정리해 보였고 저장소 소유자가 추천안을
모두 골랐다.

## 무엇을 바꿨나

| 결정 | 바꾼 자리 |
|------|-----------|
| 1. `IDLE` 에는 세션 객체가 없다 | `protocol.md` 9.1 표와 문단, 9.4.1 `IDLE` 행. `roadmap.md` Phase 4 검증 한 줄 |
| 2. 종료 상태 세션 2분 보존, 상한 `MAX_PEERS - 1`, 방을 떠나면 지움 | `protocol.md` 5.6, 8.5 의 세션 수 문장, 11장 만료 표. `concurrency.md` 4장, 7장 종료와 로비 표. `roadmap.md` Phase 4 검증 |
| 3. 로컬 후보와 자기 서브넷 집합은 `[loop]` | `concurrency.md` 5장 상태 소유, 8장 응답 해석 |
| 4. 후보 위생에 `0.0.0.0/8`, `240.0.0.0/4` | `protocol.md` 10.1 위생 표와 문단. `control_plane.md` 4.4 거부 정책과 대역 문단. `roadmap.md` Phase 4 구현 |
| 5. 이름 안 공백의 헤더 줄 거부 | `control_plane.md` 3.3 헤더 줄 문법, 3.5 클라이언트 검사 3번. `roadmap.md` Phase 4 구현 |
| 6. Phase 8 제목 | `roadmap.md` 제목 줄 |

그 밖에 `decisions/0020`(새 ADR), `plan.md`(다음에 할 일, 구현 때 같이 볼 자리, 문서 부채 열하나에서 다섯).

## 중요한 결정

- **3 은 문서 쪽에서 생각한 것보다 작았다.** 로비 상태 기계와 응답 해석이 이미 `[loop]` 에서 돈다
  (`control/runner.hpp`). 인터페이스 읽기를 `GetAdaptersAddresses` 로 20번 재 보니 중앙값 2.1ms, 최대 4.8ms 였다
- **2 의 상한은 결정에 더한 것이다.** 2분만 두면 들고 나는 일이 잦을 때 세션 수가 `concurrency.md` 4장의 "한
  자릿수" 를 넘을 수 있다
- **4 와 5 는 코드보다 문서가 앞선다.** 서버 재배포를 Phase 4 표시 이름 배포에 묶었다. 배포된 서버는 그때까지
  지금대로 돈다
- **4 에서 7장 출발지 위생은 바꾸지 않았다.** 두 대역은 목적지로 무의미하다는 것이 근거이고, 출발지로 온 패킷에
  답해도 증폭이 없다

## 검증

| 무엇 | 결과 |
|------|------|
| 인터페이스 읽기 시간 | ctypes 로 `GetAdaptersAddresses(AF_INET)` 20번. 중앙값 2.06ms, 최대 4.83ms |
| RFC 확인 | RFC 9110 5.1 `field-name = token` 을 원문으로 확인 |
| 문서 게이트 | `docgate.py` `VERDICT: pass` |

## 크로스 모델 리뷰

Codex. staged diff 에 렌즈 둘(문서 간 일관성, 영어 미러와 기록)을 따로 돌렸다. 미러와 기록 렌즈는 `LGTM - no blockers`
였다.

| 지적 | 처리 |
|------|------|
| warn. `protocol.md` 8.5 가 가상 IP 회수 뒤 옛 피어의 패킷을 곧바로 `drop_unknown_peer` 로 적는데 옛 세션이 남아 있으면 검사 7번을 지난다 | 반영. 남아 있으면 `drop_terminal_state`, 지워졌으면 `drop_unknown_peer` |
| warn. `ROSTER` 의 멤버가 세션과 따로 정의되어 있지 않다. `IDLE` 멤버는 세션이 없고 떠난 멤버는 세션이 남는다 | 반영. 멤버는 호스트 자신과 마지막 `host_report` 응답의 `peers` 다. 세션 목록에서 만들지 않는다. 비트 0 은 `CONNECTED` 세션일 때만 1 |
| warn. 4.3 의 "새 시도를 시작할 때 이전 시도의 고정 epoch 를 등록" 은 그 값이 세션 삭제 뒤에도 남는다고 전제한다 | 반영. 남아 있는 종료 상태 세션에서 읽고, 지워졌으면 등록할 값이 없다. 같은 상대와 새 시도하는 경로는 지금 정의되어 있지 않다고 적었다 |
| warn. 방이 서버에서 끝났을 때의 `host_report` 규칙이 "세션이 있으면" 을 묻는데, 남긴 종료 상태 세션이 그 말에 걸린다 | 반영. "종료 상태가 아닌 세션" 으로. `protocol.md` 11장, `control_plane.md` 4.6, `concurrency.md` 7장 로비 표 |

2차 리뷰에서 warn 하나가 나왔다. 새 비트 0 규칙이 호스트 자신의 항목(늘 1)과 어긋났다. 반영했다. 세션 기준 규칙은 플레이어
항목에만 걸고 호스트 항목은 늘 1 이다.

3차 리뷰(그 수정 확인)는 `LGTM - no blockers` 였다.
