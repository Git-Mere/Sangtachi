# Display Name Design (FR-16, ADR 0015)

## Why

This is one of the Phase 4 before-start decisions, the first item of the next work in `plan.md`. It
had to be decided whether the `FAIL` line of a pair failure on the host side carries which player it
belongs to (`concurrency.md` chapter 7 Lobby left it undecided).

The candidates were `peer_id` and `virtual_ip`. The repository owner judged that both are hard for a
person to recognize, and proposed choosing a name when entering a room and showing that name. Four
things were decided together.

| Question | Decision |
|------|------|
| Characters and length | ASCII letters, digits, underscores. 1~16 characters |
| Duplicate names | The server rejects them with `name_taken`. Compared ignoring case |
| Is it required | Required. No default value |
| Does the host have a name too | Yes |

The design was decided in documents only. The code is the display name work of `roadmap.md` Phase 4.

## Important Decisions

- **The name is for display only.** Receive validation, routing, and record matching use `peer_id`.
  The v1 `ROSTER` is not authenticated, so the names on the screen can be forged
- **The counterpart field of the `FAIL` line is always present.** For the three session codes it is
  the counterpart's name, and for the rest it is `-`. `-` is not in the name character set
- **Uniqueness is the conditional write of the `NAME#` item.** In the cancellation reason order it
  comes before `VIP#`. So a join whose name collided does not walk the pool
- **Reclaim finds `NAME#` by `peer_id`.** If the key were built from the `name` of `PEER#`, then when
  that value cannot be read the `NAME#` would remain and block the name until the room ends. The
  review found this
- **A name is released together with its slot.** A player whose process died comes back in with the
  same name only after the host's idle timeout. Until then it uses a different name
- **The item cap per room grew from 15 to 20.** The worst case of 7.6 was recomputed. It is written
  that the measured values are from before
- **`--name` is required from Phase 4.** Writing "from Phase 3" would make the finished Phase 3
  binary violate the startup input contract after the fact
