# 친구 가정의 매핑 수명 측정

## 왜 했나

`protocol.md` 11장 타이머의 `KEEPALIVE` 규칙(`간격 × 3 < 잰 수명의 최솟값`)은 잰 망들의 최솟값을 쓴다. 첫
측정은 이 기기의 집 Wi-Fi 하나였다(`[58, 60)` 초). 저장소 소유자의 친구 집에서 같은 도구로 쟀다.

## 측정

조건. 친구 기기, 친구 집 Wi-Fi. 공인 IP 는 이 기기와 다르다(보안 그룹 규칙을 그 `/32` 로 열었다). 공유기 모델,
방화벽 창의 허용 여부, VPN 은 기록받지 않았다. 응답기는 커밋 `d122719` 의 `natlife.py` 를 EC2 에 다시 올려 띄웠다.
결과 JSON 은 저장소 소유자가 `tools/nat-lifetime/results/` 에 넣었다(ignore 됨).

| 회차 | 지연(초) | 도착 | 판정 |
|------|------|------|------|
| check | 2 | 전부 | 확인 통과 |
| friend-r1, r2, r3 | 5, 20, 30, 40, 45, 50, 55, 60, 70, 80, 90, 100, 110, 120, 135, 150, 165, 180, 210, 240, 270, 300 | 전부 | 세 번 모두 `300` 이상 |

- 본 측정 세 번의 모든 시행에서 데우기 ACK 6/6, 확인 시행에서 2/2 를 받았다. 마지막 ACK 는 모두 "예약함" 이다.
  거절과 창 밖 도착은 0 이다
- 응답기 로그의 `scheduled` 와 `late_sent` 가 둘 다 67(확인 1 + 66)이다
- **친구 집 경로는 300초 이상이다.** 상한은 보지 못했다. 응답기 상한(600초)보다 짧은 목록으로 쟀다

## 판정

잰 망의 최솟값은 이 기기의 집 58초 그대로다. 15초는 45초라 규칙을 지킨다. `protocol.md` 11장의 15초와 50초는
그대로다. 두 집의 값이 크게 다르므로 시연 상대가 다른 망이면 그 망도 잰다.

## 정리

- 측정 뒤 응답기를 끝냈고 UDP 47000 이 닫혔다
- 보안 그룹의 친구 `/32` 규칙과 이 기기 `/32` 규칙은 저장소 소유자가 지운다
