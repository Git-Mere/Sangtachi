# Qt 런타임 통과 조건을 모듈 목록 판정으로 닫는다

## 왜 했나

`windows-prereq.md` 4절 Qt 런타임의 통과 조건은 "Qt 와 VC++ 런타임을 따로 설치하지 않은 대상 PC 에서 배포물만으로 GUI 가 뜬다" 였다.
친구 PC 에서 배포물이 떴지만 그 PC 에 런타임이 없었는지는 확인하지 않았다. 개발 기기에는 둘 다 설치돼 있다.

깨끗한 Windows 를 구할 길을 따졌다.

| 대안 | 판단 |
|------|------|
| Windows Sandbox | 쓸 수 없다. 개발 기기가 Windows Home(`EditionID = Core`)이고 `WindowsSandbox.exe` 가 없다. Hyper-V 도 없다 |
| EC2 Windows 인스턴스 | 가능하다. 다만 Windows Server 이고, AMI 에 VC++ 재배포 패키지가 있는지 띄워서 확인해야 하고, 비용과 정리가 든다 |
| 개발 기기에서 `System32` 의 VC++ DLL 을 잠시 지우기 | 기각. 다른 프로그램이 쓰는 파일이고, 쓰는 중이면 지워지지 않는다. Visual Studio, Qt 같은 곳의 복사본이 `PATH` 로 채울 수 있어 지워도 깨끗한 환경이 되지 않는다 |
| 배포물로 띄운 프로세스의 모듈 목록 보기 | 채택. 막으려는 위험은 배포물에 빠진 DLL 을 설치된 런타임이 몰래 채우는 것이다. 각 모듈을 어느 경로에서 불러왔는지 보면 그것이 직접 보인다. 실행 중에 불러오는 플러그인도 잡히고 시스템은 건드리지 않는다 |

저장소 소유자가 통과 조건을 모듈 목록 판정으로 바꾸는 것을 승인했다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 통과 조건을 모듈 목록 판정으로 바꿨다. 배포물 밖에서 온 모듈은 모두 서명이 유효하고 서명자가 `CN=Microsoft Windows` 여야 한다. 판정 명령, 관리자 셸이 필요한 이유, 판정하지 않는 경우, 결과, 근거를 적었다 | `windows-prereq.md` 4절 Qt 런타임 |
| Qt 소절과 4절을 "부분 실측" 에서 "실측" 으로 고쳤다. 0절의 절 수를 실측 8절, 부분 실측 3절로 고쳤다 | `windows-prereq.md` 0절, 4절 |
| "런타임이 없는 PC 에서의 확인이 남았다" 두 곳을 지웠다 | `windows-prereq.md` 0절, 14절 |
| 남은 일에서 Qt 런타임 항목을 지우고 번호를 당겼다 | `plan.md` |

- 경로나 이름이 아니라 서명자로 가른다. VC++ 재배포 패키지는 `System32` 에 깔리고(개발 기기에도 `C:\Windows\System32\vcruntime140.dll`, `msvcp140.dll` 이 있다), 걸러야 할 VC++·Qt 파일 이름을 빠짐없이 적을 수 없다. 처음 안은 "`C:\Windows` 아래 + 이름 목록" 이었고 리뷰 지적으로 바꿨다(아래)
- 다른 프로그램이 넣는 DLL 처럼 Windows 구성요소가 아닌 모듈이 나오면 실패한다. 잘못 통과하는 쪽이 아니라 잘못 실패하는 쪽이므로 그대로 두었다
- Qt 와 VC++ 런타임이 없는 PC 에서 띄우지 않았다는 사실은 검증 줄에 남겼다

## 검증

| 무엇 | 결과 |
|------|------|
| 판정에 쓴 배포물 | `C:\me\build\test\gui-dist`. `logs`, `records` 를 빼면 16개 파일, 30,155,983바이트로 4절 표와 같다 |
| 모듈 목록 | 소유자가 배포물의 `sangtachi_gui.exe` 를 띄우고 관리자 PowerShell 에서 판정 명령을 돌렸다. 100개 |
| 배포물 폴더에서 온 모듈 | 12개. `sangtachi_gui.exe`, `wintun.dll`, Qt 5개, VC++ 5개로 4절 표의 실행 파일과 DLL 과 같다 |
| 배포물 밖 모듈 | 나머지 88개. 모두 `C:\Windows` 아래다. 그 경로들에 `Get-AuthenticodeSignature`(PowerShell 7)를 돌렸다. 88개 모두 `Valid` 이고 서명자가 `CN=Microsoft Windows` 다. 스크립트로 셌다 |
| 반례 | 같은 판정을 이 기기의 `System32\vcruntime140.dll`, `System32\msvcp140.dll` 에 돌리면 `CN=Microsoft Windows Software Compatibility Publisher`, `Qt6Core.dll` 은 `CN=The QT Company Oy` 다. 셋 다 실패로 갈린다 |
| `docgate.py`, `--claims` | `VERDICT: pass` |

## 크로스 모델 리뷰

Codex(`gpt-6.1-sol`). 판정 건전성(A)과 한영·기록 일관성(B) 렌즈를 한 번에 돌렸다.

| 지적 | 처리 |
|------|------|
| warn [A] `C:\Windows` 에는 OS 구성요소만 있지 않고, 이름 목록은 `vcamp140.dll` 같은 VC++ 라이브러리와 `qwindows.dll` 같은 Qt 플러그인을 빠뜨린다. 거기 깔린 의존성이 두 조건을 다 통과할 수 있다 | 반영. 이름 목록을 버리고 서명자 허용 목록(`Valid` 이고 `CN=Microsoft Windows`)으로 바꿨다. 88개와 반례 셋에 돌려 확인했다 |

고친 뒤 같은 렌즈로 전체 staged 차이를 다시 돌렸다. `LGTM - no blockers` 였다. 이 줄을 채운 뒤의 최종 차이도 한 번 더 확인했다.
