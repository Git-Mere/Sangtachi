# 0025. Phase 5 착수 전 결정

- 상태: 채택
- 날짜: 2026-10-15
- 관련: [`../roadmap.md`](../roadmap.md) Phase 4·5, [`../protocol.md`](../protocol.md) 4.5·9.6·10.4·15장, [`../architecture.md`](../architecture.md) 9장

## 맥락

Phase 5 를 시작하기 전에 문서를 훑어 걸리는 자리 여섯을 찾았다. 저장소 소유자가 자리마다 선택지 가운데 하나를 골랐다.

- `protocol.md` 4.5 의 `pkt_pos = position - back` 이 첫 수용 패킷보다 앞선 번호에서 64비트로 감싸 돈다
- 손실 값을 내는 자리가 없다. 4.5 는 텔레메트리 서비스에 올린다고 하지만 그 서비스는 Phase 9 다
- `TUNNEL_DROPPED` 뒤 자동 재시도 여부가 미정이다 (9.6, 10.4)
- 퍼즈 시험의 "메모리 오류 없음" 을 판정할 수단이 빌드에 없다
- Phase 4 를 닫는 기준이 체크박스로 적혀 있는데 아무도 체크하지 않았다. 사양 문서에 진행 상태를 적는 것은 `plan.md` 를
  현재 상태의 단일 출처로 둔 규칙과도 어긋난다
- 장시간 시험 둘을 어디서 돌리는지 정해져 있지 않다

## 결정

| 자리 | 고른 것 |
|------|---------|
| `pkt_pos` 언더플로 | `position` 을 0 이 아니라 `REPLAY_WINDOW` 에서 시작한다. `back` 이 그 이하이므로 뺄셈이 감싸 돌지 않는다 |
| 손실 값의 출력 | 로그 고정 이벤트 `session.loss`(`peer_id`, `expected`, `accepted`, `lost`). 세션 카운터 표와 같은 때에 낸다 |
| 재협상이 집계를 초기화할 때 | 그 구간의 값을 세션 합계에 더한 뒤 초기화한다. `session.loss` 는 세션 전체의 값이다 |
| 자동 재시도 | 하지 않는다. 새 시도는 플레이어가 다시 참가할 때 시작한다 |
| 메모리 오류 판정 | ASan 을 켠 시험 빌드(MSVC `/fsanitize=address`)에서 퍼즈 두 단계를 단위 시험으로 돌린다 |
| 장시간 시험의 자리 | 10분 제어 평면 중단과 1시간 유지는 `scripts/test.ps1` 밖의 별도 스크립트. 둘 다 같은 기기의 두 프로세스로 판정하고, 1시간 시험은 서로 다른 두 집에서 한 번 더 돌려 관측값으로 남긴다 |
| `protocol.md` 15장 | 이름을 구현 적합성 목록으로 바꾸고 체크박스와 Phase 문구를 지운다. 일정은 `roadmap.md` 가 15장을 가리켜 정하고, 코드와 대조한 결과는 `commit_history/` 에, 남은 항목은 `plan.md` 에 둔다 |
| Phase 4 캡처 C6~C9 | 제어 서버 하네스의 가짜 피어에 그 장면을 만드는 모드를 Phase 5 에서 더한다 |

## 대안

**언더플로.** 재정렬 분기에 "baseline 이전" 플래그를 두는 안을 버렸다. 판정 결과의 구조가 바뀌고 분기가 하나 는다. 집계 조건을
`back < position - baseline` 으로 바꾸는 안도 버렸다. 수학적으로 같지만 4.5 의 `pkt_pos` 설명과 수용 창 코드를 함께 걷어 내야
한다. 시작값을 옮기는 안은 상수 하나만 바뀐다.

**손실 출력.** 세션 카운터 표에 `rx_expected`, `rx_accepted` 를 넣는 안을 버렸다. 새 키가 필요 없지만 손실률을 읽으려면 계산이
한 단계 더 든다. 10초마다 한 줄을 더 내는 안은 1시간 세션에 줄이 360개 늘어 버렸다. 로컬 기록 파일에 넣는 안은 M-6 판정
입력의 형식(`v=1`)을 바꾸므로 버렸다. 10초 스냅샷은 Phase 9 업로드의 일이다.

**재협상 구간.** 마지막 `CONNECTED` 구간만 세는 안을 버렸다. 재협상 앞의 손실이 사라져 세션의 품질이 실제보다 좋게 보인다.

**자동 재시도.** 플레이어가 같은 방 코드로 자동 재참가하는 안을 버렸다. 재참가가 없으므로 새 `peer_id` 와 새 가상 IP 를 받고,
게임에게는 다른 피어라 그 위의 연결은 어차피 끊긴다. 같은 `peer_id` 로 옛 세션을 잇는 안도 버렸다. 제어 평면에 재참가 규칙을
새로 세워야 하고 P1 범위를 넘는다.

**메모리 오류.** 지금의 Debug 빌드와 CRT 디버그 힙으로 판정하는 안을 버렸다. 표준 라이브러리 단언은 컨테이너와 반복자를
거친 접근만 본다. 문구를 "크래시와 단언 없음" 으로 낮추는 안은 기준을 낮추는 것이라 버렸다.

**장시간 시험.** 실제 두 집 사이에서만 판정하는 안을 버렸다. 두 번째 기기와 사람이 필요하고 자동 판정이 어렵다. 같은 기기만
쓰는 안은 keepalive 와 NAT 매핑 수명이 맞물리는 것을 보지 못해 버렸다.

**15장.** 체크박스를 코드 대조 결과로 체크하는 안을 버렸다. 진행 상태가 사양 문서에 들어간다. 15장을 `roadmap.md` 로 옮기는
안도 버렸다. 목록은 프로토콜을 구현한 코드가 갖춰야 할 것이고 그 근거가 `protocol.md` 의 절이다.

**C6~C9.** 실측과 함께 Phase 4 에 남겨 두는 안을 버렸다. 두 번째 기기 없이 한 기기에서 만들 수 있는 장면인데 기다릴 이유가 없다.

## 결과

**얻는 것.**

- 손실이 음수로 감싸 도는 경우가 구조적으로 사라진다
- Phase 5 검증이 볼 손실 값과 출력 시점이 정해진다
- 9.6 과 10.4 의 미정 항목 하나가 닫힌다
- 15장이 일정 없는 사양으로 남아 Phase 를 바꿔도 고칠 필요가 없다

**치르는 것.**

- `position` 의 절대값이 64 만큼 밀린다. 그 값을 직접 보는 수용 창 시험의 기대값이 바뀌었다
- 로그 고정 이벤트가 열여덟이 된다
- 시험 빌드 구성이 하나 는다. ASan 빌드는 느리고 `/RTC` 와 함께 쓸 수 없다
- 시연 중 연결이 끊기면 사람이 다시 참가해야 한다
