## 중요한 결정

- **일반적인 "문서가 적은 개수" 검사는 만들지 않았다.** 문장 속 "5건" 같은 주장을 기계로 믿을 만하게 뽑기 어렵다. 셀 수 있는
  이름 집합인 카운터만 대조하고, 틀린 개수가 나오면 그 개수를 문장에서 빼서 셀 일을 없앤다. 14장이 그 첫 사례다.
  저장소 소유자가 docgate 설계를 맡겼다
- **코드 쪽 이름은 모양으로 거르지 않는다.** 문서 쪽만 `drop_` 같은 모양으로 카운터를 알아본다. 코드의 이름은 모양과 무관하게
  문서에 그대로 있어야 하므로, 모양 규칙 밖의 새 카운터도 걸린다
- **`run()` 의 `counters`, `pending` 인자는 시험용 이음새다.** 기존 문서 검사 시험이 카운터 픽스처 없이 돌게 한다. 명령줄은 늘
  기본값으로 부르고, 그것을 지키는 시험이 따로 있다
- **중복 주장 링크화 stash 를 버렸다.** 09-22 에 만든 것이고, 이름과 달리 새 요구사항(NFR-11, NFR-4 의 "피어 발견")이 섞여
  있었다. 저장소 소유자가 버리기로 했다. 그 stash 가 찾은 14장 불일치는 HEAD 에 그대로 있었으므로 따로 고쳤다
- **Phase 1 두 머신 실측은 따로 기다리지 않는다.** `roadmap.md` Phase 1 검증이 한 기기의 두 프로세스도 받고, 실제 두 기기
  사이의 송수신은 Phase 4 의 같은 LAN 시험이 본다. 저장소 소유자가 정했다
- 추적하지 않던 `tools/nat-probe/natprobe_EN.py` 를 지웠다. `host`, `players` 가 없는 낡은 사본이었다. 추적하지 않던 파일이라 이 diff 에는 없다

## 크로스 모델 리뷰

Codex. staged diff 에 렌즈 둘(카운터 검사의 정확성, 문서의 사실과 일관성)을 따로 돌렸다. 아래는 1차다.

| 지적 | 처리 |
|------|------|
| blocker. 주석이 낀 `case` 처럼 일부만 읽혀도 나머지가 읽히면 조용히 통과한다 | 반영. 주석을 걷어 낸 뒤 읽고, `case Counter::` 수와 읽은 이름 수가 다르면 실패로 적는다. 코드 쪽 이름의 글자 제한도 없앴다 |
| warn. 코드 스팬이 백틱 run 길이를 보지 않는다. ``` `` drop_typo `` ``` 는 놓치고 짝 없는 백틱은 센다 | 반영. CommonMark 대로 같은 길이의 run 으로 닫고 양끝 공백을 한 칸 걷는다 |
| warn. `drop_new_` 처럼 밑줄로 끝나는 이름이 빠진다 | 반영. README 의 "로 시작하는" 규칙에 맞췄다 |
| warn. `test_exit_one_on_failure` 가 카운터 픽스처 없이 돌아 parity 검사를 지워도 통과한다 | 반영. 카운터가 깨끗한 픽스처에서 parity 만 깨뜨리고, 실패가 parity 인 것을 같이 본다 |
| warn. CMake 기록이 "툴체인이 도는지 본 스모크" 라고 diff 에 없는 의도를 적었다 | 반영. 커밋 메시지만 남겼다 |
| warn. 일반 개수와 산술 검사가 구현되지 않았는데 부채 줄을 지웠다 | 기각. 위 결정대로 만들지 않기로 정했다. 부채가 아니라 범위에서 뺀 것이다 |

2차는 1차 수정을 확인했다.

| 지적 | 처리 |
|------|------|
| blocker. `case Counter ::New` 처럼 `::` 앞뒤에 공백이 있으면 셈과 읽기 둘 다 놓쳐 조용히 통과한다 | 반영. 공백과 이름공간 한정을 읽고, 셈은 파일의 `case` 전부로 넓혀 읽지 못한 것이 하나라도 있으면 실패로 적는다 |
| warn. 닫는 백틱을 더 긴 run 의 끝부분에서 잡는다. 1차 기록의 "같은 길이의 run 으로 닫는다" 가 사실이 아니었다 | 반영. 닫는 run 은 길이가 정확히 같은 온전한 run 이어야 한다. 이 함수는 HTML 주석 처리도 쓰며 기존 시험이 모두 통과한다 |
| warn. 짝 없는 백틱 시험이 결과 모양 덕에 우연히 통과했다 | 반영. `code_spans()` 결과를 직접 비교하고, 잘못 닫으면 없는 카운터가 생기는 경우를 따로 둔다 |

3차에서 warn 하나가 나왔다. HTML 주석 처리가 짝 없는 여는 백틱 run 을 한 글자씩 넘겨, 그 run 의 뒷부분이 스팬을 다시 열고
뒤따르는 주석 안의 카운터 이름을 본문으로 드러냈다(`` ``<!-- `x` --> ``). 반영했다. 짝 없는 run 은 통째로 글자로 넘긴다. 이 결함은
이번 변경 전부터 있었고, 카운터 검사가 그 결과를 읽으면서 드러났다.

4차 리뷰(그 수정 확인)는 `LGTM - no blockers` 였다.
