# Phase 1 로그와 카운터

**대상 커밋:** 이 커밋
**Phase:** 1 (핵심 UDP 네트워킹)

`architecture.md` 9장 로그 출력이 정한 계약을 코드로 옮겼다. 뒤의 Phase 검증 항목이 전부
이 줄을 읽으므로 형식이 먼저 서야 한다.

## 9장의 규칙이 스스로와 충돌했다

**앞 커밋이 넣은 따옴표가 9장을 어겼다.** 9장 "단위" 계약이 "이스케이프 표기를 쓰지
않는다" 로 적는데, 앞 커밋의 `main.cpp` 는 `arg="a b"` 처럼 값을 감싸고 `"` 와 `\` 를
이스케이프했다. 그때 `plan.md` 에 "그 규칙이 문서에 없다" 로 적었는데 **틀린 진단이었다.**
규칙은 있었고 내가 어긴 것이다.

**그런데 원래 규칙도 성립하지 않았다.** 9장은 "줄바꿈과 제어문자는 공백 하나로 바꿔
싣는다" 로 적었다. 줄 모양은 `<수준> <이벤트키> <이름>=<값> ...` 이므로 **값에 공백이 들어가면
`이름=값` 의 경계가 사라진다.** 제어문자를 공백으로 바꾸는 규칙 자체가 그 일을 만든다.
값이 공백을 가질 수 없던 시절의 규칙이고, 사용자가 준 문자열을 싣는 필드가 생기면서 깨졌다.

| 안 | 내용 | 채택 |
|----|------|:----:|
| A | 공백과 제어문자를 **밑줄 하나**로 바꾼다 | **예** |
| B | 값을 따옴표로 감싸고 따옴표를 이스케이프한다 | 아니오 |
| C | 규칙대로 공백으로 바꾸고 경계 문제를 둔다 | 아니오 |

B 를 버린 이유는 9장이 이미 금지한 것이기 때문이다. 따옴표가 든 값을 실으려면 이스케이프가
필요하고, 그러면 읽는 쪽이 표기를 해석해야 한다. C 는 검증이 읽는 줄이 모호해진다.

A 의 대가는 **치환을 되돌릴 수 없다는 것**이다. 9장에 그 사실과 함께 "원문이 필요한 판정을
로그로 하지 않는다" 를 적었다. 판정의 입력은 로컬 기록 파일이다.

## 무엇을 넣었나

| 대상 | 내용 |
|------|------|
| `log.hpp` / `log.cpp` | `INFO`/`WARN`/`ERROR`, `sanitize_value`, `format_line`, `emit` |
| `counters.hpp` / `counters.cpp` | 카운터 39개, `Counters`, `format_all`, `emit_all` |
| `main.cpp` | 임시 `quote_for_log` 를 지우고 로그 모듈을 쓴다. 종료 전에 카운터 전량을 낸다 |

**`format_line` 을 순수 함수로 뒀다.** 시험이 표준 오류를 가로채거나 전역 상태를 건드리지
않고 줄 모양을 판정할 수 있다. `emit` 은 그 위에 줄바꿈을 붙여 한 번의 `fwrite` 로 낸다.
두 번에 나누면 다른 스레드의 줄이 사이에 낄 수 있다.

**카운터 이름 39개는 세 문서에서 모은 것이고 여기서 새로 짓지 않았다.** 아직 아무도 올리지
않는 이름도 들고 있다. 9장이 "값이 0 인 카운터도 함께 낸다" 로 정했고, 없는 것과 0 인 것을
구분해야 검증이 "오르지 않았다" 를 판정할 수 있기 때문이다.

**`[loop]` 단독 소유 규칙을 그대로 옮겼다** (`architecture.md` 3.2.5). 예외인
`console_queue_dropped` 는 `[console]` 이 올리는 원자 변수라 큐 쪽이 들고 있고, `[loop]` 가
낼 때 `set` 으로 이 표에 반영한다. 그래서 `Counters` 자체에는 원자 변수가 없다.

**넘침은 감싸 돌지 않고 멈춘다.** 감싸 돌면 "오르지 않았다" 를 보는 검증이 통과한다.

## 검증

| 무엇 | 건수 |
|------|:---:|
| Catch2 케이스 | 25 -> **40** |
| CLI 케이스 | 18 -> **19** (카운터 전량 출력 1건) |
| `build.ps1 -SelfTest` | 7 |

변이 13건을 돌렸고 **전부 죽었다.**

| 대상 | 변이 | 죽음 |
|------|:---:|:---:|
| `log.cpp` | 8 | 8 |
| `counters.cpp` | 5 | 5 |

로그 쪽 8건은 위생 처리의 경계(공백만, 제어문자만, `DEL` 만, 상위 바이트까지)를 하나씩
어긋내는 것과 줄 모양(구분 공백, `=`, 수준 토큰)을 깨는 것이다. 카운터 쪽 5건은 포화,
증가량 무시, `set` 무력화, 0 인 카운터 누락, 이름 중복이다.

## 크로스 모델 리뷰

Codex 에 렌즈 둘(정확성, 계약)을 붙여 돌렸다. 지적 2건을 모두 반영했다.

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | `sanitize_value` 가 `0x80` 이상을 그대로 두므로 U+2028 같은 유니코드 줄 구분자가 값에 남는다. 유니코드를 아는 읽는 쪽에서는 "공백과 제어문자를 싣지 않는다" 가 깨진다 | **반영.** 디코딩까지 하지 않는다. 대신 **계약이 바이트 단위라는 것과 그 한계를 9장에 적고** 케이스로 못박았다. 판정은 `0x0A` 로 나눈다 |
| warn | 이 기록의 리뷰 절이 자리표시자로 남아 있다 | **반영.** 이 표가 그 자리다 |

**유니코드까지 디코딩하지 않은 이유.** 로그는 사람이 읽는 진단이고, 판정의 입력은 로컬 기록
파일이다(9장). 디코더를 넣으면 그 디코더가 시험 대상이 되고, 얻는 것은 이 프로젝트가 쓰지
않는 도구에서의 표시뿐이다. 대신 무엇을 보장하고 무엇을 보장하지 않는지를 적었다.

## 남은 것

Phase 1 은 UDP 소켓 래퍼와 `[loop]` 이벤트 루프가 남았다. 카운터 이름의 문서-코드 대조가
없다는 것을 `plan.md` 문서 부채에 적었다.
