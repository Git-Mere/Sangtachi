# Moved the control plane case tables into tests and added mutation tests

## Why

This is item 1 of "Next to do" in `plan.md` and the first item of the `roadmap.md` Phase 3 work. The case
tables in eight places of `control_plane.md`, nine tables (2.1, 3.3, 4.4, 4.5, two in 4.6, 5.1, 6.4, 7.4), were moved
to `control-server/tests/`, the pure parts the tables judge were implemented, and a mutation test was added
for each table. This comes before the server code (`store.py`, `ops.dispatch`, the accept loop).

| What | Decision | Record |

| How to start DynamoDB local | A Docker container | ADR 0014, `roadmap.md` Phase 3 |

The options the agent proposed were `unittest` and the jar. The reasons both were dropped are in ADR 0014.

## How the work was split

The director wrote the skeleton (`constants.py`, `errors.py`, `conftest.py`, the mutation runner
`tests/mutate.py`) first and split the tables among three workers. The workers are the same model and each
touched only its own files. Only the director edited documents.

| Worker | Tables | Files |
|--------|--------|-------|
| worker-http | 3.3 HTTP subset, 6.4 rate limit, the after-parse part of 7.2 | `server.py`, `test_http.py`, `test_rate_limit.py` |
| worker-ids | 2.1 `room_id`, 4.4 sanitation, 7.4 clock | `ids.py`, `candidates.py`, `clock.py` and their tests |
| worker-ops | 5.1 room, 4.5 element field sets, the two 4.6 tables | `ops.py` (pure part), its tests |

**The 8 rows that need the store to run were only moved and are skipped.** These are all 6 rows of the 4.6
confirm race table and 2 rows of the server reclamation table. The store was not faked. `pytest.mark.store`
and skip are attached together, and `conftest.py` stops at collection on a skip for any other reason.

## Mutation runner

`tests/mutate.py` copies `controlplane/` into a temporary folder, changes one place, passes it via `CP_SRC`,
and runs pytest in a new process. For each mutation, the rows that must fail are listed in `kills`, and it is
`KILLED` only when those rows are `FAILED` in the test body. The default of the four verdicts is cannot
determine (`ERROR`).

- `conftest.py` checks that the `controlplane` actually imported is under `CP_SRC`. If the original were
  read instead, every mutation would look like it survived
- Before mutating, the same tests are run on the original. If the original fails, no verdict is given
- If `old` does not appear exactly once in the original, that mutation is `ERROR`. This keeps a stale
  mutation from passing quietly after the code changes

**On the first run, some mutations survived.** The first result of worker-http was 61/64. One row had the
wrong test axis (the marker body was not JSON, so it did not go through the array path), and one row guarded
nothing and was removed together with its handling code. worker-ids found by mutation that the full-width
rows of 2.1 alone did not guard the ASCII check, and added the `ſ` row.
