# 0030. 기동 입력과 콘솔 화면

- 상태: 채택
- 날짜: 2026-10-22
- 관련: [`../architecture.md`](../architecture.md) 3.5·8장·9장, [`../windows-prereq.md`](../windows-prereq.md) 1절·4절·14절, [`../roadmap.md`](../roadmap.md) Phase 8, [`../control_plane.md`](../control_plane.md) 2.7, [ADR 0015](0015-멤버를-표시-이름으로-가리킨다.md)

## 맥락

`roadmap.md` Phase 8 은 착수 전에 GUI 가 쓰는 기동 입력 경로와 권한 승격 시점을 정하라고 한다. 저장소 소유자가 Phase 7 의 두
기기 실측을 기다리는 동안 그중 GUI 구조와 무관한 부분을 먼저 정했다. 출발점은 실행 파일을 쓰기가 번거롭다는 것이었다.

- 실행할 때마다 `--server <주소>` 와 `--name <이름>` 을 쳐야 했다. 제어 서버는 하나이고 주소가 고정이다
- 탐색기에서 더블클릭하면 관리자가 아니라 기동 실패(`adapter.error reason=not_elevated`)였고, 창이 바로 닫혀 이유가 보이지 않았다
- 로비에서 무엇을 칠 수 있는지 알려 주는 것이 없었다. 로그가 같은 창에 나와 화면을 채웠다
- 사람에게 보이는 문장이 한국어였다

## 결정

저장소 소유자가 아래를 정했다.

**1. 제어 서버 주소의 기본값을 빌드에 넣는다.** CMake 값 `SANGTACHI_DEFAULT_SERVER` 다. `--server` 가 덮어쓴다. 비우면
지금처럼 `--server` 가 필수다. 레포는 공개라 실제 주소를 레포에 두지 않고, 배포 빌드를 만드는 사람이 설정할 때 준다.
시험 빌드는 비워 둔다.

**2. `--name` 을 필수에서 뺀다.** 없으면 `user_` 뒤에 ASCII 소문자와 숫자 8자를 CSPRNG 로 고른 이름을 쓴다. 로비의
`name` 명령으로 바꾼다. 붙임표가 아니라 밑줄인 것은 `control_plane.md` 2.7 의 문자 집합에 붙임표가 없기 때문이다.

**3. 표준 출력이 콘솔이면 로비 안내를 낸다.** 로비 안내, 방 안내, 새 명령 `help`, 거부 사유 안내, `Loading...`,
입력 자리 표시 `> ` 다. 표준 출력이 리다이렉트되면 하나도 내지 않는다.

**4. 사람에게 보이는 줄은 모두 영어다.** 안내와 `architecture.md` 8장의 실패 문장이다.

**5. 로그는 로그 파일로 간다.** 실행 파일 옆 `logs\` 에 기록 파일과 같은 이름으로 연다. 표준 오류에는 리다이렉트됐으면
전부, 콘솔이면 기동 중의 `ERROR` 줄만 쓴다.

**6. 배포 빌드는 관리자 권한 매니페스트를 넣는다.** CMake 옵션 `SANGTACHI_REQUIRE_ADMIN` 이다. 시험 빌드는 넣지 않는다.

**7. 혼자 쓰는 창에서 기동에 실패하면 Enter 를 기다린다.** 안내 두 줄로 이유가 `ERROR` 줄에 있다는 것과 로그 파일
이름을 알린다.

## 대안

**대안 1. 서버 주소를 소스 상수로 둔다.**
버렸다. 가장 단순하다. 대가는 공개 레포에 주소가 남는 것이다. `deploy/*.local.md` 를 ignore 하는 이유와 부딪친다.

**대안 2. 서버 주소를 실행 파일 옆 설정 파일에 둔다.**
버렸다. 다시 빌드하지 않고 주소를 바꿀 수 있다. 대가는 `architecture.md` 3.5 가 Phase 1~5 에 두지 않기로 한 설정 파일을
여는 것이고, 어느 파일로 돌렸는지가 기록에 남지 않는다.

**대안 3. 기본 이름 없이 `--name` 을 그대로 필수로 둔다.**
버렸다. ADR 0015 의 대안 8 은 모두가 같은 기본 이름을 써서 `name_taken` 에 걸리는 것 때문에 버려졌다. 8자 난수 접미사는
36의 8제곱 가지라 한 방(최대 다섯 명) 안에서 겹치는 일이 사실상 없다. 겹치면 `name_taken` 의 `FAIL` 뒤 `name` 으로 바꾼다.
남는 대가는 사람이 정하지 않은 이름이 `FAIL` 줄의 `<상대>` 와 멤버 목록에 보일 수 있다는 것이다.

**대안 4. 안내를 늘 표준 출력에 낸다.**
버렸다. 표준 출력을 읽는 스크립트가 줄마다 안내인지 가려야 한다. 콘솔 여부가 사람과 스크립트를 이미 가른다.

**대안 5. 로그를 화면에 그대로 둔다.**
버렸다. 안내가 묻힌다. 표준 오류를 리다이렉트하는 스크립트와 현장 절차는 바뀐 규칙에서도 전부 받는다.

**대안 6. 관리자가 아니면 클라이언트가 스스로 UAC 승격을 요청해 다시 실행한다.**
버렸다. 관리자가 아닌 셸의 `--no-adapter` 실행이 배포 빌드에서도 된다. 대가는 다시 실행하는 경로의 인자 전달, 새 창,
거부 처리 코드다. 매니페스트는 코드가 없다.

**대안 7. 안내를 한국어로 둔다.**
버렸다. 저장소 소유자가 사람에게 보이는 줄을 영어로 정했다.

## 결과

**얻는 것.**

- 배포 빌드는 더블클릭과 UAC 동의만으로 로비까지 간다
- 시험 스크립트가 읽는 표준 출력과 표준 오류는 그대로다

**치르는 것.**

- 배포 빌드는 관리자가 아닌 셸에서 띄울 수 없다. `--no-adapter` 도 그렇다
- 기본 주소가 바뀌면 배포 빌드를 다시 만든다
- 실행할 때마다 `logs\` 에 파일이 하나 는다. 지우는 것은 사람이다
- `field-kit-p7` 키트는 이 결정 앞의 태그라 바뀐 동작이 없다. 다음 키트부터 들어간다
