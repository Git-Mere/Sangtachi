# Loss accounting counts from the peer's connected signal

## Why

[Issue 0009](../../issue_history/0009-닿지-않는-후보로-보낸-hello-가-손실로-세졌다.md). When we entered `CONNECTED` first, the number of a punch `HELLO` the peer then sent to an unreachable candidate stayed as loss. The repository owner decided to fix the accounting and measure the Phase 9 batches again.

## What changed

| What | Where |
|------|-------|
| Accounting start condition. Both our `CONNECTED` and the peer's connected signal hold. A connected signal is a `KEEPALIVE`, `DATA`, `PING`, or `ROSTER` that advanced `highest` after `got_ack`. Renegotiation step 3 clears the signal mark | `protocol.md` 4.5, 9.2, 9.5, chapter 15 |
| Decision and rejected alternatives | [ADR 0041](../../decisions/0041-loss-accounting-starts-at-peer-connected-signal.md) |
| Implementation. The `peer_signal_` mark and `start_loss_segment()` | `client/src/peer/session.cpp`, `session.hpp` |
| Tests. The issue 0009 order, a signal type table, a table of signals that do not advance, a signal before `got_ack`, a signal dropped after 8.3, a signal arriving first, the signal mark after renegotiation. Existing loss tests now feed a signal first | `tests/peer/session_test.cpp`, `tests/tunnel/tunnel_test.cpp` |
| Closed issue 0009 as resolved | `issue_history/` |
| Measure the Phase 9 batches again | `plan.md` (Korean only), `field-test/required-test.md` |

## Cross-model review

Codex (`gpt-6.1-sol`). The code side ran with the correctness (A) and test (B) lenses; the docs side ran separately with the Korean/English parity and conflicts with other living documents (C) and handoff (D) lenses. The docs side was `LGTM - no blockers` on the first run.

| Finding | Handling |
|---------|----------|
| [A] warn. The renegotiating side keeps its `sequence` and sends `HELLO` again, so a late signal from before the renegotiation starts accounting early | Applied. Only a signal that advances `highest` counts |
| [B] warn. No test pins the 8.3 boundary for the signal (duplicate, too old, dropped by a type check after 8.3) | Applied. Added two tests |
| [A] blocker (repair round 1). A late old `HELLO` can pin the new attempt's epoch, and an old `KEEPALIVE` can then advance. Advancing alone does not stop it | Applied. Only a signal after `got_ack` counts, because a `HELLO_ACK` echoing the new attempt's nonce comes only after the renegotiation. Added that order as a test |

Repair round 2 was `LGTM - no blockers`. The final staged diff with this record filled in was run again with the same lenses. `LGTM - no blockers`.
