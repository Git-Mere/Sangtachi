# Startup input and console screen (part of the Phase 8 pre-start decisions)

## Why

The repository owner tried the executable and pointed out what was awkward. Every run needed `--server` and `--name`. A double-click in
Explorer was not elevated, so the window closed at once. Nothing told the user what to type in the lobby, and logs filled the screen.
These are the parts of the startup input path and privilege elevation that `roadmap.md` Phase 8 asks to settle before it starts, and they
do not depend on the GUI structure. So they were decided and implemented while the Phase 7 two-machine measurement waits. The decision
is ADR 0030.

## Key decisions

- **The owner settled the wording while looking at the screen.** The first guide was in Korean. The owner asked for English, no example on
  the join line, an input prompt and `Loading...`. In the end the owner made every line a person sees English, including the failure sentences
- **The default name uses `user_`.** The owner said `user-`, but the character set of `control_plane.md` 2.7 has no hyphen and the server
  would reject it. The owner was told and the underscore was used
- **Guides and `> ` appear only when stdout is a console.** The stdout that test scripts read is unchanged. `lobby-check`'s "no role: nothing
  on stdout" and "exactly one stdout line" still pass
- **Logs go to a file, and when stderr is redirected everything also goes there.** This keeps the `2>` of the tests and the `field-test`
  procedure as they are. On a console only startup `ERROR` lines stay on screen, because the startup failure window points at them
- **Elevation uses a manifest.** The owner chose it over relaunching itself (ADR 0030 alternative 6). Starting a release build from a shell needs
  an elevated cmd. An Explorer double-click asks for UAC consent
- **`field-test/README.md` was not changed.** The current procedure is for the kit of tag `field-kit-p7`. What to change for the next kit is
  in `plan.md` "Places to look at during implementation"

## Verification

- `pwsh -NoProfile -File scripts/test.ps1`: `all tests passed`. 641 unit tests, `cli-check`, `e2e-check`, `lobby-check`, `session-check`
- A release build (`SANGTACHI_REQUIRE_ADMIN=ON`) started from a non-elevated shell was refused by Windows (`Permission denied`)
- A test build started in a new window it owns alone failed startup with `missing_server`. It was still alive after 4 seconds, waiting for Enter
- The same way, a `--no-adapter` start created a file under `logs\` and wrote the log into it
- **The first full test run failed `lobby-check`'s "--room without a role exits within 10s".** A parent without a console that redirects stdin
  to a pipe makes the child own a new console, and the child went into the Enter wait. After making it wait only when stdin is a console it passed
- The owner double-clicked a release build and saw the UAC prompt, the lobby guide and `> `
- `python tools/docgate/docgate.py`, `--claims`: `VERDICT: pass`

## Cross-model review

Codex reviewed the code diff twice. The lenses were "correctness and contract preservation + lifecycle and concurrency" and "security +
robustness". There were three findings. All were applied.

| # | Finding | Disposition |
|---|---------|-------------|
| 1 | `blocker` [correctness]. The startup failure window's guide could be written even when stdout is redirected, against the console-only rule | Applied. The guide and the wait happen only when stdout is also a console. The `architecture.md` 3.5 sentence was fixed too |
| 2 | `blocker` [security]. `console.rejected` for an unknown command carries the typed text. Logs now stay in a file, so the room code of a typo like `Join K7PQ2M` is stored | Applied. Only the reason is logged. A test was added to `loop_test`. The line already went to stderr before this change, and the field procedure saved it with `2>` |
| 3 | `warn` [robustness]. `SANGTACHI_DEFAULT_SERVER` goes straight into a string literal of the generated header, so a quote or backslash breaks the source | Applied. Configuration stops if the value has anything other than letters, digits, `.`, `-` and `:`. The format check at startup is unchanged |

Codex then reviewed the full staged diff including documents and records. The lens was "code-document agreement + records". There were three
findings, all `warn`. All were applied.

| # | Finding | Disposition |
|---|---------|-------------|
| 4 | [agreement] The `--no-adapter` row of `architecture.md` 3.5 says it starts without administrator rights, but the release build's manifest requires elevation even with that switch | Applied. The row says release builds are the exception and points to `windows-prereq.md` section 1 (mirror included) |
| 5 | [agreement] Starting with a `host` or `player` role shows no `> ` until a response arrives | Applied. After handing over the startup command, `> ` is shown when stdout is a console |
| 6 | [records] "A release build can only be started from an elevated cmd" contradicts the double-click run | Applied. From a shell it needs an elevated cmd, a double-click asks for UAC consent. `plan.md` too |
