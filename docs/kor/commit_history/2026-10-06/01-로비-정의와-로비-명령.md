# 로비를 방 소속으로 다시 정의하고, 후보 없이 떠난 참가자의 자리를 서버가 회수하게 했다

## 왜 했나

`roadmap.md` Phase 3 착수 전 항목 가운데 문서만으로 끝나는 것이 하나였다. 로비가 받는 입력,
`FAIL` 줄, 시도 실패 뒤의 프로세스 거동이다. ADR 0008 결정 8 이 "콘솔 빌드도 로비로 돌아간다"
를 정하고 "콘솔 어휘와 CLI 인자의 관계" 를 `architecture.md` 3.5 로 넘겼는데 그 서술이 없었다.

같은 작업에서 `plan.md` 의 "다음에 할 일" 표를 고쳤다. 1번 eng 미러(`bfd2b54`)와 2번 Phase 2
감사(`baa1374`)가 이미 끝났는데 남아 있었다.

## 저장소 소유자가 정한 것

에이전트가 안을 내고 소유자가 전부 권하는 안으로 정했다. 두 번에 나눠 물었다.

| 묻은 것 | 정한 것 |
|---------|---------|
| 로비 명령 | `host`, `join <방 코드>`. 방에 있거나 미결 요청이 있으면 `WARN` |
| CLI 와 로비 명령의 관계 | CLI 역할은 기동 직후의 로비 명령이다. 역할은 필수가 아니다 |
| 시도 실패 뒤 | `FAIL` 줄을 내고 로비로 간다. 종료 코드는 시도 결과를 담지 않는다 |
| Phase 6 이후의 `[console]` | 콘솔 빌드에 남는다. `--peer` 와 `raw` 만 사라진다 |
| 로비의 정의 | 세션 목록이 아니라 방 소속이다. 호스트는 방을 세운 뒤 세션이 없어도 남는다 |
| 미결 요청 중 `leave` | 시도를 중단하고 늦은 응답을 버린다. 그 응답 전에는 `host` / `join` 을 받지 않는다 |
| 로비에서 다시 참가할 때 STUN | 다시 돌린다. 건너뛸지는 실측 전까지 미결 |
| 후보 없이 떠난 참가자의 자리 (리뷰 1라운드가 짚음) | 서버가 회수한다. 대상은 후보가 비어 있고 유예가 지난 피어뿐이다. ADR 0012 |
| 정원이 찬 방에서 퇴장 직후의 `room_full` (소유자가 짚음) | 호스트가 세션 종료 즉시 `host_report` 를 보낸다. ADR 0012 결정 6 |

**자리 회수의 범위는 소유자와 두 번 주고받아 정했다.** 소유자는 처음에 "방 관리 주체를 서버로"
를 물었다. 에이전트는 서버가 터널 생존을 볼 수 없다는 점을 들어 좁은 범위를 권했고 소유자가
그쪽을 골랐다. 모든 회수를 서버로 옮기면 연결된 피어가 서버에 계속 신호를 보내야 하고, 제어
평면 장애가 살아 있는 피어의 자리를 회수하게 된다.

**가상 IP 풀을 `10.100.0.10` 까지 늘리는 안은 소유자가 냈고 검토 뒤 버렸다.** 풀 크기가 곧 방
정원이라, 늘리면 5명 제한이 깨지거나 정원을 따로 셀 때 같은 `room_full` 이 난다. 이유는 ADR
0012 대안 5 다.

**로비 정의는 질문하기 전에 문서를 읽다가 나온 구멍이다.** `concurrency.md` 7장과 ADR 0008
결정 1 이 로비를 "세션 목록이 빈 상태" 로 적었다. 호스트는 방을 막 세웠을 때와 마지막 플레이어가
나갔을 때 세션이 없으므로, 그 정의대로면 방을 버린다. 결정을 좁히는 것이라 ADR 0011 을 새로
쓰고 ADR 0008 은 고치지 않았다.

**Phase 6 이후의 콘솔 입력도 문서끼리 어긋나 있었다.** `concurrency.md` 1장이 `[console]` 을
Phase 1~5 스캐폴딩으로 적었는데 ADR 0008 결정 8 은 Phase 6 이후의 콘솔 빌드도 로비로 간다고
했다. 그때는 명령을 받을 스레드가 없다.
