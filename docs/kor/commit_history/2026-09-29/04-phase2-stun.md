# Phase 2. STUN 클라이언트

## 무엇을 했나

NAT 뒤 클라이언트의 공인 UDP 엔드포인트를 알아낸다. [`roadmap.md`](../../roadmap.md) Phase 2 다.
범위는 [`protocol.md`](../../protocol.md) 13장 STUN 사용 범위, 재시도와 마감은 11장 타이머,
서버 선택과 기동 입력은 [`architecture.md`](../../architecture.md) 3.5 가 정한 그대로다.

## 나눈 방법

작업을 셋으로 갈라 둘을 병렬로 돌렸다. **빈 파일과 CMake 배선을 먼저 만들고 빌드를 확인한 뒤**
각자에게 자기 파일만 주었다. 같은 트리에서 두 에이전트가 같은 파일을 고치면 서로 덮어쓴다.

| 조각 | 무엇 |
|------|------|
| 이음새 | `TimerSet` 에 이름 키·취소·일회성, `platform::random_bytes`, `platform::resolve_ipv4` |
| 코덱 | `network/stun`. 메시지 구성과 파싱. **순수 함수만** |
| 배선 | 수신 분류, 송신 이음새, `network/stun_client`, 기동 입력, 로그와 카운터 |

**코덱에서 난수와 타이머와 소켓을 뺀 것이 이 분할의 핵심이다.** 트랜잭션 ID 를 인자로 받으면
시험이 값을 고정할 수 있다. 안에서 뽑으면 골든 벡터를 만들 수 없다.

## 설계에서 정한 것

- **재시도 500ms·1s·2s 는 간격이다.** 0, 500, 1500, 3500 에 보낸다. 절대 시각으로 읽으면
  간격이 500/500/1000 이 되어 RFC 5389 7.2.1 의 배증 수열이 아니다
- **빈 자리는 마감뿐 아니라 응답으로 비었을 때도 채운다.** 마감에서만 채우면 목록 4개에서
  앞 서버가 1s 에 응답하고 뒤가 5s 에 마감할 때 끝이 15s 가 된다. 상한은 10s 다
- **응답은 트랜잭션 ID 로만 잇는다.** 출발지 주소를 함께 보지 않는다 (`protocol.md` 7장)
- **끝나는 경로 셋(응답·마감·단계 종료)이 같은 자리를 지난다.** 그래야 끝난 트랜잭션의 뒤늦은
  응답을 폐기로 세지 않는다
- **난수원, 시계, 소켓, 이름 해석을 전부 주입한다.** 시험이 500ms 를 실제로 기다리지 않고
  DNS 에 기대지 않는다

## 문서를 고친 것

코드가 먼저 정하지 않게 문서를 앞세웠다.

| 무엇 | 어디 |
|------|------|
| 주소 없는 성공 응답은 폐기한다 | `protocol.md` 13장 |
| **`XOR-MAPPED-ADDRESS` 가 두 개 이상이면 폐기한다.** `ERROR-CODE` 는 처음 것만 읽는다 | 같은 절 |
| 파싱 실패는 `drop_stun_parse` 로 센다. 이유를 코드별로 나누지 않는다 | 같은 절 |
| **해석 결과가 같은 엔드포인트인 항목은 하나로 친다** | `architecture.md` 3.5 |
| 7장 출발지 위생의 자기 서브넷 브로드캐스트 판정을 Phase 4 로 건다 | [`roadmap.md`](../../roadmap.md) Phase 4 |
| `FAIL` 표준 출력 줄과 시도 실패 뒤의 프로세스 거동을 Phase 3 으로 건다 | `roadmap.md` Phase 3 |

**중복 속성의 처리를 둘로 가른 이유.** `XOR-MAPPED-ADDRESS` 는 우리가 상대에게 알릴 공인
엔드포인트가 되므로 틀린 것을 고르면 그 뒤의 홀펀칭이 통째로 엉뚱한 곳을 향한다.
`ERROR-CODE` 는 로그에만 쓰인다. **판정에 들어가는 값과 그렇지 않은 값의 차이다.**

## 검증

| 무엇 | 결과 |
|------|------|
| 빌드 | `build ok` (MSVC /W4 /WX 경고 0) |
| 시험 | `0 checks failed` / `all tests passed`. 101 -> **154건** |
| e2e | `0 checks failed`. 검사 28 -> 35 |
| `platformgate` | `VERDICT: pass` |
| `docgate` | `link` 0건 |

**e2e 는 공개 STUN 서버를 부르지 않는다.** 스크립트 안에 최소 STUN 응답기 두 대를 띄워
`stun.result` 의 `mapped` 가 그 클라이언트의 로컬 포트와 맞는지까지 본다. 이것을 하기 전에는
실제 Google STUN 응답이 `rx.raw` 로 섞여 Phase 1 대조가 6건 깨졌다.

**기본 STUN 목록은 세 곳이 같다.** `natprobe.py` 의 `DEFAULT_STUN_SERVERS`(68줄),
`architecture.md` 3.5 의 코드 블록, `stun_client.hpp` 의 `kDefaultStunServers`(99줄)를 네
항목의 이름·포트·순서까지 눈으로 대조했다. **`natprobe.py` 는 이 커밋에서 바뀌지 않았다.**
그 파일이 출처이고 나머지 둘이 그것을 따라 적은 것이므로 바꿀 것이 없다.

### 반영

| 지적 | 어떻게 |
|------|--------|
| 중복 `XOR-MAPPED-ADDRESS` 를 "첫 번째" 로 결정한다 | 반영. 폐기로 바꾸고 이유를 새로 만들었다(`kDuplicateMappedAddress`). 기존 이유에 얹으면 로그 토큰 하나가 서로 다른 두 조건을 가리킨다 |
| 마감으로 끝난 트랜잭션의 뒤늦은 응답을 폐기로 센다 | 반영. 끝나는 경로 셋을 한 자리로 모았다. **구현자가 적어 둔 규칙과 코드가 어긋난 자리였다** |
| `owns_timer` 가 `stun.` 접두를 전부 자기 것이라 한다 | 반영. 모양 일치로 바꿨다. 접두 일치는 배제 목록이고 모양 일치가 허용 목록이다 |
| 시험이 진짜 난수를 써서 ID 유일성이 확률 명제다 | 반영. 난수원을 주입한다. `random_bytes` 실패 경로에 시험이 생겼다 |
| `resolve_test` 의 한 케이스가 성공하면 `SUCCEED()` 로 끝나 아무것도 지키지 않는다 | 반영. 전제를 가정하지 않고 검사한 뒤 단정한다 |
| 옛 형식 IPv4 가 `getaddrinfo` 로 새 나간다 | 반영. 숫자 모양 판정을 앞에 두고 케이스 표를 붙였다. **다만 아래 "못 지킨 것" 을 보라** |

### 시점을 건 것 (blocker 1건)

**7장 출발지 위생의 자기 서브넷 브로드캐스트 판정이 없다.** 기각하지 않았다. 인터페이스 주소와
넷마스크가 있어야 계산되고 그것을 읽는 자리가 `protocol.md` 10.1 로컬 후보 수집이라 Phase 4 다.
넷마스크를 모르는 채로 추측해 막으면 그것이 `CLAUDE.md` 규칙 7 이 금지하는 것이다.
`roadmap.md` Phase 4 에 항목으로 걸고 **그때까지 남는 위험**을 그 자리에 적었다. 회신을 내는
코드(`HELLO_ACK`, `PONG`)가 같은 Phase 에 생기므로 지금은 증폭시킬 회신 자체가 없다.

## 못 지킨 것

**숫자 모양 판정의 변이가 시험에 잡히지 않는다.** `resolve_ipv4` 에서 그 호출을 지운 변이가
통과한다. 이 기계의 `getaddrinfo` 가 `1.2.3`, `0x7f.1`, `010.1.1.1` 같은 표기를 스스로 거부해
반환값이 같기 때문이다. **그래서 그 규칙을 지키는 것은 판정 함수의 케이스 표 하나이고**,
`resolve_ipv4` 쪽 단정은 거동만 못박는다. 그 사실을 헤더와 시험 주석 양쪽에 적었다.

**리뷰어가 든 기전은 이 기계에서 재현되지 않았다.** 위 표기 여덟 개를 `AF_INET`/`SOCK_DGRAM`
으로 물어 전부 해석 실패였다. 그래서 "Winsock 이 옛 `inet_addr` 형식을 해석한다" 를 단정으로
적지 않고 확인 가능한 두 번째 기전(NXDOMAIN 가로채기, 검색 접미사)을 근거로 남겼다.

## 구현자가 찾은 것

리뷰가 아니라 구현자가 낸 지적이다. **기본 목록의 앞 두 항목이 같은 IP 로 풀린다.**
`tools/nat-probe/` 실측이 그렇게 기록했다. 목록 항목으로는 "서로 다른 두 서버" 지만 실제
목적지는 하나이고, 그러면 `spec.md` 지원 네트워크 조건의 판정이 성립하지 않는데 **항목 수만
보면 두 개로 보인다.** `architecture.md` 3.5 에 엔드포인트로 중복을 거르는 규칙을 적고
구현했다. 목록 4개 중 실제 목적지가 3개이므로 단계 상한은 `5s x ceil(3/2)` = 10초 그대로다.

## 이번에 확인한 것

- **변이가 통과하는 데는 두 가지 이유가 있다.** 시험이 약한 것과 변이가 닿지 않는 자리에 있는
  것이다. 구현자가 죽은 코드에 변이를 넣어 통과한 사례를 스스로 구분했다. 그 구분을 하지 않으면
  "통과했으니 시험이 약하다" 는 틀린 결론을 낸다
- **MSVC 디버그에서 변이 시험은 모달 창에 매달린다.** 경계 검사를 지운 변이가
  `span subscript out of range` 창을 띄워 하네스가 멈췄다. 사용자가 화면을 보고 알려 주었다.
  `tests/crt_report_guard.cpp` 로 단언과 `abort()` 와 오류 보고를 표준 오류로 돌렸다.
  **이제 크래시하는 변이는 매달리지 않고 실패로 잡힌다**
- **부모가 그 가드 파일을 넣고 빌드를 돌리지 않은 채 하위 에이전트에게 다시 빌드하라고 지시했다.**
  레포 전체 빌드가 그 파일에서 멈췄고 하위 에이전트가 정확히 짚어 돌려주었다
