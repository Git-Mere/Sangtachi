# 기동 입력과 콘솔 화면 (Phase 8 착수 전 결정 일부)

## 왜 했나

저장소 소유자가 실행 파일을 직접 써 보고 불편한 점을 짚었다. 실행할 때마다 `--server` 와 `--name` 을 쳐야 했고,
탐색기에서 더블클릭하면 관리자가 아니라 창이 바로 닫혔고, 로비에서 무엇을 칠 수 있는지 알려 주는 것이 없었고, 로그가
화면을 채웠다. `roadmap.md` Phase 8 이 착수 전에 정하라고 한 기동 입력 경로와 권한 승격 가운데 GUI 구조와 무관한
부분이라, Phase 7 의 두 기기 실측을 기다리는 동안 먼저 정하고 구현했다. 결정은 ADR 0030 이다.

## 중요한 결정

- **문구는 저장소 소유자가 화면을 보며 정했다.** 처음 한국어 안내를 넣었고, 소유자가 영어로, join 의 예시를 빼고, 입력 자리 표시와
  `Loading...` 를 더하라고 했다. 마지막에 사람에게 보이는 줄을 실패 문장까지 모두 영어로 정했다
- **기본 이름은 `user_` 다.** 소유자는 `user-` 를 말했지만 `control_plane.md` 2.7 의 문자 집합에 붙임표가 없어 서버가 거부한다.
  소유자에게 알리고 밑줄로 했다
- **안내와 `> ` 는 표준 출력이 콘솔일 때만 낸다.** 시험 스크립트가 읽는 표준 출력은 그대로다. `lobby-check` 의 "no role: nothing on
  stdout" 과 "exactly one stdout line" 이 그대로 통과한다
- **로그는 파일로 가고, 표준 오류가 리다이렉트되면 전부 같이 나간다.** 시험과 `field-test` 절차의 `2>` 를 바꾸지 않으려는 것이다.
  콘솔이면 기동 중의 `ERROR` 줄만 화면에 남긴다. 기동 실패의 창이 그 줄을 가리킨다
- **권한 승격은 매니페스트로 했다.** 스스로 다시 실행하는 방법과 견줘 소유자가 골랐다(ADR 0030 대안 6). 배포 빌드를 셸에서 띄울 때는
  관리자 cmd 여야 한다. 탐색기 더블클릭은 UAC 동의를 묻는다
- **`field-test/README.md` 는 고치지 않았다.** 지금 절차는 태그 `field-kit-p7` 의 키트를 위한 것이다. 다음 키트에서 바꿀 것을 `plan.md`
  "구현 때 같이 볼 자리" 에 적었다

## 검증

- `pwsh -NoProfile -File scripts/test.ps1`: `all tests passed`. 단위 시험 641개, `cli-check`, `e2e-check`, `lobby-check`, `session-check`
- 배포 빌드(`SANGTACHI_REQUIRE_ADMIN=ON`)를 관리자가 아닌 셸에서 띄우면 Windows 가 거부했다(`Permission denied`)
- 시험 빌드를 혼자 쓰는 새 창으로 띄워 `missing_server` 로 기동에 실패하게 했다. 4초 뒤에도 프로세스가 살아 Enter 를 기다렸다
- 같은 방법으로 `--no-adapter` 기동을 띄워 `logs\` 에 파일이 생기고 로그가 쓰이는 것을 봤다
- **처음 전체 시험에서 `lobby-check` 의 "--room without a role exits within 10s" 가 실패했다.** 콘솔 없는 부모가 표준 입력을 파이프로
  돌려 띄우면 자식이 새 콘솔을 혼자 쓰게 되어 Enter 대기에 들어갔다. 표준 입력이 콘솔일 때만 기다리게 고친 뒤 통과했다
- 저장소 소유자가 배포 빌드를 더블클릭해 UAC 동의, 로비 안내, `> ` 를 확인했다
- `python tools/docgate/docgate.py`, `--claims`: `VERDICT: pass`
