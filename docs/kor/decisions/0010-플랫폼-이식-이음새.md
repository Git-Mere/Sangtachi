# 0010. 플랫폼 이식 이음새를 지금 고정한다

- 상태: 채택
- 날짜: 2026-09-29
- 관련: [`../spec.md`](../spec.md) 제외·스트레치 목표·C-1, [`../architecture.md`](../architecture.md) 3.1·10장·12장, [`../concurrency.md`](../concurrency.md) 2장·4장, [`../protocol.md`](../protocol.md) 6장, [`../roadmap.md`](../roadmap.md) 스트레치 목표

## 맥락

살아 있는 문서 넷이 플랫폼을 말한다. 넷 다 "안 한다" 쪽이다.

| 문서 | 무엇을 적었나 |
|------|---------------|
| `spec.md` 제외 | 모바일 지원, macOS 지원 |
| `spec.md` 스트레치 목표 | Linux 상호 운용성 |
| `architecture.md` 12장 | "macOS / 모바일: 지원하지 않는다. Linux는 시간이 남으면 상호 운용성만 검토" |
| `roadmap.md` 스트레치 목표, `spec.md` 우선순위 | P4 = 암호화 + 릴레이 + 추가 플랫폼 |

**"언젠가 할 수도 있다" 는 적혀 있고 "그때 무엇을 다시 써야 하는가" 는 어디에도 없다.**
ADR 9건 가운데 이식을 다룬 것이 없고, `architecture.md` 3.1 클라이언트 모듈 표는 이음새를
이름으로 갖지 않는다. 모듈 이름 자체가 벤더인 자리도 있다(`adapter/wintun_adapter`).

코드를 세어 보니 이음새는 작다. 이 결정을 쓰기 **전**의 클라이언트에서 OS 헤더를 포함하는
원본은 다섯이고(`console.cpp`, `hash.cpp`, `loop.cpp`, `network/udp_socket.cpp`,
`network/wsa.cpp`), 공개 헤더(`client/include/`)에는 OS 헤더가 하나도 없었다. 우연이 아니라
Phase 1 이 그렇게 썼다. `udp_socket.hpp` 는 소켓을 `std::uintptr_t` 로, 이벤트를 `void*` 로
내놓고 `wsa.hpp` 는 `WORD` 대신 `VersionWord` 별칭을 둔다.

**지금 하는 이유는 Phase 6 이다.** 이음새가 지금은 소켓과 루프뿐이다. Wintun 과 IP Helper 가
들어오면 어댑터, 라우팅, 권한까지 퍼지고, 그때는 같은 작업이 몇 배가 된다.

## 결정

**이식하지 않는다. 이음새만 이름으로 고정한다.** 다섯을 포함한다.

**1. 이음새는 다섯이다.** 이식할 때 다시 쓰는 자리가 이것이고, 그 밖은 다시 쓰지 않는다.

| # | 이음새 | 계약의 출처 | 이 결정 시점의 코드 자리 |
|---|--------|-------------|----------------|
| 1 | 소켓 | `protocol.md` 6장 소켓 소유권 | `platform/win32/wsa.cpp`, `platform/win32/udp_socket.cpp` |
| 2 | 대기와 단조 시계 | `concurrency.md` 2장 대기, 4장 타이머 | `platform/win32/wait.cpp` |
| 3 | 가상 어댑터와 라우트 | `architecture.md` 3.2.3, 7장 | 아직 없다. Phase 6 |
| 4 | 해시 | `architecture.md` 9장 (`rx.raw` 의 `sha256`) | `platform/win32/hash.cpp` |
| 5 | 기동과 권한 | `windows-prereq.md` | 코드가 아니라 실행 전제다 |

오른쪽 칸은 이 결정을 내릴 때의 자리다. **현재 배치의 출처는 `architecture.md` 10장 목표
구조이고 이 표가 아니다.** 어댑터 원본이 생기면 그 문서를 고친다.

> **왜 다섯인가.** 처음에는 넷으로 셌다. 소켓, 대기, 어댑터, 기동이다. 코드를 읽고 해시를
> 더했다. `sha256_hex` 가 `BCryptHash` 를 부른다. 옮기려면 다른 구현이 필요하고, 그것이
> 서드파티라면 `spec.md` NFR-5 의 승인 대상이 된다. 세지 않았으면 이식 견적에서 빠졌을 자리다.

**2. 규칙은 하나다. OS 헤더를 포함하는 클라이언트 원본은 `client/src/platform/` 아래에만
둔다.** `client/include/` 아래에는 OS 헤더가 하나도 없다. 새 플랫폼 코드는
`client/src/platform/win32/` 에 만든다.

> **왜 "포함" 이 기준인가.** 기계가 셀 수 있는 유일한 축이기 때문이다. "Windows 에 기댄다"
> 는 판정은 사람이 매번 다르게 내리고, 그러면 규칙이 라운드마다 흔들린다.

**3. 헤더의 의미까지 중립인 것은 아니다.** `udp_socket.hpp` 는 `WSAGetLastError` 의 정수
오류와 Win32 이벤트 핸들을 그대로 내놓고, `RecvStatus::WouldBlock` 은 `WSAEWOULDBLOCK` 을
가리킨다. `timer.hpp` 의 `kInfiniteTimeout` 은 `INFINITE` 와 같은 값이다. **이 ADR 은 그것을
바꾸지 않는다.** 이름만 중립으로 바꾸면 이식된 것처럼 보이고 실제로는 아니다. 오류 코드와
핸들의 중립 타입은 두 번째 구현을 쓸 때 정한다.

**4. `concurrency.md` 2장의 대기 프리미티브는 이식하면 다시 쓴다.** `WaitForMultipleObjects`
를 고른 이유가 "Wintun 읽기 대기가 소켓이 아니라 Win32 이벤트 핸들" 이었는데, `epoll` 과
`kqueue` 에는 그 문제 자체가 없다. 고른 근거가 그 OS 에만 있으므로 결론도 그 OS 에만 있다.
그 사실을 `concurrency.md` 가 한 줄로 적는다.

**5. 규칙 2를 사람이 세지 않는다.** `tools/platformgate/` 가 판정한다. 마지막 줄이
`VERDICT: pass` 여야 한다. 그 도구가 정한 판정 규칙 여섯을 이 결정에 포함한다.

| # | 규칙 | 왜 |
|---|------|-----|
| a | 전처리기를 평가하지 않는다. `#if 0` 과 `#ifdef _WIN32` 안의 `#include` 도 센다 | 게이트가 지키는 것은 컴파일 결과가 아니라 원본의 배치다. `#if 0` 으로 감싸면 통과하는 게이트는 우회 수단을 알려 주는 것과 같다 |
| b | 주석과 문자열 안의 `#include` 는 세지 않는다 | 컴파일러가 보지 않는 글자다 |
| c | 허용 자리는 `client/src/platform/` 하나이고 하위 디렉터리를 포함한다 | 규칙을 한 줄로 유지한다. `client/include/` 아래는 `platform` 이라는 이름의 디렉터리라도 예외가 없다 |
| d | 경로 비교는 대소문자를 가린다 | 저장소는 철자 하나(`src/platform`)를 쓴다 |
| e | OS 헤더 판정은 **이름 목록**이다. 목록에 없는 헤더는 판정하지 않고 통과시킨다 | 모르는 헤더를 OS 헤더로 단정하지 않는다. 허용 목록이 아니므로 **새 OS 헤더를 쓰기 시작하면 `OS_HEADERS` 에 먼저 넣어야 한다.** 그 의무는 `roadmap.md` Phase 6 이 갖는다 |
| f | 검사 대상 확장자는 `.cpp` 와 `.hpp` 뿐이다 | 저장소가 그 둘만 쓴다. **`.h` 나 `.c` 로 된 원본을 들이면 게이트가 보지 못하므로 `SOURCE_SUFFIXES` 를 먼저 고쳐야 한다.** e 와 같은 종류의 의무이고 같은 자리(`roadmap.md` Phase 6)가 갖는다 |

**게이트의 범위는 `client/` 의 `.cpp` 와 `.hpp` 다.** `tests/` 는 판정하지 않는다. 시험은
플랫폼 동작을 재현하는 것이 일이라 OS API 를 직접 부르는 것이 정상이다. **대가는 시험 코드도
이식할 때 다시 쓴다는 것이고**, 이 ADR 은 그것을 이음새 목록에 넣지 않았다. 그 밖에 판정하지
못하는 것은 `tools/platformgate/README.md` 가 표로 갖는다.

### 이 ADR 이 정하지 않는 것

- **어느 OS 를 언제 지원할지.** `spec.md` 의 제외와 스트레치 목표가 그대로다. 이 결정은
  범위를 넓히지 않는다
- 오류 코드와 핸들의 중립 타입 설계 (결정 3)
- `BCryptHash` 를 무엇으로 대신할지. 서드파티라면 `spec.md` NFR-5 승인이 먼저다
- Wintun 의 대응물 선택. 이음새 3은 Phase 6 에서 코드가 생긴 뒤에 다시 본다
- Qt 는 이음새에 넣지 않았다. 툴킷이 이미 여러 OS 를 도는 것이 그 이유이고, 배포물 패키징이
  OS 마다 다르다는 것은 이음새 5가 갖는다

## 대안

**대안 1. 아무것도 하지 않는다.**
버렸다. 이 상태를 유지하는 비용은 지금 0 이고 Phase 6 뒤에 오른다. 어댑터가 들어오면
이음새가 라우팅과 권한까지 번지므로, 그때 같은 작업을 하면 건드릴 자리가 늘어난다.

**대안 2. 문서에만 적는다.**
버렸다. `architecture.md` 12장에 이음새 목록을 적고 끝내는 안이다. 얻는 것은 코드 변경이
없는 것이고, 치르는 것은 규칙을 지키는 장치가 없는 것이다. `CLAUDE.md` 가 "세는 것은
스크립트가 한다" 로 정한 자리가 정확히 이런 규칙이다. 다음 Phase 가 `<windows.h>` 를 새 파일에
넣어도 아무것도 알려 주지 않는다.

**대안 3. 전면 플랫폼 추상화 계층.**
버렸다. 추상 인터페이스와 가상 함수로 소켓, 대기, 어댑터, 해시를 감싸는 안이다. 얻는 것은
두 번째 구현을 끼울 자리이고, 치르는 것이 둘이다. 첫째, 구현이 하나뿐인 인터페이스는 첫
구현의 모양을 그대로 베낀다. `WSAEventSelect` 를 전제한 인터페이스는 `epoll` 에서 다시
버려진다. 둘째, P0 를 늦춘다. **이식할 때 인터페이스를 그때 만드는 것이 이 대안을 버리는
대가다.**

**대안 4. 지금 이식한다.**
버렸다. `spec.md` 가 macOS 를 제외로, Linux 를 스트레치로 적었고 이 세션은 그것을 뒤집지
않는다. 최소 성공 M-1 ~ M-6 이 Windows 한 대에서 나온다.

## 결과

**얻는 것.**

- 이식 견적이 목록이 된다. 다시 쓰는 파일이 한 디렉터리에 있고 그 계약의 출처가 표에 있다
- Phase 6 의 Wintun 코드가 갈 자리가 이미 정해져 있다. 판단할 것이 하나 줄어든다
- 공개 헤더에 OS 헤더가 없다는 것이 지금은 우연히 지켜진 성질인데, 게이트가 그것을 성질에서
  규칙으로 바꾼다
- 게이트가 기계로 확인하는 것은 **목록에 있는 OS 헤더가 `client/src/platform/` 밖에서
  포함되지 않는다는 것 하나**다. 그것이 "다시 쓸 필요가 없다" 는 증명은 아니다. 남는 결합은
  결정 3이 적었다

**치르는 것.**

- **파일이 옮겨져 이력이 끊겨 보인다.** `git log --follow` 가 필요하다
- **`platform/win32/` 안에 프로토콜 계약을 따르는 코드가 같이 산다.** 소켓 옵션이 그것이다.
  코드가 있는 자리가 계약의 출처를 옮기지 않는다. 그 출처는 `protocol.md` 6장이다
- **게이트는 "포함" 만 본다.** 의미가 Win32 인 중립 헤더는 통과한다. 결정 3이 그것을 알고
  둔 것이지 게이트가 놓치는 것이 아니다
- 규칙을 하나 더 지켜야 한다. 새 원본에 OS 헤더를 넣으려면 자리를 먼저 정해야 한다
