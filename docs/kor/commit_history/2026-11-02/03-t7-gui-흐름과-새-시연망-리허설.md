# T-7 의 GUI 만의 흐름과 새 시연 망의 리허설

## 왜 했나

`spec.md` T-7 은 GUI 만으로 끝에서 끝까지를 요구한다. 앞선 세 기기 측정의 호스트는 콘솔이었다. 소유자가 친구와 GUI 기기 둘로 돌았다.
같은 날 [ADR 0038](../../decisions/0038-시연-호스트를-집-wi-fi-에-둔다.md) 의 새 시연 망으로 리허설도 했다.

## 결과

결과와 한계는 [`experiments.md`](../../experiments.md) 3.4, 4.2 가 갖는다. 요약이다.

| 항목 | 결과 |
|------|------|
| T-7 의 GUI 만의 흐름 | 통과. A 가 GUI 로 방을 만들고 코드를 읽었고, F 가 그 코드로 참가했고, 양쪽 창에 상대가 Connected 로 보였고, F 가 창을 닫자 A 의 목록에서 F 가 빠졌고, F 가 없는 방 코드로 참가해 실패 코드가 보였다 |

## 어떻게 쟀나

- T-7: A 는 휴대폰 핫스팟, F 는 친구의 집 Wi-Fi 다. 두 기기 모두 `field-kit-p8` GUI 배포물을 더블클릭으로 띄웠다. 근거는 A 와 F 의 GUI
  로그, F 의 실패 화면 캡처, A 의 방 화면 캡처다. A 와 F 의 창에 상대가 Connected 로 보인 것은 소유자가 보고 F 에게 들은 것이다
- 리허설: G 는 소유자의 집 Wi-Fi 에서 `ssh` 로 띄웠다. G 의 표준 오류에는 줄마다 받은 시각을 붙였다. 근거는 G 의 로그와 기록 파일,
  Minecraft 서버 로그, A, C, F 의 GUI 로그, 네 멤버가 보이는 A 의 화면 캡처다
- 원본은 `field-test/2026-11-02/` 에 두고 커밋하지 않는다

## 작업 중에 생긴 일

- 같은 두 기기로 A 의 Minecraft 가 싱글 월드를 LAN 에 공개했고 F 가 A 의 가상 IP 와 그 포트로 들어왔다. 따로 띄운 서버 없이도 된다
- 리허설에서 A 가 호스트와 같은 이름으로 참가해 `name_taken` 을 두 번 받았다. FR-16 대로다. 다른 이름으로 참가했다
- 친구의 Minecraft 계정을 G 의 화이트리스트에 넣었다. 리허설 뒤에도 G 의 호스트와 Minecraft 서버는 켜 둔 채다

## 크로스 모델 리뷰

Codex(`gpt-6.1-sol`). 근거·계약(A)과 한영·기록 일관성(B) 렌즈를 한 번에 돌렸다. 처음 T-7 만 담은 차이에서 warn 하나, 리허설을 더한 차이에서 warn 둘을 받았다. 모두 받아들였다.

| 지적 | 처리 |
|------|------|
| [A] F 가 명부를 받은 것은 F 의 창에 A 의 이름이 보였다는 근거가 아니다 | 반영. 소유자가 F 에게 확인해 F 의 관찰로 적었다 |
| [B] 이슈 0007 의 "그날 처음 띄운 GUI" 가 이슈 0006 의 같은 날 기동과 어긋난다 | 반영. 리허설을 위해 처음 띄운 GUI 이고 앞선 GUI 가 약 4시간 46분 전에 끝났다고 고쳤다. 가설도 그에 맞췄다 |
| [B] `plan.md` 가 리허설 호스트를 끝냈다고 하면서 켜 둔 채라고도 한다 | 반영. 스크립트의 쓰임으로 고쳤다 |

고친 뒤 전체 staged 차이를 같은 렌즈로 다시 돌렸다.
