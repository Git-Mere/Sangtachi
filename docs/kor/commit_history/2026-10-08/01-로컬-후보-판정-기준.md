# 로컬 후보 판정 기준 (ADR 0017)

## 왜 했나

`plan.md` 다음에 할 일의 첫째인 Phase 4 착수 전 결정 가운데 하나다. `protocol.md` 10.1 이 "활성 IPv4
인터페이스" 에서 루프백, APIPA, 자기 Wintun, 다른 터널/VPN 어댑터를 빼라고 했지만 "활성" 과 "터널/VPN"
의 판정 입력이 없었다.

선택지 여섯(`IfType` 제외 목록, 이름 문자열, 게이트웨이, `HardwareInterface`, 기본 경로만, 거르지 않음)의
장단점과 케이스 표 초안을 저장소 소유자에게 보였고, 소유자가 추천안을 골랐다. 함께 정해야 한다고 짚은
셋(자기 서브넷 집합의 범위, prefix 31·32, 상한을 넘을 때 자르는 순서)도 추천대로 정했다.

| 질문 | 결정 |
|------|------|
| 활성 | `OperStatus` `Up` 이고 주소 `DadState` `Preferred` |
| 터널/VPN | `IfType` 24·53·131·23 제외. 목록 밖은 포함. `IfType` 6 인 가상 어댑터는 거르지 않는다 |
| 자기 Wintun | 기록한 `InterfaceGuid` 로 따로 본다 |
| 등록 목록 | 반사 후보, 기본 경로 인터페이스의 로컬 후보, 나머지 로컬 후보. 중복 제거 뒤 앞에서 8개 |
| 자기 서브넷 집합 | 활성 단계만 통과한 주소. 루프백 대역과 prefix 31·32 는 넣지 않는다 |

## 중요한 결정

- **제외 목록이다.** 문서 작업 규칙은 안전에 걸린 분류에 허용 목록을 권한다. 이 판정은 보낼 곳을
  고르는 것이고 증폭은 10.1 위생과 7장 출발지 위생이 막고 유니캐스트 반사는 2장 상한이 걸리므로 안전
  분류가 아니라고 보았다.
  모르는 `IfType` 은 넣는다
- **기본 경로는 `0.0.0.0/0` 경로다.** 제안 단계에서는 "STUN 서버 방향의 최선 경로" 도 말했다. 풀터널
  VPN 에서 정렬이 뜻을 잃어 `0.0.0.0/0` 으로 정했다(ADR 0017 대안 9)
- **자기 서브넷 집합을 어느 스레드가 만들고 수신 루프가 어떻게 받는지는 정하지 않았다.**
  `concurrency.md` 의 몫이라 `plan.md` 문서 부채로 두었다

## 검증

| 무엇 | 결과 |
|------|------|
| 실측 | `Get-NetAdapter`, `Get-NetIPAddress`, `Get-NetRoute`. Tailscale 이 Wintun 드라이버이고 `IfType` 53, TAP 과 Hyper-V 는 6, 끊긴 어댑터에 `Tentative` APIPA 주소가 남는다 |
| 표준 원문 | RFC 8445 5.1.1.1(VPN 인터페이스 포함, 루프백만 필수 제외), RFC 8828 Mode 2 를 rfc-editor.org 원문으로 확인 |
| 케이스 표 기대값 | 규칙을 옮긴 스크립트로 22행과 O1~O8 을 계산해 문서 값과 대조했다. 불일치 0. O9~O11 은 실패 규칙을 읽어 손으로 맞췄다 |
| 변이 | 같은 스크립트에 변이 열하나(53 누락, 131 누락, 23 누락, `OperStatus` 만, 주소만, "실패 상태가 아님", 식별자 규칙 삭제, 집합을 후보에서 만듦, 31 계산, prefix 범위 미검사, prefix 로 후보 제외)를 넣었다. 모두 한 행 이상에서 걸렸다. prefix 범위 미검사는 스크립트에서 예외로 멈췄다 |
| 시나리오 추적 | 같은 LAN 의 두 PC, 한쪽에 Tailscale. Wi-Fi `10.0.0.49/24` 만 후보이고 등록 목록은 반사 후보 다음 그 주소다. 자기 서브넷 집합은 `{10.0.0.49/24}` 이고 `10.0.0.255` 를 막는다. Tailscale `/32` 는 들어가지 않는다. `10.0.0.255` 출발지는 `drop_bad_source` |
| 문서 게이트 | `docgate.py` `VERDICT: pass` |

## 크로스 모델 리뷰

Codex. 한국어와 영어를 함께 담은 staged diff 에 렌즈 둘을 따로 돌렸다.

| 렌즈 | 지적 | 처리 |
|------|------|------|
| 일관성 | warn. 서로 다른 반사 후보가 많으면 "상한에 걸려도 기본 경로 LAN 후보가 남는다" 가 성립하지 않는다 | 반영. 조건을 붙이고 O8 을 더했다. ADR 도 고쳤다 |
| 일관성 | warn. 케이스 표의 집합 열이 브로드캐스트 주소인데 집합의 원소는 주소와 prefix 다 | 반영. 열 이름을 "자기 서브넷 집합이 막는 브로드캐스트" 로 |
| 일관성, 실패 처리 | warn. 열거와 경로 조회의 실패가 정해지지 않았다. 실패를 빈 결과로 다루면 브로드캐스트 판정이 꺼진다 | 반영. 열거 실패는 로컬 후보 없이 등록하고 이전 집합 유지, 빈 성공은 집합을 비움, 경로 조회 실패는 기본 경로 없음. 두 실패는 `WARN`. O9~O11, 로드맵의 실패 주입, ADR 결정 7 과 대안 10 |
| 실패 처리 | warn. 수집 사이에 바뀐 인터페이스가 다음 수집까지 보호받지 못한다 | 일부 반영. 남는 위험으로 적고 회신은 무검증 목적지 공통 예산이 묶는다고 적었다. 승인된 후보와 `peer_endpoint` 는 그 예산 밖이라는 단서도 적었다. 변경 알림으로 다시 모으는 것은 넣지 않았다(ADR 대안 11). 스레드 소유를 v1 에 더하는 대가가 빈틈보다 크다고 보았다 |
| 실패 처리 | warn. prefix 가 범위 밖 값이면 계산이 정의되지 않는다 | 반영. 0 이상 30 이하만 넣는다. 22행 |
| 실패 처리 | warn. "반사와 증폭은 위생이 막는다" 는 2장이 상한만 있다고 한 유니캐스트 반사와 어긋난다 | 반영. 증폭은 막고 유니캐스트 반사는 2장 상한이 건다로 |

## 배운 것

영어 미러에서 다른 문서의 절 이름을 한국어 제목에서 번역해 적었다가 실제 영어 제목과 달라 두 곳을
고쳤다(`control_plane.md` 8.4, `windows-prereq.md` 3절). 영어 미러에서 절 이름을 인용할 때는 영어 파일의
제목 줄을 읽고 옮긴다. 규칙으로 올리지 않은 관찰이다.

수정을 담은 staged diff 에 2차 렌즈(수정 확인, 미러, 새 문장의 모순)를 돌렸다.

| 지적 | 처리 |
|------|------|
| warn. 남는 위험의 회신이 언제나 예산에 묶이는 것은 아니다. 승인된 후보와 `peer_endpoint` 는 9.4 가 예산에서 뺀다 | 반영. 단서를 10.1, ADR 대안 11, 이 기록에 적었다 |
| warn. O9·O10 이 집합을 브로드캐스트 주소로 적어 "주소와 prefix" 정의와 어긋난다 | 반영. `{10.0.0.49/24}` 로 적고 막는 브로드캐스트를 따로 적었다 |
| warn. 이 기록의 한국어가 아직 "반사를 막는다" 로 적었다 | 반영 |
| warn. 이 기록의 "셋 다 `WARN`" 이 10.1 과 어긋난다. 빈 성공에는 `WARN` 이 없다 | 반영. "두 실패는 `WARN`" |

3차 렌즈(2차 수정 확인)에서 warn 하나가 나왔다. 이 기록의 시나리오 추적이 집합을 `10.0.0.255` 로 적었다. 반영했다. `{10.0.0.49/24}` 이고 `10.0.0.255` 를 막는다.
