# Phase 9 의 부하 방법, 짝지은 매핑 거동 표, 대시보드 시점

## 왜 했나

`plan.md` 의 남은 일 가운데 결정 셋을 소유자가 정했다.

- 전체 상한까지의 텔레메트리 부하는 인스턴스 안에서 루프백 출발지 여러 개로 건다
- 실측 환경은 `roadmap.md` Phase 9 테스트 환경 표의 다섯이다. 상대와 일정은 소유자가 잡는다
- 호스트 레코드와 짝지은 매핑 거동 표가 필요하다

CloudWatch 대시보드는 측정값이 생긴 뒤에 만드는 편이 낫다는 소유자 의견으로 시점을 실측 뒤로 옮겼다.

## 중요한 결정

- **짝은 `peer` 가 아니라 방으로 찾는다.** 호스트의 STUN 은 방을 만들 때 한 번이라 한 방의 호스트 값은 하나다(`architecture.md` 6.3). 방으로 찾으면 그 플레이어와의 호스트 `establish` 가 없어도 같은 방의 다른 호스트 레코드로 값을 얻는다. 값이 엇갈리면 단정하지 않고 "불일치" 로 적는다
- **짝지은 표의 분모는 기존 필드별 표와 같다.** `ABORTED` 와 `room_known` 이 `true` 가 아닌 `OK` 는 빠지고 실패는 든다
- **부하 출발지는 루프백이다.** 서버는 연결의 상대 IP(`peername`)로 출발지를 가른다. 비용과 인프라 변경이 없고 배포한 설정을 그대로 쓴다. 부하 프로그램이 같은 인스턴스 자원을 쓰는 것과 망을 지나지 않는 것은 결과와 같이 적는다
