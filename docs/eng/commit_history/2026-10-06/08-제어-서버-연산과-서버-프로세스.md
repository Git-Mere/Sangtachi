# Operations and server process of the control server

## Why

This is the second step of item 1 of "Next to do" in `plan.md`. On top of the store layer (`a0ad5ca`), the
five operations (`ops.Service`) and the server process (accept loop, logs, counters, entry point) were
added. With this, the control server runs end to end on DynamoDB local.

## How the work was split

The director wrote the shared log module `log.py` first and gave the two workers a fixed contract.

| Worker | Assigned |
|--------|----------|
| worker-ops2 | `ops.Service.dispatch` and the five operations, the 7.3 processing order, walking the addresses and redrawing, the 8 skipped rows of `test_host_report.py` |
| worker-server | Accept loop, `MAX_INFLIGHT`, send timeout, linger, `http.request` and counters, `__main__.py` |

The contract has two parts. `Service(store).dispatch(req) -> dict`, and errors are `OpError`. Logs are
emitted only through the allowlist of `log.py`.

## Decided in the documents

The gaps raised by the workers and the review were written in the documents before the code.

| Section | Decided |
|---------|---------|
| 2.2 | The `peer_id` redraw limit is one per request |
| 2.6 | `LINGER_S`, `LINGER_MAX_BYTES`, `MAX_REJECTING` |
| 3.4 | A send timeout closes the connection with no counter. When answering without reading the whole request, the write side is closed first and the server waits while discarding the remaining input (linger) |
| 4.3 | `NONCE#` of a reclaimed peer, a room deleted first by TTL, nonce reuse across operations |
| 4.5 | When the host calls `get_peers`, everyone except itself. The order of elements is not decided |
| 4.6 | The caller's own `peer_id` is skipped. A read failure on re-read is `internal`. `departed` reclamation also deletes `NONCE#`, and a peer in `departed` is not judged again by server reclamation |
| 6.3 | `NONCE#` delete in the reclamation row |
| 7.2 | A dedicated thread pool is set as the default executor. The limit on rejecting connections |
| 7.3 | The time is read once at the start of the request. The point where only the ready time is written |
| 7.5 | `server.started`, levels, `ms` and `op` of `http.request`, the allowlist |
| 7.6 | Port format, exit codes 2 and 1, startup failure wording, shutdown procedure |

**One decision changed code.** When the host reclaimed via `departed`, it did not delete `NONCE#`, so if
the reclaimed peer came back with the same nonce, `internal` repeated. It now deletes it like server
reclamation does, so that it becomes a new join.

## RST reproduced on Windows

worker-server found it. If the server sends `503` or `413` without reading the whole request and closes
right away, the OS sends an RST because of bytes that arrive late, and the client gets `WinError 10053`
before reading the response. Without linger, each response was sent 20 times and all 20 were lost. After adding linger,
all 20 were received.

## End to end

`python -m controlplane` was started on DynamoDB local and the five operations were called in turn with
`curl`.

- Room created `10.100.0.1`, joined with a lowercase room code `10.100.0.2`, a retry with the same nonce
  gives the same response
- A loopback candidate is rejected by sanitation. Before confirm, `get_peers` is `ready: false`. After
  confirm, one `pair.ready` line and the candidates
- Wrong token `403`, missing room `404`, after `departed` reclamation the old nonce is a new join
- The server log was scanned for the room code, the two tokens and the two nonces: 0 hits

During this check, the director's table creation script left out `endpoint_url`, so a request with fake
credentials almost went to real AWS. It stopped before the request because it could not find a region. A
warning was written in the README.

## Cross-model review

Codex. Lenses were paired. There were eleven rounds.

| Round | Lenses | Result | Handling |
|-------|--------|--------|----------|
| b1 | spec-conformance + scenario-trace of ops | warn 1. If the same peer is put in both `departed` and `confirm` and its `client_nonce` cannot be read, it ends in `internal` after reclamation and cannot renew | Accepted. A peer handled in step 2 is skipped in step 3 |
| b2 | spec-conformance + security of server | blocker 1, warn 2. Shutdown waits for in-progress `boto3` calls. A malformed endpoint gives exit code 1. There is no limit on the number of rejected connections | Accepted. Dedicated pool and `os._exit`, format check, `MAX_REJECTING` |
| b3 | test-strength + flakiness | warn 13. Token comparison, time within a request, nonce reuse, redraw budget, reclamation order, overlap of concurrent tests, time dependence of the linger and send tests, port races | Accepted. Deterministic tests and stress tests were split, and mutation kills apply only to deterministic tests |
| b4 | documents consistency + readability | warn 1, nit 5 | The warn and nit 2 accepted. README nit 3 rejected. The readability rules target the eight living documents, and the README is not one of them |
| b5 | repair + security | blocker 1, warn 1. An endpoint with broken brackets puts the value into the traceback. If a stored `peer_id` is a list, it blows up before reclamation | Accepted |
| b6 | repair + security | warn 2. A backslash host and a bad region carry the value | Accepted. Host and region allowlists, every exception from client creation turned into fixed wording |
| b7 | repair + spec | blocker 1. If the port is in use, a traceback containing the port value | Accepted. The whole startup made the boundary. Exit code 1 and the error names in 7.6 |
| b8 | repair + security | warn 3. The `Store` import is outside the boundary. 7.6 wrote only one naming rule | Accepted |
| b9 | repair + security | warn 2. The top-of-module import draws the random value of `clock.py` outside the boundary | Accepted. Only the standard library at the top of `__main__.py` |
| b10 | repair | `none` | - |
| b11 | record + consistency | warn 4. The test count missed the one time limit test. The mutation count, time and limit description in the README were stale | Accepted |

**The same type of finding came up five times, from b5 to b9.** It is the path where an error during startup
prints a config value. Each time only the one place pointed out was blocked. b6 instructed "block the whole
type", but the scope went only as far as client creation. Wrapping the whole startup in the boundary came in
b7, and wrapping the imports too came in b9. If the goal from the start had been "no line runs outside the
boundary from entering main to listening", it would have ended in one round.
