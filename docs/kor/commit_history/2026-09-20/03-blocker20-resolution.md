## 결정 1 — 대비책을 도입하지 않는다

`plan.md` 5장의 선택지 A(NAT 에뮬레이션), B(릴레이 P1 승격), C(핫스팟 필수화)를 **전부
기각**하고 M-1/M-4를 현재 문구 그대로 유지한다. 세 안 모두 "성공 기준을 함께 개정해야 한다"는
대가가 있었는데, 실측이 기준을 만족시켰으므로 그 대가를 치를 이유가 사라졌다.

**개정 불필요도 결정이므로 근거를 남겼다.** 기준을 고치면 실제로 달성한 것보다 약한 주장을
하게 된다.

받아들인 위험 네 가지를 ADR에 적었다. 그중 둘이 중요하다.

- **세 조건(NAT↔NAT + 다른 ISP + Windows↔Windows)을 한 측정 안에서 동시에 만족한 적이 없다.**
  조합으로는 덮였지만 단일 측정으로 증명한 것은 아니다
- **대비책의 대비책이 없다.** 시연 당일 조건이 바뀌면 남는 것이 없다. 그래서 Phase 8 준비
  절차에 시연 직전 재측정을 넣었다

## 결정 2 — 리바인딩 복구를 보장하지 않는다

**예상하지 않았던 발견이다.** 09-20 측정에서 Windows 방화벽 프롬프트가 뜨지 않았는데도
인바운드가 전부 들어온 것을 조사하다 드러났다.

인바운드 기본 동작이 `Block`이고 `python.exe` 규칙도 없는데 펀치는 성립했다. **상태 기반
UDP** 로 설명된다. 우리가 먼저 보냈으므로 응답이 요청된 트래픽으로 분류됐다는 것이다.
다른 설명을 배제하지는 않았다. 그래서
**보낸 적 없는 출발지 포트에서 오는 패킷**이 시험되지 않은 채 남아 있었다.

`--unsolicited` 시험을 만들어 세 쌍에서 재봤다. **6건 전부 `blocked`다.**

| 호스트 OS | 호스트 방화벽 | 결과 |
|-----------|---------------|------|
| Windows 11 | 인바운드 기본 `Block`, `python.exe` 규칙 없음 | `blocked` |
| macOS | Application Firewall 기본 꺼짐 | `blocked` |
| Linux | `/etc/ufw/ufw.conf` 가 `ENABLED=no` (직접 확인) | `blocked` |

**호스트 방화벽 필터링이 없다고 보이는 기기에서도 막혔으므로 원인은 NAT의 포트 제한
필터링일 가능성이 가장 높다.** macOS는 기본값 추론, Linux는 `ufw` 만 확인이라 단정하지 않는다. 어느 쪽이든
클라이언트가 고칠 수 없으므로 결정은 같다.

이것이 `protocol.md` 10.4 (c) 경로 검증의 전제를 깬다. 절차가 "후보 집합에 없는 주소에서
패킷이 오면"으로 시작하는데 그 패킷이 도착하지 않는다. 10.4가 지명 대신 학습을 고른 세 이유 중
**NAT 리바인딩 복구 하나가 실측으로 무효가 됐다.**

**(c)를 삭제하지는 않았다.** 같은 NAT 뒤 헤어핀과 후보 집합 안에서의 전환에 여전히 필요하고,
위조 출발지 방어라는 보안 역할이 남는다. 주소 제한 필터링을 쓰는 NAT에서는 정상 동작할 수도
있다. **"보장하지 않는다"이지 "불가능하다"가 아니다.**

**클라이언트가 방화벽 규칙을 등록하지 않기로 했다. 잠정 결정이다.** 원인이 NAT일 가능성이
높아 효과가 없다. 덕분에 관리자 권한 요구사항이 생기지 않았고 `spec.md`의 "수동 포트 포워딩
없이" 주장이 유지된다. **이 발견이 없었다면 없는 요구사항을 설계에 넣을 뻔했다.**

다만 **우리 Windows가 받는 방향에서는 방화벽이 원인일 가능성이 배제되지 않았다.** 상대가
macOS/Linux인 방향만 NAT으로 좁혀졌다. ADR 0002에 재검토 조건을 적었다. Windows 한 대에서
범위를 좁힌 임시 인바운드 허용 규칙을 넣고 `--unsolicited` 를 다시 돌리면 갈린다.

## 실측 원본을 커밋하지 않는다

`tools/nat-probe/results/` 와 `records/` 를 `.gitignore` 에 넣었다. 이 레포는 public이고
JSON과 기록에 두 가정의 공인 IP와 분 단위 시각이 들어 있다. 친구 집 IP를 공개 레포에 올리는
것은 되돌릴 수 없고 본인 동의도 없다.

첨부는 원본 그대로 하지 않는다. 제출 시스템과 공유 링크에도 같은 노출이 생긴다. **공인 주소는 되돌릴 수 없는 가명(`망 A`, `망 B`)으로 바꾸고 시각은 날짜 단위까지만 남긴다.** IPv4 마지막 옥텟만 가리는 것으로는 부족하고 IPv6에도 적용되지 않는다. 그렇게 하지 않으려면 당사자 동의를 명시적으로 받는다. 어느 쪽을 택했는지 보고서에 적는다.

**대가:** 기기를 옮기면 원본이 따라가지 않는다. 판정과 근거는 `plan.md` 5.7~5.9와 ADR 2건에
남으므로 결론 자체는 유실되지 않는다.

**`.gitignore` 만으로는 부족하다.** 이미 추적 중이거나 이력에 들어간 사본은 무시 규칙이
보호하지 못한다. 확인했다.

```
git log --all --diff-filter=A --name-only --format='' | grep -E 'results/|records/|\.json$'
  -> tools/nat-probe/records/.gitkeep
     tools/nat-probe/results/.gitkeep
```

**측정 파일은 git 이력에 한 번도 들어간 적이 없다.** 추적 중인 것도 `.gitkeep` 두 개뿐이다.
