# 0035. Linux 콘솔 클라이언트를 만든다

- 상태: 채택
- 날짜: 2026-10-31
- 관련: [`../spec.md`](../spec.md) C-1·C-2·범위, [`../architecture.md`](../architecture.md) 7장·10장·12장, [`../concurrency.md`](../concurrency.md) 2장·4장·7장, [`../protocol.md`](../protocol.md) 6장, [`../linux-prereq.md`](../linux-prereq.md), [ADR 0010](0010-플랫폼-이식-이음새.md)

## 맥락

Phase 8 의 두 기기 실측은 상대 기기를 가진 사람의 시간에 묶여 있다. 저장소 소유자에게 Ubuntu 기기가 하나 더 있다.
그 기기에서 클라이언트가 돌면 Windows 기기와 Linux 기기 둘로 소유자 혼자 실측할 수 있다.

[ADR 0010](0010-플랫폼-이식-이음새.md) 은 "이식하지 않는다. 이음새만 고정한다" 로 정했다. 그 결정 덕분에 다시 쓸 자리가
`client/src/platform/` 하나다. 플랫폼 밖의 클라이언트 원본은 g++ 13 에서 컴파일 검사를 통과했다. 오류는 0건이고
경고는 쓰지 않는 변수 하나였다.

## 결정

**Ubuntu x64 콘솔 클라이언트를 만든다. 가상 어댑터를 포함한다.** ADR 0010 의 "이식하지 않는다" 를 Linux 콘솔
클라이언트에 한해 뒤집는다. 이음새 다섯과 OS 헤더 배치 규칙은 그대로다.

**1. 범위.** 대상은 Ubuntu 24.04 이상 x64, 컴파일러는 g++ 13 이상이다. 콘솔 실행 파일 `sangtachi_client` 하나다.
GUI 와 배포물 패키징은 Windows 만이다. macOS 는 범위 밖이고 따로 정한다. 와이어 프로토콜과 제어 평면 계약은 OS 와
무관하므로 Windows 클라이언트와 Linux 클라이언트가 한 방에 섞인다.

**2. 배치.** POSIX 공통 원본은 `client/src/platform/posix/`, Linux 전용 원본은 `client/src/platform/linux/` 에 둔다.
나중에 macOS 를 넣을 때 다시 쓰는 자리를 줄이기 위해서다.

| 자리 | 원본 |
|------|------|
| `posix/` | 대기, UDP 소켓, TCP, 이름 해석, 난수, 표준 출력, 기록 파일, 종료 신호, Winsock 자리의 빈 구현, 세션 종료, SHA-256 |
| `linux/` | 단조 시계, 실행 파일 경로, 인터페이스와 기본 경로 조회, TUN 장치와 주소·경로, 권한 확인, 서브넷 충돌 검사 |

**3. 공개 헤더의 타입은 바꾸지 않는다.** `void*` 핸들에 파일 기술자를 담는다. ADR 0010 결정 3이 남긴 "중립 타입은 두 번째
구현을 쓸 때 정한다" 는 이 결정으로 "지금 타입을 유지한다" 로 정한다. 바꾸는 공개 선언은 둘이다.

- 실행 파일 옆에 둘 파일 목록 `kAdapterFiles` 를 플랫폼이 정의하는 함수로 바꾼다. Linux 는 빈 목록이다
- 방화벽 판정에 "검사하지 않았다" 를 더한다. 로그 값은 `adapter.firewall verdict=skipped` 다

**4. 대기는 파이프와 `poll` 이다.** 이벤트 하나가 논블로킹 파이프 한 쌍이다. 자동 리셋 이벤트는 대기가 깨운 것 하나만 파이프를
비워 소비하고, 수동 리셋 이벤트는 비우지 않는다. 여럿이 준비되면 가장 낮은 인덱스를 돌려준다. 이렇게 Windows 의 대기 의미를
그대로 재현한다. 규칙의 출처는 [`concurrency.md`](../concurrency.md) 2장이다. `eventfd` 를 쓰지 않는 이유는 macOS 에 없기 때문이다.

**5. 종료 신호는 신호 대기 스레드가 받는다.** `SIGINT`, `SIGQUIT`, `SIGHUP`, `SIGTERM` 을 모든 스레드에서 막고 전용 스레드가
`sigwaitinfo` 로 받는다. 신호 처리기 안에서 정리를 기다리면 그 신호가 배달된 `[loop]` 스레드가 멈춘다. 대응표는
`concurrency.md` 7장이 갖는다.

**6. 서브넷 충돌 검사는 C++ 로 한다.** Windows 의 `Test-SubnetOverlap.ps1` 과 같은 판정표를 netlink 로 읽은 main 경로 표와 IPv4
주소에 적용한다. 판정표는 [`linux-prereq.md`](../linux-prereq.md) 가 갖는다. TUN 장치는 비영구라 프로세스가 끝나면 사라지므로 자기
어댑터를 제외하는 단계가 없다.

**7. 방화벽은 클라이언트가 만지지 않는다.** 배포판마다 방화벽 도구가 다르다(ufw, firewalld, nftables). 호스트가 받아야 하는 인바운드는
사람이 연다. 절차는 `linux-prereq.md` 가 갖는다.

**8. SHA-256 은 직접 구현한다.** Linux 제품 경로는 해시를 쓰지 않는다. 시험 빌드의 `data.tx`, `data.rx` 만 쓴다. 서드파티를
들이면 [`spec.md`](../spec.md) NFR-5 승인이 필요하다. FIPS 180-4 구현은 150줄 안쪽이고 시험 벡터로 확인한다.

**9. 시험 범위.** 공용 코드의 시험은 Windows 에서 통과한 것으로 본다. Linux 에서는 새로 쓴 플랫폼 원본의 시험과 이식 없이
컴파일되는 플랫폼 시험만 돈다. 저장소 소유자의 결정이다. 공용 코드를 Linux 에서 다시 시험하는 비용보다 두 기기 실측을 앞당기는
이득이 크다고 봤다.

**10. 로그 토큰은 그대로 둔다.** 플랫폼 밖 코드가 내는 `op=WaitForMultipleObjects` 같은 토큰은 Linux 에서도 같은 문자열이다.
토큰은 실패한 단계를 가리키는 이름이다. 바꾸려면 플랫폼이 토큰을 돌려주는 모양이 필요하고 Windows 의 출력이 바뀐다.
플랫폼 원본이 직접 내는 토큰은 실제 호출 이름(`poll`, `recvfrom`, `TUNSETIFF` 등)이다.

## 대안

**대안 1. 이식하지 않고 실측 상대를 기다린다.**
버렸다. 실측 일정이 상대의 시간에 묶인다. 이 결정의 이유가 그것이다.

**대안 2. 공용 코드 시험까지 Linux 에서 다 돈다.**
버렸다. 시험 도우미 일부가 Winsock 을 직접 쓰고 시험 진입점이 PowerShell 이다. 얻는 것은 컴파일러 차이로 생길 결함을 잡는
것이고, 치르는 것은 시험 기반 이식이다. 결정 9의 대가로 남는다.

**대안 3. `eventfd` 와 `epoll` 을 쓴다.**
버렸다. Linux 만 보면 더 간단하다. 대가는 macOS 를 넣을 때 대기를 다시 쓰는 것이다. 이벤트 수는 다섯 이하라 `poll` 의 비용은 문제가 아니다.

**대안 4. 방화벽을 클라이언트가 연다.**
버렸다. ufw, firewalld, nftables 를 각각 다뤄야 하고 기계 전체의 정책을 바꾼다. 실측 기기 하나를 위해 들일 일이 아니다.

## 결과

**얻는 것.**

- 소유자 혼자 Windows 기기와 Linux 기기로 두 기기 실측을 할 수 있다
- Windows 와 Linux 가 한 방에 섞이므로 `spec.md` 스트레치의 "Linux 상호 운용성" 을 콘솔에 한해 채운다
- macOS 를 넣을 때 다시 쓸 자리는 `linux/` 의 어댑터와 경로 조회, 시계, 실행 파일 경로다

**치르는 것.**

- 공용 코드는 Linux 에서 시험하지 않는다. g++ 에서만 드러나는 결함은 실측에서 처음 보인다
- 방화벽 검사가 없다. 호스트가 인바운드를 열지 않으면 Minecraft 접속이 막히고 클라이언트는 그것을 알리지 않는다
- 로그 토큰 일부가 Windows API 이름이다. Linux 로그를 읽는 사람은 그 이름을 단계 이름으로 읽어야 한다
- `--no-adapter` 없이 띄우려면 root 또는 `CAP_NET_ADMIN` 이 필요하다
