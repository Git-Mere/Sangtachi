## 가정망 대 가정망 묶음의 끝을 고쳤다

[같은 날 앞 기록](01-phase-9-가정망-대-가정망-다시-재기와-분석.md)은 가정망 대 가정망 묶음의 끝을 시행 스크립트가 끝난 때로 적었다. 친구 호스트의 마지막 `end` 는 그 몇 초 뒤에 왔다. 분석 도구는 마지막 묶음의 끝 뒤에 온 레코드를 읽지 않으므로 그 레코드 하나가 빠졌다. 그림 1 을 그리며 CloudWatch `Rtt` 표본 수(120)와 분석 도구의 RTT 표본 수(114)를 맞춰 보다 찾았다.

묶음 끝을 늦추고 소유자가 CloudShell 에서 `--save` 를 다시 돌렸다. 레코드가 461개로 하나 늘었다. 이 PC 에서 `--load` 로 다시 낸 출력은 줄 끝 말고 같았다.

| 값 | 앞 기록 | 고친 뒤 |
|----|---------|---------|
| 가정망 대 가정망 RTT | 25.8ms (18.7~57.7), n=114 | 25.3ms (18.7~57.4), n=120 |
| 가정망 대 가정망 지터 | 7.8ms (6.2~15.5), n=19 | 7.7ms (6.2~15.0), n=20 |
| 가정망 대 가정망 손실 | 0/315 | 0/330 |
| 실제 환경 합산 RTT | 27.9ms, n=572 | 27.7ms, n=578 |
| 실제 환경 합산 지터 | 6.6ms, n=97 | 6.6ms, n=98 |
| 실제 환경 합산 손실 | 1/1582 | 1/1597 |

리포트의 나머지 줄은 같다. 고친 뒤 네 실제 환경의 RTT 표본 수가 CloudWatch 의 묶음별 `Rtt` 표본 수와 같다.

## 그래프 도구

- 그림 1 은 CloudWatch `Rtt` 의 분마다 중앙값과 사분위수다. 1분 구간의 시각은 그 구간의 시작이라 묶음과 겹치는 구간을 모두 넣는다. 처음에는 묶음 시작 뒤의 구간만 넣어 첫 구간이 빠졌다
- 그림 2, 3 은 `tmanalysis` 의 `assign`, `summarize`, `wilson` 을 그대로 쓴다. 표의 숫자와 같은 값이다
- 같은 입력으로 두 번 그려 PNG 가 바이트 단위로 같았다. PNG 메타데이터는 matplotlib 버전과 dpi 뿐이다
- 처음에 `uv pip install matplotlib` 이 `VIRTUAL_ENV` 를 따라 `control-server/.venv` 에 설치됐다. 지웠고 `uv pip check` 와 제어 서버 시험(747 passed, 290 skipped)을 다시 돌았다. 도구는 `uv run --no-project --with matplotlib` 로 돈다

## 결정한 것

- 이번 가정망 대 가정망의 상대는 `experiments.md` 의 기기 F, 망 W 로 적었다. 친구에게 준 `host.cmd` 의 이름이 `F_host` 다
- 이번 가정망 대 가정망에서 A 의 망은 H 로 적었다. 시행 스크립트가 적은 A 의 공인 주소가 2026-11-19 동일 LAN 묶음의 A, G 공인 주소와 같다. 앞 기록에서 확인하지 못했다고 한 것을 이것으로 확인했다
- ADR 0005 에서 교수가 받아들인 것은 시험 실행기의 구분이다. 분석 도구를 같은 종류에 넣는 것은 저장소 소유자의 판단으로 ADR 0042 에 적었다

## 크로스 모델 리뷰

Codex(`gpt-6.1-sol`) 둘을 따로 돌렸다. 문서 리뷰는 원시 출력과 숫자 대조(A), 한영 일치(B), 살아 있는 문서끼리의 일치(C), 공개 레포 노출(D) 렌즈다. 원시 출력은 커밋하지 않는 로컬 파일로 넘겼다. 코드 리뷰는 `tools/tm-plot` 의 그린 값, 빈 자료, 시각 노출, README 명령을 봤다.
