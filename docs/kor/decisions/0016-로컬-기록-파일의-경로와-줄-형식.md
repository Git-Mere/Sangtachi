# 0016. 로컬 기록 파일의 경로와 줄 형식

- 상태: 채택
- 날짜: 2026-10-07
- 관련: [`../architecture.md`](../architecture.md) 9장, [`../spec.md`](../spec.md) M-6·FR-13·FR-16, [`../concurrency.md`](../concurrency.md) 5장·7장, [`../windows-prereq.md`](../windows-prereq.md) 4절, [`../roadmap.md`](../roadmap.md) Phase 4, [ADR 0015](0015-멤버를-표시-이름으로-가리킨다.md)

## 맥락

`architecture.md` 9장은 로컬 기록 파일의 계약 넷(내용, 시점, 추가 전용, 독립성)과 두 종류의
줄(수립 줄, 종료 줄)만 정했다. 경로와 줄 형식, 빈 값의 표기, 한 시도의 두 줄을 묶는 방법은 정하지
않았다. 그래서 `spec.md` M-6 은 "지금은 판정할 수 없다" 였다. `roadmap.md` Phase 4 는 이것을 착수
전 결정으로 두었고, `leave` 로 중단한 시도를 어떻게 적는지도 같이 정하라고 했다.

## 결정

저장소 소유자가 아래를 정했다.

**1. 경로는 실행 파일 폴더 아래 `records\` 다.** 경로를 바꾸는 기동 인자는 두지 않는다.

**2. 프로세스마다 새 파일을 만든다.** 이름은 `<UTC 기동 시각>-<PID>.log` 다. 지우거나 돌려쓰지
않는다.

**3. 줄은 `<이름>=<값>` 쌍을 공백으로 이은 것이다.** 필드 아홉의 순서를 고정하고 형식 버전 `v`
를 둔다. 빈 값은 `-` 다.

**4. 필드는 `v`, `kind`, `ts`, `attempt`, `role`, `peer`, `result`, `rtt_us`, `setup_ms` 다.** RTT
는 마이크로초 정수다. 표시 이름은 넣지 않는다. 수립 시간 `setup_ms` 를 더한다. 9장의 내용 계약이
그만큼 넓어진다.

**5. 시도는 세션 하나, 또는 세션이 생기기 전에 끝난 참가나 방 만들기 하나다.** 호스트의 쌍은
따로 센다. 방을 만들고 아무도 오지 않은 호스트는 줄이 없다.

**6. `CONNECTED` 에 닿기 전에 그만둔 시도는 `result=ABORTED` 수립 줄이다.** 이쪽의 `leave` 나 종료
이벤트, 또는 상대의 `CLOSE`(`reason` `0x00`·`0x01`)가 계기다. 상대의 `CLOSE` 가 실패(`0x02`·`0x03`)를
알리면 `PEER_FAILED` 다. 수립 줄과 종료 줄 둘 다 그렇다.

**7. 기동 때 파일을 열지 못하면 기동 실패다.** 실행 중 쓰기 실패는 `WARN` 과 카운터
`record_write_failed` 이고 터널은 유지한다. 그 뒤로는 그 파일에 쓰지 않는다. 줄마다 OS 에 바로 쓰고
디스크 캐시는 비우지 않는다.

**8. 줄 수 판정은 종료 절차를 끝까지 돌았고 쓰기 실패가 없는 실행에만 한다.** 그 밖은 판정 불가다.

## 대안

**대안 1. `%LOCALAPPDATA%` 아래 기본 경로와 `--record-dir` 인자.**
버렸다. 실행 파일 폴더에 쓸 수 없는 배치에서도 돈다는 장점이 있다. 저장소 소유자는 찾기 쉬운 쪽을
골랐다. 대가는 [`windows-prereq.md`](../windows-prereq.md) 4절의 쓰기 전제다.

**대안 2. 현재 작업 폴더.**
버렸다. 어디서 실행했느냐에 따라 기록이 흩어진다.

**대안 3. 모든 프로세스가 파일 하나를 나눠 쓴다.**
버렸다. 한 기기에서 여러 프로세스를 띄우는 시험이 있고, 동시 추가가 섞이지 않는다는 보장을
확인하지 않았다.

**대안 4. TSV.**
버렸다. pandas 로 바로 읽힌다. 대가는 열 순서에 기대는 것이라 필드를 늘릴 때 깨지기 쉽다.

**대안 5. JSON Lines.**
버렸다. 자기 설명적이다. 대가는 C++ 쪽 JSON 쓰기 코드이고, 라이브러리를 쓰면 `spec.md` NFR-5
승인 대상이다.

**대안 6. RTT 를 밀리초 정수로 적는다.**
버렸다. 같은 LAN 의 RTT 가 0 이 되어 "없는 값을 0 으로 적지 않는다" 와 섞인다.

**대안 7. 중단한 시도는 적지 않는다.**
버렸다. "모든 시도에 수립 줄" 에 예외가 생기고 중단이 기록에서 사라진다.

**대안 8. 중단을 실패 코드 하나로 적는다.**
버렸다. 사람이 그만둔 것이 NAT 실패로 집계된다.

**대안 9. 파일을 열지 못해도 돌고 `WARN` 만 남긴다.**
버렸다. 그 실행은 M-6 으로 판정할 수 없는데 그것을 늦게 안다.

**대안 10. 상대의 `CLOSE` 는 `reason` 과 무관하게 `ABORTED` 로 적는다.**
버렸다. 값이 하나 준다. 대가는 `protocol.md` 5.6 이 Phase 9 를 위해 나눈 "사람이 껐다" 와 "실패했다" 가
이 파일에서 합쳐지는 것이다.

## 결과

**얻는 것.**

- M-6 을 판정할 수 있다. 줄 수와 필드로 기계가 센다
- Phase 9 가 두 기기의 기록을 UTC 시각과 `peer_id` 로 맞출 수 있다

**치르는 것.**

- 실행 파일 폴더에 쓸 수 있어야 한다. 관리자 권한 없이 `Program Files` 아래에서 돌리면 기동 실패다
- 기록 파일이 쌓이고 지우는 것은 사람의 몫이다
- 호스트와 플레이어의 `setup_ms` 기점이 달라 두 값을 서로 비교하지 않는다
- 줄을 쓰는 동안 `[loop]` 가 잠깐 멈춘다. 시도 하나에 두 줄이라 작다고 보고 재지 않았다
