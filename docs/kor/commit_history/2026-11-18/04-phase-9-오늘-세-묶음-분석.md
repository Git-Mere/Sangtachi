# Phase 9 오늘 세 묶음의 분석

## 왜 했나

오늘 잰 캠퍼스망 대 가정망, 가정망 대 가정망, 에뮬레이션한 목적지 의존 매핑 세 묶음을 분석 도구로 냈다. 소유자가 AWS CloudShell 에서 `tools/tm-analysis` 를 `--save` 로 돌려 결과를 넘겼다. 이 PC 와 인스턴스 역할은 텔레메트리 테이블을 읽지 못한다.

## 무엇을 했나

| 무엇 | 결과 |
|------|------|
| 분석 도구 | 레코드 196개, 묶음 일곱. 이 PC 에서 `--load` 로 같은 레코드를 다시 돌려 출력이 줄 끝(CRLF) 말고는 같았다 |
| 어느 묶음에도 들지 않은 시도 9개 | 모두 묶음 밖에서 한 확인이다. 학교 유선 LAN 의 첫 참가 1(플레이어만), 한 호스트에 두 번 참가한 확인 4, 멈춘 에뮬레이션 두 시행 4 |
| CloudWatch 1분 해상도 값 | 지표 열 개를 오늘 세 묶음을 덮는 범위로 받아 git 이 무시하는 `tools/tm-analysis/local/cw-2026-11-18-1min.json` 에 두었다. `Attempts` 합 35 는 그 범위의 묶음 세 개(30)와 묶음 밖 플레이어 시도(5)의 합이다 |

CloudWatch 값을 받으려던 SSH 가 학교 유선 LAN 에서 다른 호스트 키를 받았다. [이슈 0008](../../issue_history/0008-학교-유선-lan-에서-ssh-호스트-키가-달랐다.md) 이다. `mere-galaxy` 를 거쳐 받았다.

## 분석 결과

| 환경 | 종류 | 성공/시도 | 플레이어 수립 시간 중앙값 | 호스트 수립 시간 중앙값 | RTT 중앙값 (사분위 범위) | 지터 중앙값 | 손실 |
|------|------|-----------|---------------------------|-------------------------|--------------------------|-------------|------|
| 캠퍼스망 대 가정망 | 실제 | 10/10, Wilson 95% 72.2~100.0% | 10859.0ms | 6200.5ms | 21.2ms (17.8~28.7), n=115 | 2.3ms | 8/355 (2.25%) |
| 가정망 대 가정망 | 실제 | 10/10, Wilson 95% 72.2~100.0% | 9206.5ms | 6187.5ms | 20.8ms (17.3~26.6), n=120 | 2.6ms | 8/363 (2.20%) |
| 실제 환경 합산(묶음 넷) | 실제 | 40/40, Wilson 95% 91.2~100.0% | 10476.5ms | 6198.0ms | 21.9ms (15.6~80.8), n=471 | 2.7ms | 24/1427 (1.68%) |
| 에뮬레이션한 목적지 의존 매핑 | 통제 | 0/10, Wilson 95% 0.0~27.8% | - | - | - | - | - |

- 짝지은 매핑 표에서 실제 환경 넷은 모두 플레이어와 같은 방 호스트의 `stun_same_endpoint` 가 `true` 다. 에뮬레이션은 플레이어 `false`, 호스트 `true` 이고 0/10 이다
- 가정망 대 가정망의 플레이어 수립 시간(9206.5ms)은 다른 실제 환경 셋(10250.5~10859.0ms)보다 짧다. 그 묶음만 호스트를 계속 두었다. 호스트 수립 시간은 넷 모두 약 6.2초다
- 손실이 동일 LAN 은 0 이고, 나머지 실제 환경 셋은 모두 8 이다. 기대 수가 비슷한 묶음에서 같은 수가 나온 까닭은 보지 않았다
- 분석 도구의 `controlled` 절 제목은 "통제된 실패 (실패 처리 경로의 증거. 실패율이 아니다)" 다. 그 절에 에뮬레이션도 든다. `experiments.md` 에 실을 때 에뮬레이션은 통제된 실패와 따로 적는다(ADR 0040)
