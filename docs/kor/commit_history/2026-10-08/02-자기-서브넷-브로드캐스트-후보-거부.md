# 받은 후보에서 자기 서브넷 브로드캐스트를 거부한다 (ADR 0018)

## 왜 했나

ADR 0017 리뷰 중에 찾았다. 수신 후보 위생이 브로드캐스트를 `255.255.255.255` 하나로만 판정해서, 상대나
악의적 서버가 우리 LAN 의 directed broadcast 를 후보로 넣으면 펀치 동안 `HELLO` 가 우리 LAN 전체로 나갔다.
ADR 0017 로 자기 서브넷 집합이 생겨 판정할 입력이 있다. 저장소 소유자가 지금 규칙에 넣으라고 정했다.

## 중요한 결정

- **서버는 이 행을 적용하지 않는다.** 서버에는 집합이 없고, prefix 를 서버에 보내지 않는 10.1 의 이유는 그대로다
- **클라이언트 코드는 지금 고치지 않는다.** 판정 입력인 자기 서브넷 집합이 Phase 4 의 로컬 후보 수집에서
  생긴다. `plan.md` 구현 때 같이 볼 자리에 적었다

## 검증

| 무엇 | 결과 |
|------|------|
| 케이스 표 | 규칙을 옮긴 스크립트로 5행을 계산해 문서 값과 맞췄다 |
| 변이 | 행 없음, 서브넷 전체 거부, 넷마스크를 넓게 잡음, 마지막 옥텟 255 거부. 넷 모두 한 행 이상에서 걸렸다 |
| 시나리오 추적 | 플레이어가 `192.168.0.10/24` 에서 등록하고, `get_peers` 응답에 상대 후보 `192.168.0.255:5000` 과 반사 후보가 온다. 8.4 의 8번 위생에서 앞의 것이 거부되고 `HELLO` 는 반사 후보로만 나간다. 서버는 그 후보를 저장했다 |
| 문서 게이트 | `docgate.py` `VERDICT: pass` |
