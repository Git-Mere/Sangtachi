## 결정

**점검을 diff가 아니라 문서 전문 대상으로 했다.** 메커니즘, 플랫폼, 성립성 세 렌즈를
독립적으로 병렬 수행했다. 그때까지의 diff 리뷰는 국소 결함만 잡고 있었다.

**근본 원인 두 가지를 기록했다.**

1. 시나리오를 끝에서 끝까지 추적한 적이 없다. 컴포넌트 목록과 검증 항목만으로는
   구멍이 보이지 않는다.
2. 이전 라운드에서 지적을 국소적으로 반영하다 새 모순과 달성 불가능한 기준을 만들었다.
   **과하게 조인 검증 기준은 느슨한 기준만큼 나쁘다.**

**헤더를 16바이트에서 20바이트로 늘렸다.** `session_epoch`를 추가했다. 없으면 재시작 후
이전 인스턴스의 지연 패킷이 새 세션에 수용된다. 4바이트 필드를 모두 4의 배수 오프셋에
배치해 MSVC 기본 정렬에서도 패딩이 생기지 않게 했지만, 그래도 필드 단위 직렬화를 강제한다.
정렬이 우연히 맞는 것에 의존하면 조용히 깨진다.

**Phase 4가 프로토콜을 설계하지 않는다.** 와이어 프로토콜 미확정이 구현 불가 수준의
blocker로 드러나서, `protocol.md`를 구현 착수 전에 확정본으로 썼다. 구현 중 빠진 값이
발견되면 코드에서 임의로 정하지 않고 `protocol.md`를 먼저 고친다.

**지명 방식을 엔드포인트 학습으로 대체했다.** ICE식 후보 지명은 같은 NAT 뒤의 두 피어가
각각 LAN 경로와 헤어핀 공인 경로를 지명하면 서로의 패킷을 전부 걸러내 교착한다.
WireGuard식 학습은 이 경우와 NAT 리바인딩 회복을 모두 처리한다.

실제로 위험했던 결함:

| 결함 | 수정 |
|------|------|
| 재협상 시 양쪽이 각자 로컬 epoch를 새로 뽑아 **무한 epoch 핑퐁**. 두 피어가 영원히 연결되지 않는다 | 로컬 epoch/nonce 유지. `IDLE`에서 새 시도를 시작할 때만 변경 (9.5) |

| 후보 지명 방식이 같은 NAT 뒤에서 교착 | 엔드포인트 학습으로 대체 (10.4) |
| `is_newer(a,b)`가 `a == b`에서 참을 반환해 중복이 새 패킷으로 분류됨 | `a != b` 조건 추가 (4.4) |
| 출발지를 위조하면 게임 트래픽 전체를 임의의 피해자에게 돌릴 수 있어 2장의 제3자 피해 차단 약속과 모순 | 후보 집합 밖 주소는 nonce 경로 검증 통과 후에만 전환 (10.4 c) |
| 분류 단계가 magic을 보므로 `drop_magic`/`drop_version`이 영원히 0이고 악성 트래픽이 `drop_unclassified`에 숨음 | 상위 2비트 기준 분류로 변경, magic은 검증 단계로 이동 (7장) |
| 비트맵 `shift == 64`에서 비트맵을 지워 직전 `highest`가 중복인데도 재수용 | `shift > 64`일 때만 지우고 `shift == 64`는 비트 63을 세움 |
| `seq == highest`가 "오래됨" 분기로 내려가 `uint64_t{1} << (0-1)` 미정의 동작 | 명시적 중복 판정을 먼저 배치 |

**위 8건은 전부 구현 착수 전에 문서화됐다.** 중복 억제 부재와 지명 교착은 Phase 4에서
드러났다면 "가끔 연결이 안 된다" 형태로 나타나 재현조차 어려웠을 것이다.
