## 결정

**도구의 출처는 도구 자신이다.** nat-probe README 에서 뺀 것은 JSON 스키마 전문, 긴 실행
절차, 기록 작성 절차다. 각각 `natprobe.py` 의 주석과 `--help`, `RECORD-TEMPLATE.md` 가
갖는다. README 는 그쪽을 가리킨다.

**줄이면서 지켜야 할 것은 "이걸 모르면 틀린 측정을 맞다고 믿게 되는 문장" 이다.** 분량이
아니라 그 기준으로 남긴다.

## 이번 작업의 실패

**처음 90줄까지 줄이면서 안전·유효성 경고 네 종류를 떨어뜨렸다.** 크로스 모델 리뷰가
라운드마다 하나씩 찾아냈다.

| 라운드 | 떨어뜨린 것 | 그대로 뒀다면 |
|:--:|-------------|---------------|
| 1 | Windows 방화벽 프롬프트 허용 | 프롬프트를 거부한 채 잰 `failure` 를 NAT 거동으로 읽는다 |
| 1 | 서로 다른 가정망 요건 | 같은 공유기 아래 PC 2대 결과를 blocker 20 의 증거로 쓴다 |
| 1 | `--peer` 노출 경고 | 상대 공인 주소가 셸 기록과 프로세스 목록에 남는다 |
| 1 | 방화벽 규칙 잔존 경고 | 비정상 종료 뒤 인바운드 포트가 열린 채 남는다 |
| 4 | `--peer` 가 Enter 동기화를 건너뛴다 | README 를 그대로 따라 시작 시각이 어긋난 무효 결과를 만든다 |
| 5 | 경로 오염 제거 | VPN 이 켜진 채 잰 값을 가정망 측정으로 기록한다 |
| 5 | `socket.behind_nat` 확인 | **한쪽이 NAT 뒤에 없는 측정을 NAT ↔ NAT 으로 보고한다** |

마지막 것은 실제로 한 번 겪은 사고다. 한 측정에서 한쪽의 로컬 주소가 곧 공인 주소였고,
사후에 알아챘다. 내가 유효성 검사를 "양쪽 공인 IP 가 다른가" 로 줄였는데 **그 검사는 이
경우를 통과시킨다.**

**원인은 "간결하게" 를 분량 목표로 읽은 것이다.** 무엇을 반드시 남길지 목록을 먼저 만들고
줄였어야 했다. 먼저 지우고 리뷰가 되살리게 해서 라운드가 다섯 번 더 들었다.

줄 수는 90 -> 123 -> 135 -> 144 로 늘었다. 그래도 원문의 4분의 1이 조금 넘는다.
**간결함과 안전 경고가 충돌하면 안전이 이긴다.** 잘못 재면 결과가 틀리는 것이 아니라 틀린
결과를 맞다고 믿게 된다.
