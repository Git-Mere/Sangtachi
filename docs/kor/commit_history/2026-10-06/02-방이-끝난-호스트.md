# 서버에서 방이 끝난 호스트의 거동을 정했다

## 왜 했나

`roadmap.md` Phase 3 착수 전 항목 가운데 문서로 정할 것이 하나 남아 있었다. 방을 세운 뒤
`host_report` 가 확정 오류를 받았을 때 호스트가 어떻게 하는가다. ADR 0011 이 미결로 남겼다.

`control_plane.md` 8.3 은 확정 오류를 곧바로 `CONTROL_PLANE_EXCHANGE_FAILED` 로 끝내고, 5.1 은
임대가 끊겨도 터널이 유지된다고 정했다. 그 자리에서 두 규칙이 어긋났다.

나머지 착수 전 항목 다섯(Elastic IP·DNS, 자격 증명, 프리 티어, 배포 설정 값, 시계 전제 둘)은
AWS 계정이 필요하다. 저장소 소유자가 직접 하고 결과를 알려 주기로 했다.

## 저장소 소유자가 정한 것

에이전트가 오류를 셋으로 나눈 안을 냈고 소유자가 권하는 안대로 정했다. ADR 0013 이다.

| 받은 것 | 호스트가 하는 것 |
|---------|------------------|
| `room_expired`, `room_not_found`, `unauthorized`, `bad_request` | `FAIL` 한 줄, `host_report` 멈춤, 세션 유지, 남은 세션이 끝나면 로비 |
| `rate_limited` | `FAIL` 없이 다음 주기에 다시 |
| 일시 오류 | 다음 주기에 다시 |

**`rate_limited` 를 나눈 근거는 6.4 의 케이스 표 12번 행이다.** 같은 공인 IP 의 다른 출발지가
예산을 태우면 정상 요청도 막힌다. 그때 멈추면 살아 있는 방이 남의 추측 때문에 죽는다.
