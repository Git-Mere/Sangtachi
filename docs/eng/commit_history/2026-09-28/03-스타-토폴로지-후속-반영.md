## Decisions

**The host now records readiness.** ADR 0008 fixed the unit as the pair but left the writer
open. While writing `host_report` we saw that **readiness from both registrations alone lets a
peer start punching while the host does not know about it.** With no packet leaving the host
side, no hole opens. Moving the reference instant to the moment the host learns of the pair
solves three things at once.

1. Both peers get the same reference instant
2. Only the host writes `PAIR#`, so the two-peer conditional-write race disappears
3. **A peer joining a dead host's room no longer gets `HOLE_PUNCH_TIMEOUT`.** With no host to
   confirm, the pair never becomes ready and the attempt ends at the polling deadline. That
   code names the real cause

Item 3 is a misclassification found during this work. If the host dies after registering
candidates, the pair becomes ready and the newcomer sprays an unanswered address for ten
seconds, which is then recorded as a NAT failure. That path is now structurally gone.

**The report interval is split in two.** Five seconds while a seat is free, thirty when the
room is full. Once confirmation is the host's job, a late joiner waits on that interval. A full
room has nobody waiting.

**Quoting check numbers is now forbidden.** Renumbering the 8.5 checks silently falsified
"check 1 of 8.5" in `roadmap.md`. Outside the table, refer to the counter name. That name is
the string the tests actually look for, so it can be cross-checked.

**Four mentions of rejoin stay.** All of them say it does not exist. Removing them would send
the next reader to the history folder to ask why.

**Both blockers sit where the lease and the reclaim were newly built.**

1. The reclaim transaction put `attribute_exists(pk)` on all three of the `PEER#`, `VIP#` and
   `PAIR#` deletes. A peer that left before confirmation has no `PAIR#`, so that condition fails
   and **the whole reclaim is cancelled.** The condition is now on `PEER#` only and the others are
   unconditional deletes
2. The confirmation write conditioned only on `PAIR#` being absent, so "both sides have at least
   one candidate" was not a storage condition. If the other peer is reclaimed between the read and
   the write, **a pair with no candidates is recorded as ready.** That is the path this commit set
   out to close. Both `PEER#` items now carry a `size(candidates) > 0` ConditionCheck in the
   transaction

**All seven warns were taken; six as substantive fixes.** Lease renewal pushing only the `ROOM` `ttl` so that the
child items of a long-lived room are deleted first; the missing ordering constraint between the
report interval and the lease; the missing reuse order for a routing-table slot; the missing path
for a departed peer's late packets after a reclaim; `plan.md` claiming five debt items against a
six-row table; and a wrong deleted-row count in the commit record.

**The remaining one was taken as a wording change.** The last row of the 1.1 table had "recover the identifiers
of a departed peer" in the **Does** column while the right cell said it does not. The two columns
are independent lists, so the left cell became something actually done (recording pair readiness)
and the recovery item moved to the right.
