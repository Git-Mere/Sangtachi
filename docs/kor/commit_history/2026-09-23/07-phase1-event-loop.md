# Phase 1 이벤트 루프와 콘솔

**대상 커밋:** 이 커밋
**Phase:** 1 (핵심 UDP 네트워킹) — 마지막 묶음

`architecture.md` 3.2 동시성 모델을 코드로 옮겼다. Phase 1 의 모든 조각이 여기서 묶인다.

## 무엇을 넣었나

| 대상 | 내용 |
|------|------|
| `timer.hpp` / `timer.cpp` | `next_timeout_ms`, `TimerSet`. 선형 주사로 가장 이른 마감을 구한다 |
| `console.hpp` / `console.cpp` | 16줄 SPSC 큐. 가득 차면 새 줄을 버리고 생산자가 카운터를 올린다 |
| `hash.hpp` / `hash.cpp` | SHA-256. Windows CNG 를 쓴다 |
| `loop.hpp` / `loop.cpp` | `EventLoop`, `run_console_reader` |
| `main.cpp` | 소켓을 열어 `socket.bind` 를 내고 루프를 돈다 |
| `scripts/e2e-check.ps1` | 프로세스 여럿이 실제로 주고받는지 본다 |

**SHA-256 을 직접 구현하지 않았다.** Windows CNG 는 OS 기본 제공이라 `spec.md` NFR-5 의
서드파티 의존성이 아니고 C-2 가 요구하는 네이티브 Windows API 다. 직접 짜면 시험 대상이
하나 늘 뿐 얻는 것이 없다.

**`next_timeout_ms` 를 순수 함수로 뒀다.** `architecture.md` 3.2.2 가 경고한 언더플로 두
가지를 케이스로 고정하기 위해서다. 마감이 지났을 때 뺄셈을 먼저 하면 거대한 값이 되고,
32비트로 좁히면 `INFINITE` 에 착지해 루프가 영원히 깨지 않는다.

**밀린 주기를 따라잡지 않는다.** 다음 마감은 `직전 마감 + 간격` 이 아니라 `now + 간격` 이다.
판정 축이 만료 **횟수**가 아니라 **간격**이라는 것을 케이스 이름에 적었다.

### 살아남았다가 케이스를 채워 죽인 변이

`WSAEnumNetworkEvents` 호출을 지운 변이가 처음에 살아남았다. **그 결함은 스핀이라 바퀴를
정해진 횟수만 도는 시험으로는 보이지 않는다.** 이벤트가 신호 상태로 남아 대기가 매번 즉시
반환할 뿐, 결과는 같다.

그래서 **비었을 때 실제로 기다리는지**를 보는 케이스를 넣었다. 타이머를 두지 않아 대기
타임아웃이 `INFINITE` 가 되게 하고, 다 비운 뒤의 바퀴가 300ms 안에 돌아오지 않는 것과 종료
신호로는 돌아오는 것을 함께 본다. 그 케이스를 넣자 변이가 죽었다.

## 시험 하네스를 두 번 고쳤다

**하나, `ctest` 에 시간 상한이 없었다.** `WSAEventSelect` 를 뺀 변이가 소켓을 블로킹으로
남겨 `recvfrom` 이 돌아오지 않았고, 하네스째로 매달렸다. `TIMEOUT 30` 을 걸고 변이
드라이버에도 상한을 뒀다. **변이는 `FAIL` 이 아니라 무한 대기로 나타날 수 있다.**

**둘, `cli-check.ps1` 이 프로그램의 새 거동을 따라오지 못했다.** `main.cpp` 가 이벤트 루프를
돌게 되면서 인자가 맞으면 스스로 끝나지 않는데, 그 검사는 끝난다고 가정하고 있었다. 표준
입력으로 `quit` 을 넣고 닫도록 고쳤고 `WaitForExit` 에 10초 상한을 뒀다.

그 과정에서 인자를 문자열로 이어 붙이는 바람에 **공백이 든 인자가 둘로 쪼개졌다.** 공백을
시험하려던 케이스가 그 공백을 프로그램에 전달하지 못했다. Windows 명령줄 인용 규칙대로
감싸는 함수를 넣었다. Windows PowerShell 5.1 에는 `ArgumentList` 컬렉션이 없다.

## 크로스 모델 리뷰

Codex 에 렌즈 둘(동시성과 수명, 시나리오 추적)을 붙였다. 지적 7건 중 **6건 반영, 1건
기각**이다. **blocker 3건이 같은 뿌리였다.**

### blocker — detach 한 스레드가 스택을 참조했다

`[console]` 은 join 하지 않는다. 3.2.7 종료가 그렇게 정했고 이유도 적혀 있다. 표준 입력
읽기를 밖에서 취소할 수단이 없으므로 join 하면 사용자가 한 줄을 더 칠 때까지 종료가 멈춘다.

**그런데 join 하지 않는다는 것은 그 스레드가 `main` 이 빠져나간 뒤에도 깨어날 수 있다는
뜻이다.** 처음 구현은 명령 큐와 중단 표시를 `main` 의 스택에, 이벤트 핸들을 `EventLoop` 에
두었다. 셋 다 그 스레드보다 먼저 죽는다.

| 등급 | 지적 | 처리 |
|------|------|------|
| blocker | 중단 표시가 원자가 아닌 `bool` 인데 스레드 둘이 읽고 쓴다 | **반영** |
| blocker | detach 한 스레드가 큐·표시·이벤트 핸들을 참조하는데 셋 다 먼저 파괴될 수 있다 | **반영** |
| blocker | `run_console_reader` 가 `const bool&` 로 받아 해제된 것을 읽는다 | **반영** |

셋을 하나로 고쳤다. `ConsoleSession` 이 큐와 원자 중단 표시와 자동 리셋 이벤트를 소유하고,
스레드가 `shared_ptr` 를 **값으로** 받아 스스로 수명을 붙든다. `EventLoop` 는 그 이벤트를
빌려 쓰기만 하고 닫지 않는다.

> **3.2.7 의 "소유한 것이 명령 큐뿐이라 잃는 것이 없다" 는 여전히 맞다.** 그 문장이 말하지
> 않은 것은 그 큐가 **어디에 있어야 하는가** 다. 스택에 두면 잃는 것이 없는 게 아니라
> 해제된 것을 건드린다.

### 그 밖의 지적

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | `valid()` 가 종료 이벤트만 본다. 콘솔 이벤트나 소켓 이벤트가 죽어 있으면 대기 배열의 "살아 있는 핸들" 규칙이 깨진다 | **반영.** 셋을 모두 본다. Phase 1~2 의 세 핸들은 전부 항상 있으므로 한 번 확인하면 배열은 구성상 조밀하다 |
| warn | `run_once` 가 널 검사 없이 세 핸들을 배열에 넣는다 | **반영.** 위 `valid()` 로 막고 그 근거를 헤더에 적었다 |
| blocker | `quit` 뒤 `main` 이 큐와 이벤트를 파괴하는 동안 읽기 스레드가 살아 있을 수 있다 | **반영.** 위와 같은 수정이다 |
| warn | `quit` 을 처리한 바퀴가 타이머까지 돌고 참을 돌려준다. 종료가 다음 바퀴로 미뤄진다 | **기각.** 그것이 3.2.3 루프 한 바퀴가 정한 동작이다. `quit` 은 `shutdown()` 을 직접 부르지 않고 종료 이벤트를 신호하며, "다음 바퀴의 대기가 종료 핸들에서 반환해 3.2.7 종료의 순서를 그대로 탄다" 고 적혀 있다. 그래야 `[telemetry]` 와 `[control]` 이 같은 신호로 함께 깨어난다. 시험이 그 두 바퀴 동작을 그대로 단언한다 |

**시나리오 렌즈가 blocker 를 냈다.** 앞선 커밋들에서도 그랬듯, 컴포넌트를 따로 보는 렌즈가
아니라 한 번의 실행을 끝에서 끝까지 따라가는 렌즈가 수명 문제를 잡았다.

### 수리 확인 라운드에서 오탐 2건이 나왔다

수리분만 보내는 라운드에서 입력을 `client`, `tests`, `docs/kor/commit_history` 로 잘랐다.
그러자 리뷰어가 "이 기록은 `scripts/e2e-check.ps1` 을 더했다고 적는데 diff 에 없다" 와
"문서 세 군데를 고쳤다고 적는데 diff 에 없다" 를 냈다. **둘 다 내가 자른 범위 밖이었다.**

`git diff --cached --name-only` 로 직접 확인하고 기각했다. `scripts/e2e-check.ps1` 과
`docs/kor/architecture.md` 는 스테이징에 있다.

> **범위를 자르면 "없다" 류의 오탐이 따라온다.** 그것이 자르지 말라는 뜻은 아니다. 자른
> 만큼 입력을 아끼고, "없다" 류의 지적만 HEAD 를 직접 확인한 뒤 받거나 기각하면 된다.
> 확정 라운드는 전체 diff 로 돌린다.
