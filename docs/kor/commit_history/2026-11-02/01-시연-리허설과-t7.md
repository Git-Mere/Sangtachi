# 시연 리허설과 멤버 목록 단절(T-7) 실측

## 왜 했나

`roadmap.md` Phase 8 의 남은 두 실측을 시연 플레이어와 함께 돌았다. 시연 전 리허설과 T-7 이다. 시연은 2026-11-05 다. 같은 날 시연 전
확인을 줄이는 결정(ADR 0037)도 내렸다.

## 어떻게 쟀나

- 기기: G 는 `mere-galaxy`(Linux Release 콘솔, 호스트, Minecraft 서버). C 는 시연 플레이어의 Windows. A 는 소유자의 Windows. A 와 C 는
  같은 GUI 배포물(`field-kit-p8`)을 썼다
- G 의 표준 오류는 줄마다 받은 시각을 붙여 남겼다. C 의 로그와 기록 파일은 시연 플레이어가 보내 줬다. 원본은 `field-test/2026-11-02/` 에
  두고 커밋하지 않는다
- C 가 명부를 받은 때는 C 의 로그에서 `CONNECTED` 뒤 5초 간격 `PING` 타이머 줄을 세어 5초 폭으로 잡았다. C 와 G 의 기록 파일 시각은 같은
  수립에서 0.02초 차이였다

## 작업 중에 생긴 일

이 관찰은 규칙으로 만들지 않았다.

- 학교 망 안의 두 기기(유선 LAN 과 학교 Wi-Fi)는 서로 연결되지 않았다. 둘 다 같은 공인 주소 뒤였고 홀펀칭이 `HOLE_PUNCH_TIMEOUT` 으로
  끝났다. G 에서 `tcpdump` 로 보니 A 의 ICMP 는 들어오고 UDP 는 하나도 들어오지 않았다. G 의 입력 방화벽은 모두 받는 상태였다. 학교 망이
  기기끼리의 UDP 를 막고 같은 NAT 안으로 되돌려 주지 않는 것으로 본다. A 쪽 캡처는 하지 않았다
- 같은 학교 유선 LAN 의 두 기기는 바로 연결됐다
- 휴대폰의 Wi-Fi 가 켜져 있으면 핫스팟이 학교 망을 거쳐 나갔다. 공인 주소가 학교 것과 같았다. Wi-Fi 를 끄자 이동통신망 주소로 바뀌었고
  학교 유선 LAN 의 A 와 바로 연결됐다
- 학교 유선 LAN 에서 A 의 Tailscale 이 제어 서버(`controlplane.tailscale.com`)에 닿지 못했다. 같은 망에서 다른 HTTPS 는 됐다.
  `ssh mere@mere-galaxy` 가 끊겨 A 의 Wi-Fi 를 같은 핫스팟에 붙이고 로컬 주소로 들어갔다. 한 번은 Sangtachi 터널의 가상 IP 로 ssh 했다
- `mere-galaxy` 는 핫스팟에 다시 붙을 때마다 Wi-Fi 절전이 켜졌다. 그때마다 껐다
- 휴대폰을 들고 자리를 떠 핫스팟이 끊기자 호스트를 다시 띄워야 했다
- T-7 강제 종료의 첫 시도는 작업 관리자 "프로세스" 탭의 작업 끝내기였다. 호스트가 `CLOSE` 를 받아 정상 종료로 돌았다. `taskkill /F`
  로 다시 했다
- C 의 백신이 배포물 zip 을 받을 때 경고를 냈다. 소유자 기기의 Defender 검사는 깨끗했고 zip 안의 실행 파일은 빌드 산출물과 SHA-256 이
  같았다. 서명 없는 실행 파일의 오탐으로 본다. 탐지 이름은 받지 못했다
