## How it was measured

- Machines: G is `mere-galaxy` (Linux Release console, host, Minecraft server). C is the demo player's Windows. A is the owner's Windows. A and C
  used the same GUI distribution (`field-kit-p8`)
- G's standard error was kept with the receive time attached to each line. C's logs and record files were sent by the demo player. The raw files
  are kept in `field-test/2026-11-02/` and not committed
- The time C received the roster was bounded to a 5-second window by counting the 5-second `PING` timer lines after `CONNECTED` in C's log. For
  the same setup, the record-file times of C and G differed by 0.02 seconds

## What happened during the work

These observations were not turned into rules.

- Two machines inside the school network (wired LAN and school Wi-Fi) did not connect to each other. Both were behind the same public address and
  hole punching ended with `HOLE_PUNCH_TIMEOUT`. `tcpdump` on G showed A's ICMP arriving and no UDP at all. G's input firewall accepted
  everything. The school network appears to block UDP between machines and not to hairpin inside the same NAT. No capture was taken on A
- Two machines on the same school wired LAN connected right away
- With the phone's Wi-Fi on, the hotspot went out through the school network. The public address was the same as the school's. With Wi-Fi off it
  changed to a mobile network address and connected right away to A on the school wired LAN
- On the school wired LAN, A's Tailscale could not reach the control server (`controlplane.tailscale.com`). Other HTTPS worked on the same network.
  `ssh mere@mere-galaxy` failed, so A's Wi-Fi was joined to the same hotspot and the local address was used. Once, ssh went over the virtual IP of the
  Sangtachi tunnel
- `mere-galaxy` turned Wi-Fi power saving on every time it rejoined the hotspot. It was turned off each time
- The hotspot dropped when the owner left with the phone, and the host had to be started again
- The first forced-kill attempt of T-7 was End task from the "Processes" tab of Task Manager. The host received `CLOSE` and it took the normal
  shutdown path. It was redone with `taskkill /F`
- C's antivirus warned when the distribution zip was downloaded. The Defender scan on the owner's machine was clean, and the executable in the zip
  had the same SHA-256 as the build output. It is taken as a false positive on an unsigned executable. The detection name was not obtained
