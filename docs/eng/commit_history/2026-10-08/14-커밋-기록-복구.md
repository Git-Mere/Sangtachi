# Restoring the 2026-10-08 Commit Records 08-13

## What went wrong

Records 08-13 in `commit_history/2026-10-08/` (both languages, twelve files) were committed with only their last line left. They
are the records of commits `d7ccc2b`, `b0e60a9`, `f962dcb`, `4cd8976`, `5e23282`, and `ffd2e27`. The wave 2 E+F subagent saw that
these files were empty in its worktree and reported it.

**Cause.** To append one review-result line to the end of a record, Python used `open(p, "w").write(open(p).read() + line)`. Opening
with `"w"` empties the file first, and the `read()` in the argument then reads the empty file. So only the one line remained. Record
07 was fine because it was read into a variable before writing.

**Why the document gate missed it.** Both languages were emptied the same way, so heading, table row, code block, and link counts
matched. The gate's pair check only compares the structure of the two languages, so it cannot catch bodies truncated the same way on
both sides.

## How it was restored

The staged diff handed to cross-review before each commit was still in the review prompt files. That diff holds the whole record, as
a new file, right before the last line was appended. The last line that was meant to be appended was added to that content.

- Sources: B from round 2, A from main round 1, C from round 2, ADR 0021 from round 2, D/D2 from main round 1, ADR 0022 from round 2.
  Each is the last review right before that commit
- Cross-check: seven files (both languages of 08, 09, 12, and the English 10) matched the record text still held in the working
  session character for character. The other five (Korean 10, both languages of 11 and 13) had no original left to compare against
