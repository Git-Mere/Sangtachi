# issue_history 도입, Linux 실측 기기 정리 시점

## 왜 했나

결정은 `decisions/`, 커밋마다의 변경은 `commit_history/` 가 갖는다. 여러 커밋에 걸치거나 코드 밖에 원인이 있는 이슈를
증상부터 처리까지 한곳에서 찾을 자리가 없었다. 저장소 소유자가 `decisions/` 형식을 따르는 번호 단위 기록을 정했다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 새 기록 폴더. 쓰는 기준, 구성(증상 / 조사 / 원인 / 처리 / 결과), 상태 셋(해결, 우회, 미해결), 갱신 규칙 | `issue_history/README.md` |
| 이번 Linux 작업에서 겪은 이슈 넷 | `issue_history/0001` ~ `0004` |
| 기록 문서 목록, 갱신 규칙, 링크 허용, 세션 시작 때 읽을 자리. 소유자가 문구를 승인했다 | `CLAUDE.md` |
| `mere-galaxy` 의 암호 없는 `sudo` 와 Wi-Fi 절전은 두 기기 실측이 끝난 뒤 같이 정리한다(소유자 결정). Wi-Fi 항목이 이슈 0001 을 가리킨다 | `plan.md` |

- **쓰는 기준.** 원인을 찾는 데 조사가 필요했던 결함이나 환경 문제다. 그래서 이번 작업의 Minecraft 화이트리스트, Docker 미실행,
  사용량 스킬의 빈 값은 쓰지 않았다. 원인이 바로 보였다
- **영어 쪽 파일 이름은 한국어와 같다.** `commit_history/` 와 같다. `decisions/` 처럼 영어 이름을 쓰면 docgate 의
  `NUMBER_PAIRED_DIRS` 를 고쳐야 해서 쓰지 않았다
- 이슈 0004 를 쓰다 바로잡은 것: 두 방향 실측은 `IFF_TUN_EXCL` 을 넣기 전 빌드로 했다. 직전 기록
  ([`02-linux-콘솔-클라이언트.md`](02-linux-콘솔-클라이언트.md))은 고친 빌드로 실측했다고 쓰지 않았으므로 고치지 않는다
