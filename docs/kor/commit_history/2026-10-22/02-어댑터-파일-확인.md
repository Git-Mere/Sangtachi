# 어댑터 파일이 없을 때의 기동 실패를 분명히

## 왜 했나

저장소 소유자가 친구에게 `sangtachi_client.exe` 하나만 줬고, 친구 PC 의 로그가 `ERROR adapter.error reason=subnet verdict=unknown
exit_code=4294770688` 로 끝났다. 그 종료 코드는 `0xFFFD0000` 이고, Windows PowerShell 이 `-File` 의 스크립트가 없을 때 낸다(이 PC 에서
없는 경로로 재현했다). 실행 파일 옆에 `Test-SubnetOverlap.ps1` 이 없었던 것이다. 로그만으로는 원인을 알 수 없었다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 어댑터 기동 단계의 첫 단계. 실행 파일 옆의 `wintun.dll`, `Test-SubnetOverlap.ps1`, `Initialize-FirewallRules.ps1` 을 보고, 없는 것을 모두 `adapter.error reason=missing_file file=...` 한 줄에 싣는다. 표준 출력이 콘솔이면 같은 폴더에 둘 파일을 알리는 안내 한 줄 | `client/src/main.cpp`, `platform/win32/tun.cpp` |
| 시험. 실행 파일만 옮긴 폴더에서 셋 다, 하나만 빠진 폴더에서 그 하나 | `scripts/cli-check.ps1` |
| 문서. 7장 어댑터 수명 표의 첫 행, 3.5 로비 안내 표, 9장 `adapter.error` 필드 | `architecture.md` (미러 포함) |

레포 밖에서는 `C:\me\build\update-latest.ps1` 이 `latest_build\Sangtachi.zip` 도 만든다. 실행에 필요한 네 파일과 `VERSION.txt` 만 넣는다.

## 중요한 결정

- **관리자 권한 확인보다 앞이다.** 파일이 없으면 승격해도 기동할 수 없다. 관리자가 아닌 셸에서도 진짜 이유가 먼저 나온다
- **없는 파일을 모두 한 줄에 싣는다.** 하나씩 고치며 다시 띄우지 않게 한다
- **`--no-adapter` 는 보지 않는다.** 그 기동은 세 파일을 쓰지 않는다

## 검증

- `pwsh -NoProfile -File scripts/test.ps1`: `all tests passed`. 단위 시험 641개, `cli-check` 43개, `e2e-check`, `lobby-check`, `session-check`
- `cli-check` 의 새 확인 둘. 실행 파일만 옮긴 폴더에서 `file=wintun.dll,Test-SubnetOverlap.ps1,Initialize-FirewallRules.ps1` 이고 `not_elevated` 가
  없다. 스크립트 하나만 빠진 폴더에서 `file=Initialize-FirewallRules.ps1` 이다
- `python tools/docgate/docgate.py`, `--claims`: `VERDICT: pass`
