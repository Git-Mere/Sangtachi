# plan.md 의 "구현 때 같이 볼 자리" 절을 지운다

## 왜 했나

Phase 1~9 가 끝났다. 남은 구현은 스트레치 목표뿐이다. 이 절의 줄은 모두 "그 코드를 다시 고칠 때" 보는 조건부 메모라 다음에 할 일이 아니다. 스트레치 목표를 할 때 그때 고려하면 된다고 소유자가 정했다. 코드 주석으로 옮기지 않고 내용은 이 기록에만 남긴다.

## 지운 내용

| 자리 | 무엇 | 언제 보려 했나 |
|------|------|------|
| `control-server/tests/mutate.py` 의 시간 초과(`telemetry-server/tests/mutate.py` 도 같은 실행기) | 상한에 걸리면 pytest 프로세스만 죽인다. 그 시험이 띄운 서버 프로세스가 남을 수 있다. 손자까지 거두려면 Windows Job Object 가 필요하다 | 변이 실행기를 다시 고칠 때 |
| `pending_pings` 상한 | `protocol.md` 5.5 의 "그래도 가득 차면 새 `PING`을 보내지 않는다" 분기를 밟는 시험이 없다. PING 간격과 항목 수명이 둘 다 5초라 표가 둘 이상 차지 않는다 | 11장 PING 간격이나 5.5 항목 수명을 바꿀 때 |
| 콘솔 `send` 의 송신 버퍼 | 송신 버퍼가 차면 `WSAEWOULDBLOCK` 으로 작업을 끝낸다. 576·1452바이트는 한 번에 45~133개만 나간다. 다음 루프 바퀴에 이어 보내면 정한 개수를 채운다. 바이트 대조는 이것에 기대지 않는다(ADR 0032) | 콘솔 `send` 로 개수를 채워야 하는 시험이 생길 때 |
| `is_valid_name` 의 자리 | `control_plane.md` 2.7 검사가 `tunnel/packet.hpp` 에 있어 기동 인자와 제어 평면 코드가 터널 패킷 모듈을 포함한다. 중립 헤더로 옮기고 `packet.hpp` 가 그것을 쓰는 편이 의존 방향이 맞다 | 그 헤더를 다음에 고칠 때. GUI 의 이름 칸 검사가 그 계기일 수 있다 |

`plan.md` 맨 위 표의 같은 이름 행도 지웠다. 이 절을 가리키던 `tests/timer_test.cpp` 주석에서도 그 참조를 지웠다. 주석만 바뀌어 시험은 돌리지 않았다.
