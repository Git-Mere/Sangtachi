# 로컬 기록 파일의 경로와 줄 형식 (ADR 0016)

## 왜 했나

`plan.md` 다음에 할 일의 첫째인 Phase 4 착수 전 결정 가운데 하나다. `architecture.md` 9장은 계약만
있고 경로와 줄 형식이 없어서 `spec.md` M-6 을 판정할 수 없었다.

저장소 소유자가 정한 것이다.

| 질문 | 결정 |
|------|------|
| 경로 | 실행 파일 폴더 아래 `records\`. 경로를 바꾸는 인자는 없다 |
| 파일 단위 | 프로세스마다 새 파일. `<UTC 기동 시각>-<PID>.log` |
| 줄 형식 | `<이름>=<값>` 을 공백으로 이은 것. 필드 아홉, 순서 고정, 빈 값 `-` |
| 중단 | `ABORTED` 수립 줄. 상대가 실패를 알린 `CLOSE` 는 `PEER_FAILED` |
| 열기와 쓰기 실패 | 열기 실패는 기동 실패. 쓰기 실패는 `WARN`, 카운터, 터널 유지 |
| 수립 시간 | `setup_ms` 를 더한다 |

## 중요한 결정

- **RTT 는 마이크로초다.** 같은 LAN 의 RTT 가 밀리초 정수로 0 이 되는 것을 막는다
- **호스트와 플레이어의 `setup_ms` 기점이 다르다.** 호스트 쪽을 STUN 에서 재면 참가를 기다린 시간이
  섞인다. 두 값은 서로 비교하지 않는다
- **`ABORTED` 는 `CONNECTED` 에 닿기 전에 끝난 중단이다.** 이쪽의 `leave` 나 종료 이벤트, 상대의
  `CLOSE`(`reason` `0x00`·`0x01`)가 계기다. 닿은 뒤의 중단은 재협상 중이어도 종료 줄 `CLOSED` 다
- **상대의 `CLOSE` 가 실패(`0x02`·`0x03`)를 알리면 `PEER_FAILED` 다.** `protocol.md` 5.6 이 Phase 9 를
  위해 나눈 구분을 기록에서도 지킨다. 원인 코드는 상대의 기록에 있다
- **호스트의 쌍 시도는 준비 완료 뒤 펀치를 시작할 때 생긴다.** 그 전에 회수된 플레이어는 호스트
  쪽에 줄이 없다
- **쓰기가 한 번 실패하면 그 파일에 더 쓰지 않는다.** 반만 쓴 줄 뒤에 이으면 두 줄이 붙는다
- **줄 수 판정은 종료 절차를 끝까지 돌았고 쓰기 실패가 없는 실행에만 한다.** 그 밖은 판정 불가다
- 기동 실패의 종료 코드는 다른 기동 실패와 같이 "0 이 아닌 값" 으로 두었다. 제안 단계에서 말한 2 는
  인자 오류의 값이다

## 검증

| 무엇 | 결과 |
|------|------|
| `icacls "C:\Program Files"` | `BUILTIN\Users` 는 `(RX)` 와 하위의 `(GR,GE)` 뿐이다. `windows-prereq.md` 4절 근거 |
| 시나리오 추적 | 플레이어가 `join` 하고 연결된 뒤 `quit`. 기동 때 파일 열기와 `record.open` → STUN 시작이 `setup_ms` 기점 → `CONNECTED` 에서 수립 줄 `OK` → 종료 절차 3번이 종료 줄 `CLOSED` 와 마지막 `rtt_us` |
| 시나리오 추적 | 호스트에 플레이어 둘, 하나는 펀치 실패, 하나는 연결 뒤 `leave`. 호스트 파일은 시도 둘, 줄 셋 |

## 크로스 모델 리뷰

Codex. 한국어 diff 에 렌즈 둘(문서 간 일관성, 실패 처리).

| 렌즈 | 지적 | 처리 |
|------|------|------|
| 일관성 | blocker. 첫 `CONNECTED` 전에 상대 `CLOSE` 로 끝난 시도의 결과가 없다 | 반영. `ABORTED` 의 계기에 상대의 `CLOSE` 를 넣었다 |
| 일관성 | blocker. 호스트의 STUN 은 `create_room` 뒤인데 "방 만들기 전 실패" 로 적었다 | 반영. "방을 세우기 전" 으로 고치고 `register_candidate` 성공을 기준으로 했다 |
| 일관성 | warn. 호스트가 본 플레이어가 준비 전에 회수되면 시도인지 정하지 않았다 | 반영. 쌍의 시도는 펀치 시작에 생기고 그 전 회수는 줄이 없다 |
| 일관성 | warn. 재협상 중의 중단이 `ABORTED` 행과 `CLOSED` 규칙 둘에 걸린다 | 반영. `ABORTED` 를 `CONNECTED` 전으로 한정했다 |
| 일관성 | warn. `ABORTED` 가 `leave`·`quit` 만 말하고 창 닫기와 Ctrl+C 를 빠뜨렸다 | 반영. 종료 이벤트 전체로 |
| 일관성 | warn. 내용 계약과 M-6 의 결과 집합에 중단이 없다 | 반영 |
| 실패 처리 | blocker. 일부만 쓰인 줄 뒤에 계속 쓰면 줄이 붙는다 | 반영. 실패 뒤로는 쓰지 않고, 읽는 쪽은 LF 없는 마지막 줄을 버린다 |
| 실패 처리 | warn. 쓰기 실패와 강제 종료가 있으면 줄 수 판정이 성립하지 않는다 | 반영. "판정할 수 있는 실행" 을 정했다 |
| 실패 처리 | warn. 양수 `rtt_us` 검사로는 단위 오류를 못 잡는다 | 반영. 줄을 만드는 함수에 값을 주입해 정확한 문자열을 본다 |
| 실패 처리 | warn. 실행 파일 폴더만 막으면 기존 `records` 가 쓰일 수 있다 | 반영. `records` 가 없는 새 폴더에서 돌린다 |
| 실패 처리 | warn. 실행 파일 경로의 형태(링크, 한글, 긴 경로)가 정해지지 않았다 | 반영. OS 가 준 경로를 그대로 쓰고, 와이드 문자로 다루고, 잘리면 열기 실패다 |

영어 미러와 기록을 더한 staged diff 에 렌즈 하나(번역 충실도와 고친 뒤의 한국어 재확인)를 다시 돌렸다.

| 지적 | 처리 |
|------|------|
| warn. `CONNECTED` 전에 받은 상대의 `CLOSE` 를 전부 `ABORTED` 로 적으면 `protocol.md` 5.6 의 `0x02`·`0x03`(실패)과 `0x01`(사람이 끔) 구분이 사라진다 | 반영. `PEER_FAILED` 를 더하고 `reason` 으로 가르는 표를 9장에 두었다. ADR 0016 결정 6 과 대안 10, `spec.md` M-6, `roadmap.md` 검증에 반영 |

미러 작업은 하위 작업자 하나가 했다. 작업자가 짚은 한국어 표현 넷(로드맵 예시의 펀치 조건, 중단도
한 줄이라는 것 세 곳, "그 절" 이 가리키는 곳)을 고쳤다. `windows-prereq.md` 4절 머리의 "미검증" 은
구현이 없으므로 그대로 둔다.

이 반영 뒤의 커밋 직전 리뷰에서 warn 하나가 나왔다. 시도 표의 "플레이어가 연결되고 나중에 끝남" 행이
종료 줄 값에서 `PEER_FAILED` 를 빠뜨렸다. 반영했다. 그 행이 결과 값 표를 가리키게 했다.
