# 세션별 카운터(ADR 0022)와 세션 구현의 문서 공백 셋

## 왜 했나

2차 E+F 의 하위 에이전트가 세션 상태 기계를 짜다가 문서 공백 다섯을 물어 왔다. 넷은 기존 문장을 문자 그대로 읽은 결과와
맞거나 동작에 영향이 거의 없어 그대로 받기로 했다. 카운터 하나는 저장소 소유자가 "어느 상대와의 연결이 나빴는지 사후에 확인하고
싶다" 며 세션별 표를 골랐다. 문서를 먼저 고친다(`CLAUDE.md`).

## 무엇을 바꿨나

| 공백 | 정한 것 | 자리 |
|------|---------|------|
| 카운터 표가 세션별인가 | 프로세스 표와 세션별 표. 오르는 자리가 범위를 정한다. 세션 줄에 `peer_id`, `peer_name`. 내는 시점 | `architecture.md` 9장, ADR 0022 |
| `drop_terminal_state` 와 8.1 검사 8번의 순서 | 8.1 의 1~8번 뒤, 8.2 앞. 종료 세션도 검사 7번의 "세션이 있는 피어" 다 | `protocol.md` 8장 머리, 9.4.1 |
| 폐기 목록이 프로세스에 하나인가 | 하나. 호스트의 세션들이 함께 쓴다 | `protocol.md` 4.3 |
| 펀치 시작 전 재협상의 7·10번 | 두 타이머는 실제 펀치 시작 때 시작한다 | `protocol.md` 9.5 |
| RTT 시계 | 문서대로(`concurrency.md` 4장 QPC). 문서 변경 없음 | |
| 리뷰가 찾은 낡은 자리 | 로비 표의 카운터 행, 11장 타이머 표의 재협상 칸, 9.4.1 근거의 "카운터", `roadmap.md` Phase 4 의 카운터 읽는 법과 폐기 목록 시험의 근거 | `concurrency.md` 7장, `protocol.md` 9.4.1·11장, `roadmap.md` Phase 4 |

## 크로스 모델 리뷰

Codex. 바뀐 규칙과 어긋나는 문장을 `architecture.md`, `concurrency.md`, `protocol.md`, `roadmap.md` 에서 찾게 했다.

| 지적 | 처리 |
|------|------|
| blocker. `concurrency.md` 7장 로비 표가 카운터를 프로세스 누적이고 초기화하지 않는다고만 적어, 세션 표가 세션과 함께 사라지는 것과 어긋난다 | 반영. 프로세스 표와 세션 표를 나눠 적었다 |
| blocker. 9.5 의 새 문단이 펀치 전 구간을 `PUNCHING` 이라 했지만 7번은 6번이 성공하면 `HANDSHAKING` 이다 | 반영. "예정 시각을 기다리는 구간" 으로 고치고 상태는 7번대로라고 적었다 |
| warn. 11장 타이머 표가 재협상 때 `HELLO` 재전송 시작과 펀치 마감 재설정을 조건 없이 적는다 | 반영. 두 칸에 펀치 시작 전 예외를 적었다 |
| warn. `roadmap.md` 의 카운터 확인이 이름으로만 카운터를 가리킨다 | 반영. Phase 4 검증 머리에 범위대로 읽는다는 규칙을 한 번 적었다 |
| warn. 폐기 목록이 프로세스에 하나면 호스트의 세션 여럿이 17개를 만들 수 있어 "만들 수 없다" 는 근거가 틀렸다 | 반영. 근거를 "시험이 무겁다" 로 고치고, 목록이 하나인 것을 보는 항목을 더했다 |
| warn. ADR 의 세션 수 상한이 종료 상태로 보존된 세션을 빠뜨렸다 | 반영. 살아 있는 것과 보존된 것을 따로 적었다 |
| warn. 9.4.1 근거의 "이미 정리한 카운터" 가 세션 표를 보존 동안 남기는 것과 어긋난다 | 반영. "세션 타이머" 로 고쳤다 |

2차 리뷰(그 수정 확인)는 `LGTM - no blockers` 였다.
