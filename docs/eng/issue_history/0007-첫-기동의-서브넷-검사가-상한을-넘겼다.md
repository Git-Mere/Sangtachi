## Symptom

For the rehearsal on the new demo networks, the first GUI started on the demo player's Windows machine (`C` in `experiments.md`) failed to
start. The previous GUI on that machine had ended about 4 hours 46 minutes earlier.

```text
ERROR adapter.error reason=subnet verdict=unknown exit_code=0 overlaps=- op=WaitForSingleObject code=258
```

`code=258` is `WAIT_TIMEOUT`. In the log this line comes right after `control.server`, and there is no `adapter.open`. The process started again
about 39 seconds later was normal, and the rehearsal was done with it.

The same machine also failed to start, for a different reason, the first time it started that distribution in [Issue 0006](0006-첫-gui-실행이-adapter-eof-로-끝났다.md).

## Investigation

| Suspected | Seen | Judgement |
|-----------|------|-----------|
| That machine's network overlaps the virtual range | The process started again passed the check on the same network and received `10.100.0.4`. The verdict is `unknown` and the overlap field is empty | No. It ended before a verdict came out |
| The client handled the timeout wrongly | `tun.cpp` waits for the check script up to `kSubnetCheckCapMs` (30 seconds), and past that it ends the process and goes to startup failure. It does not treat an undetermined verdict as a pass | No. It follows the code |

## Cause

**Confirmed.** The subnet-overlap check script did not finish within 30 seconds. On the owner's machine it takes 1 to 4 seconds per run.

**Unknown.** Why only that run on that machine took long. The candidates are a slow start of PowerShell after a few hours unused and the antivirus of
that machine scanning the script. That machine's antivirus warned when the distribution was downloaded. No data remains on where the script spent
its time.

## Handling

The code and the specification were not changed. Starting again is enough.

The way to look again is to run the check script alone on the same machine and measure the time it takes.

## Result

It happened once. The process started again was normal.
