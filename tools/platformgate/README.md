# platformgate

플랫폼 이음새 게이트. OS 헤더가 정해진 자리 밖에 있는지 기계가 판정한다.
ADR 0010 이 정한 규칙 하나를 명령으로 옮긴 것이다.

> OS 헤더를 포함하는 클라이언트 원본은 전부 `client/src/platform/` 아래에 둔다.
> `client/include/` 아래에는 OS 헤더가 하나도 없다.

```bash
python tools/platformgate/platformgate.py            # 마지막 줄이 VERDICT: pass 여야 한다
python tools/platformgate/platformgate.py --list     # 허용 자리의 OS 헤더까지 나열. 종료 코드는 안 바뀐다
python tools/platformgate/platformgate.py --root .   # 루트 지정
```

종료 코드는 통과 0, 실패 1, 루트를 찾지 못하면 2다. 2는 **판정하지 않았다는 뜻**이고 통과가
아니다. 그때는 `VERDICT` 줄을 내지 않는다.

## 무엇을 판정하는가

검사 대상은 `client/` 아래의 `.cpp` 와 `.hpp` 다. 그 안의 `#include` 중 아래 이름 목록에
있는 것을 찾아 자리를 본다.

| 자리 | 판정 |
|------|------|
| `client/src/platform/` 아래 | 허용 |
| `client/include/` 아래 | 위반. 0 건이어야 한다 |
| `client/` 의 나머지 | 위반 |

출력은 위반마다 한 줄로 `파일:줄:헤더` 다. 그 앞에 `SUMMARY:` 한 줄, 맨 끝에 `VERDICT:`
한 줄이 붙는다.

```
SUMMARY: files=24 os_includes=7 allowed=7 violations=0 public_header_violations=0
VERDICT: pass
```

## OS 헤더 목록은 허용 목록이 아니다

**목록에 없는 헤더는 판정하지 않는다.** OS 헤더로 단정하지도, 아니라고 단정하지도 않고
아무 말도 하지 않는다. 즉 **통과한다.** 지금 목록은 14개다.

`windows.h`, `winsock2.h`, `ws2tcpip.h`, `ws2spi.h`, `mswsock.h`, `mstcpip.h`, `iphlpapi.h`,
`bcrypt.h`, `ncrypt.h`, `wincrypt.h`, `wintun.h`, `netioapi.h`, `objbase.h`, `shlwapi.h`

새 OS 헤더를 쓰기 시작하면 `platformgate.py` 의 `OS_HEADERS` 에 손으로 넣는다. 넣기 전까지
게이트는 그것을 잡지 못한다. 목록을 늘릴 때 시험도 같이 늘린다.

헤더 이름의 대소문자는 가리지 않는다. `<Windows.h>` 도 같은 헤더다.

## 정해 둔 것

`#include` 를 어디까지 세는지다. 모르는 채로 두지 않고 정했다.

| 자리 | 세는가 |
|------|--------|
| 줄 주석, 블록 주석 (여러 줄 포함) | 아니다 |
| 보통 문자열, 원시 문자열 `R"(...)"` | 아니다 |
| `#if 0` 과 `#ifdef _WIN32` 안 | 센다 |
| 지시자 **안쪽**의 주석 (`#/**/include/**/<windows.h>`) | 센다 |
| 그 주석이 줄바꿈을 품어도 (`#include /*` 다음 줄 `*/ <windows.h>`) | 센다 |
| `#` 뒤에 줄 주석이 오고 `include` 가 다음 줄 | 아니다 |

표준이 주석을 공백 한 칸으로 바꾸므로 지시자 안쪽의 주석은 **컴파일되는 포함**이다. 이것을
놓치면 게이트가 "모른다" 가 아니라 틀린 답을 낸다. 여러 줄 블록 주석이 든 지시자는
**`#` 이 있는 줄**로 보고한다. 대상 앞에서 줄이 끝나거나 블록 주석이 닫히지 않으면 지시자가
완성되지 않은 것이므로 판정하지 않는다.

**전처리기를 평가하지 않는다.** `#if 0` 으로 감싸면 통과하는 게이트는 우회 수단을 알려 주는
것과 같다. 그 대가로 죽은 코드 안의 OS 헤더도 위반으로 잡힌다. 그때는 그 코드를 지우거나
파일을 옮긴다.

## 판정하지 못하는 것

이것을 모르면 `VERDICT: pass` 를 "OS 헤더가 새는 곳이 없다" 로 읽게 된다. 그런 뜻이 아니다.

| 무엇 | 왜 |
|------|-----|
| `client/` 밖 (`tests/`, `tools/`) | ADR 0010 의 규칙이 클라이언트 원본에 대한 것이다 |
| `.cpp` `.hpp` 밖 (`.h`, `.c`, `.inl`, `CMakeLists.txt`) | 이 저장소는 두 확장자만 쓴다. 늘리려면 `SOURCE_SUFFIXES` 를 고친다 |
| 목록에 없는 헤더 | 위 "OS 헤더 목록은 허용 목록이 아니다" 참고 |
| 경로가 붙은 포함 (`<winrt/windows.h>`) | 이름 목록과 정확히 같을 때만 본다 |
| 줄 이어쓰기 (`#inc\` 다음 줄에 `lude`) | 놓친다 |
| 매크로 포함 (`#include OS_HEADER`) | 이름을 알 수 없다 |
| 포함의 사슬 | `a.hpp` 가 `b.hpp` 를 부르고 `b.hpp` 가 OS 헤더를 부르는 것은 각 파일의 자리로만 본다. 전이 포함을 따라가지 않는다 |
| UTF-8 이 아닌 파일 | 읽지 못하면 통과로 적지 않고 `파일:0:<읽지 못했다: ...>` 로 올린다 |

경로 비교는 **대소문자를 가린다.** `client/src/Platform/` 은 허용 자리가 아니다. 다만
Windows 의 파일 시스템은 대소문자를 가리지 않으므로 소문자 `platform/` 이 이미 있으면 그
자리에 `Platform/` 을 만들 수 없다. 이 검사는 Linux 체크아웃과 새로 만든 디렉터리에서 문다.

## 실패하면 무엇을 고치는가

| 나온 자리 | 할 일 |
|-----------|-------|
| `client/include/...` | 그 헤더에서 OS 헤더를 뺀다. OS 타입이 필요하면 전방 선언이나 불투명 핸들로 바꾸고 구현을 `client/src/platform/` 으로 내린다 |
| `client/src/...` (platform 밖) | 그 파일을 `client/src/platform/` 아래로 옮기거나, OS 를 쓰는 부분만 잘라 그리로 옮긴다 |
| `파일:0:<읽지 못했다: ...>` | 그 파일을 UTF-8 로 다시 저장한다 |

**게이트를 느슨하게 만들어 통과시키지 않는다.** 규칙을 바꿔야 한다면 ADR 을 먼저 고친다.

## 시험

```bash
cd tools/platformgate && python -m unittest test_platformgate
```

73건이다. 케이스 표는 `test_platformgate.py` 첫머리에 있고 **판정을 고치기 전에 케이스를
먼저 쓴다.** 일부러 판정하지 않는 것도 같은 이름의 케이스로 고정해 두었다.

케이스가 무엇을 지키는지는 변이로 확인했다. 주석 건너뛰기, 문자열과 원시 문자열 건너뛰기,
따옴표 형태의 포함, 지시자 안쪽의 주석 처리, 지시자를 끝내는 줄바꿈, 보고하는 줄 번호,
지시자 이름 대조, 경로 대소문자, 허용 자리 판정, 이름 목록, 읽지 못한 파일 처리를 하나씩
망가뜨렸다. **19건 중 17건에서 시험이 `FAILED` 로 바뀌었다.**

남은 2건은 시험의 빈자리가 아니라 **출력을 바꾸지 못하는 변이**다. 닫히지 않은 블록 주석은
파일 끝까지 가므로 그 뒤에서 대상을 찾을 일이 없고, `include` 바로 뒤의 낱말 경계는 그
자리에서 대상 대조가 어차피 실패한다. 둘 다 `platformgate.py` 의 그 자리에 적어 두었다.
