# Phase 1 코드를 바뀐 문서에 맞췄다

## 왜 했나

Phase 1 구현(`8ad10b9`)이 끝난 뒤 문서만 크게 바뀌었다. ADR 0006(무중계 스타, 한 방 5인),
0007(최소 GUI·Qt), 0008(후속 결정 아홉), 0009(방 호스트 임대), 0010(플랫폼 이음새)과 그 반영
커밋들이다. `architecture.md` 628줄, `concurrency.md` 535줄(새 문서), `control_plane.md` 508줄,
`protocol.md` 229줄이 그 사이에 움직였다. **Phase 2 로 넘어가기 전에 코드가 그 문서와 어긋나는
자리를 찾는 것**이 이 작업이다.

읽기 전용 감사 셋을 렌즈별로 돌렸다. 상수·카운터·로그 토큰, 기동 입력·CLI·콘솔 어휘,
구조·동시성이다. 등급은 넷으로 나눴다. `now`(지금 어긋남), `phaseN`(그 Phase 에서 만들 자리),
`doc`(코드가 맞고 문서가 낡음), `unknown`(확인 못 함).

**없는 것을 결함으로 세지 않는 것**을 판정 규칙에 먼저 박았다. Phase 1 범위는 소켓·로그·
카운터·타이머·이벤트 루프·콘솔이 전부이고 세션도 어댑터도 제어 평면도 아직 없는 것이 정상이다.

## 고친 것

| # | 무엇 | 어디 |
|---|------|------|
| 1 | `MAX_PEERS = 5` 가 코드 상수에 없었다 (ADR 0006 이 3장 상수 블록에 넣었다) | `protocol_constants.hpp` |
| 2 | recv 오류에서 카운터를 올리지 않았다. **문서가 이름을 주지 않아 문서를 먼저 고쳤다** | `concurrency.md` 3장, `counters.*`, `loop.cpp` |
| 3 | 카운터 이름 출처 주석에 `protocol.md` 5.7 이 빠져 있었다 | `counters.hpp`, `counters_test.cpp` |
| 4 | `SetConsoleCtrlHandler` 가 없어 Ctrl+C 와 창 닫기에서 종료 절차가 돌지 않았다 | `platform/console_ctrl.*` 신설 |
| 5 | 종료 바퀴가 `console_queue_dropped` 를 반영하기 전에 반환했다 | `loop.cpp` |
| 6 | 콘솔이 `raw500` 을 `raw` 로 받아 실제로 보냈다 | `loop.cpp` |
| 7 | `timer.hpp` 주석이 문서와 반대되는 인용을 하고 있었다 | `timer.hpp` |

**카운터 이름은 `rx_err_recv` 로 정했다.** `tx_err_send` 와 짝이고 오류 코드별로 나누지 않는다.
코드가 먼저 짓지 않고 `concurrency.md` 3장에 적은 뒤 코드가 따라갔다.

**4번은 `client/src/platform/win32/` 에 넣었다.** OS 헤더를 쓰므로
[ADR 0010](../../decisions/0010-플랫폼-이식-이음새.md)의 자리다. 핸들러 본체를 상태를 인자로
받는 함수로 떼어, 시험이 도는 코드와 실제로 도는 코드가 같게 했다.

## 문서만 고친 것

| 무엇 | 어떻게 |
|------|--------|
| 타이머 마감 부등호 | `protocol.md` 11장과 `concurrency.md` 4장이 "엄격 부등호" 였는데 코드는 `deadline <= now` 다. **코드가 맞다.** 엄격으로 두면 마감이 정확히 지금인 바퀴에서 타이머는 안 돌고 `next_timeout` 은 0 을 돌려주어 1ms 동안 같은 바퀴를 반복한다 |
| `raw` 의 송신 잔량 | `concurrency.md` 3장이 `raw` 를 나눠 보낸다고 적었으나 `architecture.md` 3.5 는 1개 송신이다. 잔량이 없다 |
| 모듈 표와 트리 | `architecture.md` 3.1 과 10장에 구현된 모듈이 빠져 있었다. `loop`, `timer`, `console`, `log`, `counters`, `args`, `hash`, `platform/wait`, `platform/console_ctrl` 을 넣었다 |
| 로비가 받는 입력 | [ADR 0008](../../decisions/0008-스타-토폴로지-후속-결정.md) 결정 8 이 `architecture.md` 3.5 로 위임했는데 그 서술이 없다. `roadmap.md` Phase 3 착수 전 항목으로 걸었다. 정하지 않으면 `leave` 가 프로세스를 못 쓰게 만드는 명령이 된다 |
| `TimerSet` 의 시점 | `plan.md` 가 Phase 4 로 적었는데 **Phase 2 가 먼저 부른다.** STUN 이 서버별 재전송과 마감을 걸고 응답에 취소해야 하며 두 서버에 동시 질의한다 |
| 제어 신호 계약 둘 | 핸들러 설치 실패는 기동 실패다. 표에 없는 신호는 처리하지 않고 다음 핸들러에 넘긴다. **코드가 먼저 정한 것을 문서로 옮겼다** |

## Phase 2 가 먼저 부르는 자리 (이번에 고치지 않았다)

감사 셋 중 구조 렌즈가 낸 것이다. Phase 2 작업 자체이므로 미리 하지 않는다.

- `TimerSet` 에 키·제거·일회성이 없다
- `EventLoop` 에 송신 이음새가 없다. 송신은 `--peer` 에 묶인 비공개 `send_raw` 하나뿐인데
  `protocol.md` 6장은 STUN 이 같은 소켓을 루프를 거쳐 쓰라고 못박는다
- `drain_udp` 에 출발지 위생과 분류가 없다
- STUN 이름의 기동 시 해석과 `--stun` 목록 1개일 때의 경고가 없다

## 크로스 모델 리뷰 (Codex)

**도구가 한 번 실패했다.** `codex` CLI 가 모델 목록을 새로 읽다가
`unknown variant 'max'` 로 죽어 산출물 파일을 만들지 않았다. 종료 코드는 0 이었다.
`CLAUDE.md` 의 "리뷰가 돌고 있다는 것을 산출물 파일로만 판정한다" 가 그대로 값을 했다.
다시 돌려 얻었다.

### 반영

| 지적 | 어떻게 |
|------|--------|
| **`signal_cleanup_done()` 이 `try` 블록 안에 있어 소멸자보다 먼저 신호한다.** 창 닫기 핸들러가 그것을 보고 반환하면 OS 가 소멸자를 돌기 전에 프로세스를 끝낸다 | 반영. 신호를 `try`/`catch` 밖으로 뺐다. **Phase 1 의 손해는 작지만 Phase 6 에서 어댑터와 라우트가 남는다.** 그 이유를 주석에 적었다 |
| `architecture.md` 의 트리와 모듈 표에 `console_ctrl` 이 빠졌다 | 반영. 둘 다 넣었다. **같은 커밋에서 내가 쓴 문장이 같은 커밋의 코드에 뒤졌다** |

### 남긴 위험

- **`SetConsoleCtrlHandler` 등록과 OS 값 전달 경로에는 시험이 없다.** 간접 증거만 있다.
  설치 실패를 기동 실패로 다루므로 e2e 의 클라이언트가 전부 기동하면 설치는 된 것이다
- **3초 상한은 런타임으로 확인되지 않았다.** 값은 컴파일 시점 단언으로, 기다림 경로는 150ms 로 돈다
- `GenerateConsoleCtrlEvent` 로 실제 경로를 돌리지 않았다. 그 호출은 프로세스 그룹으로 가서
  같은 콘솔의 하네스까지 받고, `CTRL_CLOSE_EVENT` 는 애초에 만들 수 없다. 정작 기다림이
  필요한 신호가 그쪽이다
- 핸들 둘을 일부러 닫지 않는다. 핸들러가 `main` 종료 중에도 돌 수 있다

## 이번에 확인한 것

- **리뷰만 잡을 수 있는 자리가 있다.** 정리 완료 신호의 순서는 소멸자와 OS 의 프로세스 종료가
  얽혀 단위 시험으로 관측할 수단이 없다. 변이 시험으로도 안 잡힌다
- **리뷰어에게 무엇을 볼지 지목한 것이 값을 했다.** "정리가 끝나기 전에 완료를 신호할 수
  있는가" 를 프롬프트에 넣어서 나왔다
- **하위 에이전트가 지시보다 나은 선택을 했다.** 종료 시 카운터 반영을 "`emit_all` 직전" 으로
  지시했는데 루프 안 두 출구에 넣었다. `WAIT_FAILED` 출구도 같은 결함이었고, 루프 안에 두면
  `run_once()` 로 시험이 그 경로를 판정할 수 있다
