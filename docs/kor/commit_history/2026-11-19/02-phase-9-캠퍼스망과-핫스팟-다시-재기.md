# Phase 9 손실 집계를 고친 빌드로 캠퍼스망 대 가정망과 가정망 대 핫스팟 다시 재기

## 왜 했나

[ADR 0041](../../decisions/0041-손실-집계는-상대의-연결-신호부터-센다.md) 로 손실 집계를 고쳤다. `field-test/required-test.md` 가 Phase 9 묶음을 이 빌드로 다시 재라고 한다. 소유자가 학교에서 캠퍼스망 대 가정망과 가정망 대 핫스팟 실행을 지시했다.

## 구성

시행 방법은 [2026-11-17 첫 실측](../2026-11-17/05-phase-9-상대-없는-검증과-첫-실측.md)과 같다. 같은 기동 인자, 같은 시행 스크립트다. 다른 것만 적는다.

| 무엇 | 값 |
|------|-----|
| 빌드 | 둘 다 커밋 `6e6f5e4` 의 Release 콘솔. 이 PC 는 `Release-p9` 빌드 트리를 다시 빌드했다. `mere-galaxy` 는 소스를 `git archive` 로 바꾸고 다시 빌드했다 |
| `mere-galaxy` 의 망 | 세 묶음 모두 집 Wi-Fi, Comcast. Wi-Fi 절전은 꺼져 있었다(이슈 0001) |
| 이 PC 의 망, 캠퍼스망 대 가정망 | 학교 유선 LAN. 핫스팟 Wi-Fi 에도 붙어 있었고 기본 경로는 유선 LAN 이었다(경로 우선값 25 대 50). 공인 주소는 2026-11-18 묶음과 같았다 |
| 이 PC 의 망, 가정망 대 핫스팟 | 소유자 휴대폰의 핫스팟, T-Mobile. 유선 LAN 을 뽑아 기본 경로가 핫스팟 하나였다 |
| 역할 | `mere-galaxy` 가 호스트, 이 PC 가 플레이어다. 가정망 대 핫스팟에서 핫스팟 쪽이 2026-11-17 과 반대다. 그때는 `mere-galaxy` 가 핫스팟에 있었다 |
| 묶음 이름 | `batches.txt` 에 `campus-home-1119` 두 묶음과 `home-hotspot-1119` 로 적었다. 옛 집계의 묶음과 섞이지 않게 이름을 나눴다 |
| 기록 | git 이 무시하는 `field-test/2026-11-19/` 의 `campus-home/`, `campus-home2/`, `home-hotspot/` |

## 결과

아래 RTT 는 이 PC 의 로그에서 본 예비 값이다. `experiments.md` 의 숫자는 분석 도구가 테이블에서 낸 값을 쓴다.

| 묶음 | 결과 | 쓴 경로 | 이 PC 의 RTT 표본 |
|------|------|---------|-------------------|
| 캠퍼스망 대 가정망, 첫째 | 9/10 `CONNECTED`, 1회 `HOLE_PUNCH_TIMEOUT` | 연결된 9회 모두 공인 주소 | n=54, 중앙값 22.1ms, 사분위 범위 19.0~27.2ms |
| 캠퍼스망 대 가정망, 둘째 | 10/10 `CONNECTED` | 10회 모두 공인 주소 | n=58, 중앙값 23.7ms, 사분위 범위 18.8~34.2ms |
| 가정망(`mere-galaxy`) 대 핫스팟(이 PC) | 10/10 `CONNECTED` | 10회 모두 공인 주소 | n=55, 중앙값 200.7ms, 사분위 범위 147.0~362.8ms |

- 업로드 실패는 세 묶음, 두 기기 모두 0 이다. 두 기기의 `telemetry_upload_failed` 카운터가 모든 시행에서 0 이다
- `mere-galaxy` 는 모든 시행에서 STUN 서버 둘에서 같은 공인 포트를 받았다. 이 PC 도 한 시행을 빼고 그랬다

### 캠퍼스망 대 가정망 첫째 묶음의 5번 시행

- 이 PC 가 STUN 서버 둘에서 다른 공인 포트를 받았다. Cloudflare 가 `32885`, Google 이 `32884` 다. 학교 NAT 가 목적지마다 다른 매핑을 줬을 수도 있고, 두 요청 사이에 매핑을 바꿨을 수도 있다. 이 기록으로는 가르지 못한다
- 두 기기 모두 `PUNCHING` 에서 `FAILED` 로 갔다. 두 기기 모두 `session.endpoint` 가 없다. 상대의 어느 후보 주소도 확인하지 못했다. 두 기기의 `rx_datagrams` 는 3 이다
- 같은 망의 나머지 19회와 2026-11-18 묶음의 10회는 두 서버가 같은 포트를 줬다
- 실제 망에서 난 실패다. 목적지 의존 매핑의 에뮬레이션([ADR 0040](../../decisions/0040-목적지-의존-매핑-에뮬레이션.md))과 따로 다룬다

### 가정망 대 핫스팟의 RTT

2026-11-17 묶음(중앙값 111.0ms, 사분위 범위 95.4~132.9ms)보다 높고 넓다. 그 묶음과 장소, 핫스팟에 붙은 기기, 시간대가 다르다. 소유자는 묶음 동안 휴대폰으로 동영상을 보고 있었다고 했다. 무엇이 원인인지는 이 기록으로 가르지 못한다.
