# Phase 4 3차 G: 후보 밖 경로 검증과 무검증 목적지 공통 예산

## 왜 했나

Phase 4 3차의 첫 조각이다. 2차는 후보 집합 밖 출발지를 학습하지 않고 회신을 예산 없이 보내는 자리로 남겼다.
`protocol.md` 10.4 (c) 경로 검증과 9.4 무검증 목적지 공통 예산을 그 자리에 넣었다.

## 중요한 결정

**문서 공백 셋은 문서를 먼저 고쳤다.** 기존 규칙을 함께 읽은 결과를 적었다.

| 공백 | 정한 것 | 근거 |
|------|---------|------|
| probe nonce echo 의 epoch | 고정값과 다르면 `drop_stale_epoch`. 검증 `HELLO` 는 epoch 고정 뒤에만 나가므로 미고정인 경우는 없다 | 8.2 시도 nonce echo 행과 같은 이유. 다른 시도의 증거로 이 시도의 `peer_endpoint` 를 바꾸지 않는다 |
| echo 가 (b) 를 만족해야 전환하는가 | 그렇다. 재정렬로 수용된 echo 는 전환하지 않는다. 주소를 따로 기억하지 않는다 | 10.4 머리의 학습 정의가 (a)(b)(c) 모두를 요구한다 |
| `path_probe_failed` 가 세는 것 | 6번에서만 오른다. echo 가 온 경로와 세션이 먼저 끝난 경로는 세지 않는다 | 10.4 6번 |

**문서 규칙과 어긋나지 않는 작은 것은 코드가 정했다.** `session.hpp` 의 "이 코드가 정한 것" 표에 근거와 함께 적었다.

- 잠정 경로를 올리는 계기는 (a)(b) 를 만족하고 (c) 만 못 한 패킷과 재협상을 일으킨 `HELLO` 다. `CLOSE` 는 올리지 않는다
- 이미 잠정 경로인 주소는 다시 올리지 않는다. `roadmap.md` 의 토큰 셈("두 번째 발부터는 토큰 하나")과 맞는다
- 회신이 등록보다 먼저 토큰을 쓴다. 9.4 `HELLO` 행의 순서다
- 버킷은 1ms 마다 1/1000 토큰 5개씩 채운다. 처음에는 가득 차 있다
- 잠정 경로 자리의 만료는 `next_deadline` 에 들지만 `timer.tick` 을 내지 않는다(11장 만료 값 표)
- 재협상은 잠정 경로 표와 예산을 되돌리지 않는다(9.5 3번 목록에 없다)
- probe nonce 를 뽑지 못하면 등록하지 않고 토큰도 쓰지 않는다
