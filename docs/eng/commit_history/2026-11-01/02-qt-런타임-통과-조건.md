# Close the Qt runtime pass criterion with a module-list check

## Why

The pass criterion of `windows-prereq.md` section 4 Qt runtime was "the GUI comes up from the distribution alone on a target PC with no separate Qt or VC++ runtime
installation". The distribution came up on a friend's PC, but whether that PC lacked the runtimes was not checked. Both are installed on the development machine.

We weighed the ways to get a clean Windows.

| Alternative | Judgement |
|------|------|
| Windows Sandbox | Not available. The development machine is Windows Home (`EditionID = Core`) and has no `WindowsSandbox.exe`. It has no Hyper-V either |
| EC2 Windows instance | Possible. But it is Windows Server, whether the AMI carries the VC++ redistributable has to be checked after launch, and it costs money and cleanup |
| Briefly deleting the VC++ DLLs in `System32` on the development machine | Rejected. Other programs use those files, and they cannot be deleted while in use. Copies under Visual Studio, Qt, and similar places can fill in through `PATH`, so deleting them does not give a clean environment |
| Reading the module list of a process started from the distribution | Chosen. The risk to stop is an installed runtime silently filling in a DLL missing from the distribution. Seeing which path each module was loaded from shows that directly. Plugins loaded at run time are caught too, and the system is not touched |

The repository owner approved changing the pass criterion to the module-list check.

## What changed

| What | Where |
|------|-------|
| The pass criterion is now a module-list check. Every module loaded from outside the distribution must have a valid signature with signer `CN=Microsoft Windows`. The check command, why an administrator shell is needed, when not to decide, the result, and the rationale are written | `windows-prereq.md` section 4 Qt runtime |
| The Qt subsection and section 4 go from "partly measured" to "measured". The section counts in section 0 become 8 measured and 3 partly measured | `windows-prereq.md` sections 0 and 4 |
| The two places saying "checking on a PC without the runtimes remains" are removed | `windows-prereq.md` sections 0 and 14 |
| The Qt runtime item is removed from the remaining work and the numbering closed up | `plan.md` |

- It classifies by signer, not by path or name. The VC++ redistributable installs into `System32` (the development machine has `C:\Windows\System32\vcruntime140.dll` and `msvcp140.dll`), and the VC++ and Qt file names to filter cannot be listed completely. The first draft was "under `C:\Windows` + a name list"; it changed after a review finding (below)
- A module that is not a Windows component, such as a DLL injected by another program, fails the check. That errs toward a false failure, not a false pass, so it was left as is
- The fact that it was not run on a PC without the Qt and VC++ runtimes stays in the status line

## Verification

| What | Result |
|------|--------|
| Distribution used | `C:\me\build\test\gui-dist`. Without `logs` and `records`, 16 files and 30,155,983 bytes, matching the table in section 4 |
| Module list | The owner started the distribution's `sangtachi_gui.exe` and ran the check command in an administrator PowerShell. 100 modules |
| Modules from the distribution folder | 12. `sangtachi_gui.exe`, `wintun.dll`, 5 Qt, 5 VC++, the same as the executables and DLLs in the section 4 table |
| Modules outside the distribution | The other 88. All under `C:\Windows`. `Get-AuthenticodeSignature` (PowerShell 7) was run on those paths. All 88 are `Valid` and signed by `CN=Microsoft Windows`. Counted by script |
| Counterexamples | The same check on this machine's `System32\vcruntime140.dll` and `System32\msvcp140.dll` gives `CN=Microsoft Windows Software Compatibility Publisher`, and on `Qt6Core.dll` gives `CN=The QT Company Oy`. All three fall on the failing side |
| `docgate.py`, `--claims` | `VERDICT: pass` |

Codex (`gpt-6.1-sol`). The verdict-soundness (A) and Korean/English and record-consistency (B) lenses ran in one pass.

| Finding | Disposition |
