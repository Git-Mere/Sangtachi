# Readability Cleanup of the 7 Living Documents

## What Was Done

After many review rounds the living documents became hard for people to read. Six rules were
decided and applied to the seven documents in `docs/kor`. The record folders (`audit-history/`,
`commit_history/`, `decisions/`) are not in scope.

| Rule | Content |
|------|------|
| R1 | Split rules and rationale into layers. One or two sentences go in a `> **Why.**` block; a paragraph or more moves to a rationale section at the end of the chapter |
| R2 | Inside one section, link the same document only on first mention. From the second time on, use plain text |
| R3 | Attach the real heading title of the section to a numeric reference. Parenthesized citations (`(9.3)`) are not in scope |
| R4 | One bold per paragraph. An identifier label at the head of a paragraph is not counted |
| R5 | Delete progress narration. If current specification is mixed in, keep only the specification |
| R6 | Do not put criteria, procedure, rationale, and counterexamples in one bullet |

## Verification

Scripts did what can be counted. It was not left to the reviewer.

- Instrument: counts duplicate links, excess-bold blocks, unnamed numeric references, long lines
- Content preservation check: compares against the `HEAD` version and reports code spans,
  identifiers, numbers, and link paths that disappeared. **Mutation testing showed its limit.**
  It caught the deletion of a paragraph containing a code span and the deletion of 1 number, but it
  **did not catch** the deletion of a prose sentence with no code, number, or identifier. So it was
  not used as the verdict for content preservation
- `docgate.py`: 0 `link` findings. `mirror` and `parity` are normal because the English mirror lags
- Move ledger: what was moved or deleted is recorded as a table per document. 294 table rows in
  total. Kept outside the repo

## What Was Experienced This Time

- **Subagents repeatedly made only a plan and never wrote the edits to the file.** Four times for
  the `roadmap.md` owner, once for the `architecture.md` owner. They collected edits in memory and
  tried to write at the end, but the turn ended before that. Progress came after the instruction
  "write to the file right after fixing each section and check with `git diff --stat`"
- **A subagent and I edited the same file at the same time.** The owner noticed it and reported it.
  That side reads the whole file and writes it back, so with worse timing my edits would have been
  lost. The result was safe, but the check was done by hand
- **The instrument was wrong twice.** At first it took IP addresses (`10.100.0.1`) and version
  numbers (`Python 3.11`) as dead section references, and the particle verdict read the "가" of
  `2.5 가상 IP 풀` as a particle. Both were fixed, and items that cannot be judged were moved down
  to a reference list
- **The content preservation check was also built wrong once.** Joining the whole document into one
  line to reconnect code spans broken by line breaks produced 44 false positives. It was fixed to
  join per paragraph
