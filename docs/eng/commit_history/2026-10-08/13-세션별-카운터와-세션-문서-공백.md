# Per-Session Counters (ADR 0022) and Three Document Gaps of the Session Implementation

## Why

The wave 2 E+F subagent asked about five document gaps while writing the session state machine. Four matched a literal reading of the
existing text or had almost no effect on behavior, so they were taken as proposed. For the counters, the repository owner chose
per-session tables, wanting to check afterwards which peer had a bad connection. Documents are fixed first (`CLAUDE.md`).

## What changed

| Gap | Decision | Where |
|-----|----------|-------|
| Are counter tables per session | A process table and per-session tables. The place of the increment decides the scope. Session lines carry `peer_id`, `peer_name`. When they are emitted | `architecture.md` section 9, ADR 0022 |
| Order of `drop_terminal_state` and check 8 of 8.1 | After 8.1 checks 1-8, before 8.2. A finished session still counts as "a peer that has a session" for check 7 | `protocol.md` section 8 head, 9.4.1 |
| One retired list per process | One. A host's sessions share it | `protocol.md` 4.3 |
| Steps 7 and 10 of renegotiation before the punch starts | The two timers start at the actual punch start | `protocol.md` 9.5 |
| RTT clock | As documented (`concurrency.md` section 4, QPC). No document change | |
| Stale spots found by review | The counters row of the lobby table, the renegotiation cells of the section 11 timer table, "counters" in the 9.4.1 rationale, how `roadmap.md` Phase 4 reads counters and the rationale of the retired-list test | `concurrency.md` section 7, `protocol.md` 9.4.1 and section 11, `roadmap.md` Phase 4 |

## Cross-model review

Codex, told to find sentences in `architecture.md`, `concurrency.md`, `protocol.md`, and `roadmap.md` that contradict the changed rules.

| Finding | Disposition |
|---------|-------------|
| blocker. The lobby table in `concurrency.md` section 7 only says counters are per process and never reset, which contradicts session tables going away with their sessions | Applied. The process table and session tables are written separately |
| blocker. The new 9.5 paragraph called the pre-punch interval `PUNCHING`, but step 7 makes it `HANDSHAKING` when step 6 succeeds | Applied. It now says "the interval of waiting for the scheduled time" and that the state follows step 7 |
| warn. The section 11 timer table lists starting `HELLO` retransmission and resetting the punch deadline on renegotiation without the condition | Applied. Both cells state the pre-punch exception |
| warn. Counter checks in `roadmap.md` identify counters by name only | Applied. A rule to read by scope is written once at the head of Phase 4 verification |
| warn. With one retired list per process, several host sessions can produce 17 entries, so the "cannot be produced" rationale was wrong | Applied. The rationale now says "the test is heavy", and an item checks that there is one list |
| warn. The session bound in the ADR left out sessions kept in a terminal state | Applied. Live and kept sessions are stated separately |
| warn. "counters already cleaned up" in the 9.4.1 rationale contradicts keeping session tables during retention | Applied. Changed to "session timers" |

Round 2 (confirming those fixes) returned `LGTM - no blockers`.
