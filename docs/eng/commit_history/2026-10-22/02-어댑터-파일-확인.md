# Make startup failure clear when adapter files are missing

## Why

The repository owner gave a friend only `sangtachi_client.exe`, and the friend's log ended with `ERROR adapter.error reason=subnet
verdict=unknown exit_code=4294770688`. That exit code is `0xFFFD0000`, which Windows PowerShell returns when the `-File` script does not
exist (reproduced on this PC with a missing path). `Test-SubnetOverlap.ps1` was not next to the executable. The log alone did not say why.

## What changed

| What | Where |
|------|------|
| First step of the adapter startup stage. Look for `wintun.dll`, `Test-SubnetOverlap.ps1` and `Initialize-FirewallRules.ps1` next to the executable and put every missing one in one `adapter.error reason=missing_file file=...` line. When stdout is a console, one guide line naming the files to keep in the same folder | `client/src/main.cpp`, `platform/win32/tun.cpp` |
| Tests. All three in a folder with only the executable, the one in a folder missing one script | `scripts/cli-check.ps1` |
| Documents. First row of the chapter 7 Adapter lifetime table, the 3.5 lobby guide table, the chapter 9 `adapter.error` fields | `architecture.md` (mirror included) |

Outside the repo, `C:\me\build\update-latest.ps1` now also makes `latest_build\Sangtachi.zip`. It holds only the four files needed to run and `VERSION.txt`.

## Key decisions

- **It comes before the elevation check.** Without the files the client cannot start even when elevated. The real reason shows first even in a
  non-elevated shell
- **All missing files go in one line.** The user does not have to fix and restart one file at a time
- **`--no-adapter` does not check.** That start does not use the three files
