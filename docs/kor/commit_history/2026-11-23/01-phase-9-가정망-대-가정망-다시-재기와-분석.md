# Phase 9 가정망 대 가정망 다시 재기와 다시 잰 묶음의 분석

## 왜 했나

[ADR 0041](../../decisions/0041-손실-집계는-상대의-연결-신호부터-센다.md) 로 손실 집계를 고친 빌드로 Phase 9 묶음을 다시 재는 일의 마지막 묶음이다. 나머지 묶음은 [2026-11-19 기록](../2026-11-19/03-phase-9-동일-lan-에뮬레이션-핫스팟-다시-재기.md)까지 다시 쟀다. 이어서 소유자가 AWS CloudShell 에서 분석 도구를 `--save` 로 돌려 결과를 넘겼다.

## 구성

시행 방법은 [2026-11-18 가정망 대 가정망](../2026-11-18/03-phase-9-가정망-대-가정망-실측과-에뮬레이션-결정.md)과 같다. 다른 것만 적는다.

| 무엇 | 값 |
|------|-----|
| 빌드 | 둘 다 커밋 `6e6f5e4` 의 Windows Release 콘솔이다. 친구에게 준 zip 의 실행 파일은 이 PC 의 `Release-p9` 실행 파일과 SHA-256 이 같다 |
| 역할 | 친구 PC(친구 집 가정망)가 호스트, 이 PC(집 Wi-Fi)가 플레이어다. 2026-11-18 에는 `mere-galaxy` 가 플레이어였다. 소유자 결정으로 이 PC 를 썼다 |
| 이 PC 의 망 | 시행 전 `ipconfig` 에서 Wi-Fi 어댑터에 사설 주소가 있었다. 시행 스크립트가 적은 공인 주소의 AS 는 Comcast 다 |
| 호스트 | 친구가 한 번 띄워 10회 내내 두었다. 플레이어만 시행마다 새로 띄웠다. 2026-11-18 과 같은 까닭으로 이 묶음의 수립 시간은 시행마다 호스트를 새로 띄운 묶음과 비교하지 않는다 |
| 시행 스크립트 | git 이 무시하는 `.prime/p9-field/field_pc_join.py`. `field_join.py` 와 같은 절차를 이 PC 에서 직접 돈다 |
| Tailscale | 이 PC 에서 켜져 있었다 |
| 기록 | git 이 무시하는 `field-test/2026-11-23/home-home/`. 친구의 표준 오류 로그, 로컬 기록 파일, `logs\` 사본은 그 아래 `friend/` 다. 묶음 이름은 `home-home-1123` 이다 |

## 결과

아래 RTT 는 이 PC 의 로그에서 본 예비 값이다.

| 환경 | 결과 | 쓴 경로 | 이 PC 의 RTT 표본 |
|------|------|---------|-------------------|
| 가정망(이 PC) 대 친구 집 가정망 | 10/10 `CONNECTED` | 10회 모두 공인 주소 | n=60, 중앙값 25.3ms, 사분위 범위 19.3~63.1ms |

- 업로드 실패는 두 기기 모두 0 이다. 친구 쪽 `telemetry_queue_dropped` 도 0 이다
- 두 기기의 `session.loss` 줄은 모두 `lost=0` 이다. 이 PC 20줄, 친구 11줄이다
- 이 PC 는 10회 모두 STUN 서버 둘에서 같은 공인 포트를 받았다. 친구 호스트는 STUN 을 한 번 돌았고 두 서버의 포트가 같았다
- 친구 쪽 로컬 기록은 `establish` 10건이 모두 `OK`, `end` 10건이 모두 `CLOSED` 다

## 다시 잰 묶음의 분석

CloudShell 에서 `--save` 로 돌렸다. 레코드 460개다. 이 PC 에서 `--load` 로 같은 레코드를 다시 돌려 출력이 줄 끝(CRLF) 말고는 같았다.

**옛 집계의 묶음을 묶음 파일에서 뺐다.** 소유자 결정이다. 2026-11-17, 18 의 `same-lan`, `home-hotspot`, `campus-home`, `home-home`, `emu-dep-map` 이다. 두면 실제 환경 합산에 옛 손실이 섞인다. `ctl-punch` 와 `ctl-stun` 은 다시 재지 않았으므로 남겼다. 고치기 전 파일은 git 이 무시하는 `tools/tm-analysis/local/batches-before-1123.txt` 에 두었다.

- 가정망 대 가정망의 플레이어 수립 시간 중앙값은 10945.5ms 다. 옛 집계의 2026-11-18 묶음은 9206.5ms 였다. 두 묶음 모두 호스트를 계속 두었다. 까닭은 보지 않았다
- 11-19, 11-23 의 CloudWatch 1분 해상도 값은 받지 않았다
