# 6-5 바이트 대조 통과, Phase 7 닫음

## 왜 했나

`roadmap.md` Phase 7 검증의 두 기기 항목 가운데 바이트 카운터와 캡처 대조(시험 6-5)만 남아 있었다. 2026-10-22 실행은
판정하지 못했고 [ADR 0032](../../decisions/0032-바이트-대조를-파일-전송으로-한다.md) 가 대조를 64 MiB 전송으로, 망을 두 PC 의
사설 서브넷이 겹치지 않게 바꿨다. 2026-10-25 에 그 조건으로 다시 쟀다.

## 결과

A 를 휴대폰 핫스팟(`10.205.170.0/24`)에, B 를 친구 집 Wi-Fi(`10.0.0.0/24`)에 붙였다. **통과다.**

| 확인 | 결과 |
|------|------|
| 64 MiB 전송 | `VERDICT: pass`, 97.1초, SHA-256 일치 |
| dumpcap 유실 | 0 |
| `netstat` 수신 오류 | 0 → 0 |
| `tx_bytes`, `tx_datagrams` | 1,615,582 / 26,343. 캡처와 같다 |
| `rx_bytes`, `rx_datagrams` | 70,147,217 / 49,608. 캡처와 같다 |

캡처에 B 의 사설 후보로 간 `HELLO` 두 개가 있다. A 가 보낸 터널 패킷의 순번은 빠짐없이 캡처에 있다. 두 대역이 달라 그
`HELLO` 가 게이트웨이로 나갔다. ADR 0032 의 가설과 맞는다.

같은 날 앞선 한 실행은 A 가 집 Wi-Fi 에 붙어 망 조건 밖이었다. 그 원본과 보고서는 버렸다. 그 실행에서 송신 카운터가 캡처보다
120바이트 많았고, 헤더 순번으로 보면 빠진 셋이 B 의 사설 후보로 간 `HELLO` 였다.

ADR 0032 "결과" 는 핫스팟에서도 차이가 남으면 그 결정을 다시 연다고 했다. 차이가 남지 않았으므로 다시 열지 않는다.
