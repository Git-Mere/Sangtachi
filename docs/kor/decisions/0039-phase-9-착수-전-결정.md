# 0039. Phase 9 착수 전 결정

- 상태: 채택
- 날짜: 2026-11-16
- 관련: [`../roadmap.md`](../roadmap.md) Phase 9, [`../architecture.md`](../architecture.md) 3.4·3.5·6.3·9장, [`../concurrency.md`](../concurrency.md) 4장·6장, [`../protocol.md`](../protocol.md) 4.5, [`../control_plane.md`](../control_plane.md) 7.6, [`../spec.md`](../spec.md) FR-14·NFR-10·C-3, [ADR 0001](0001-직접-연결-대비책-미도입.md), [ADR 0003](0003-텔레메트리-서비스-분리.md), [ADR 0004](0004-상태-저장소-dynamodb.md)

## 맥락

`roadmap.md` Phase 9 는 착수 전에 정할 것을 둘 둔다. 텔레메트리 서비스의 스펙(수집 스키마, 인증, 업로드 주기, 보존 기간,
DynamoDB 테이블)과 한 인스턴스 안의 자원 격리다. 집계와 그래프에 대해서도 무엇을 올리는지, 환경을 어떻게 표시하는지, 그래프
라이브러리, FR-14 문구를 정하라고 한다. 문서를 읽으면서 빈칸이 더 나왔다.

- 클라이언트가 텔레메트리 서비스 주소를 받는 길이 없다. `architecture.md` 3.5 는 "Phase 9" 라고만 적었다
- `architecture.md` 3.4 는 받은 식별자의 대조 방법을 `roadmap.md` Phase 9 가 갖는다고 적었지만 그 절에 없다. 제어 평면 항목은
  방이 만료되고 하루 뒤 지워지므로 분석 시점에는 대조할 상대가 남지 않는다
- `protocol.md` 4.5 는 손실률을 10초 주기로 올린다고 적었다. 업로드 주기와 따로 정해진 값이다
- DynamoDB 의 무료 용량(RCU 25, WCU 25)은 계정 단위다. 제어 평면 테이블이 그것을 다 쓰고 있다

다른 서비스가 같은 종류의 데이터를 어떻게 다루는지 공식 문서로 확인했다. Teams 의 통화 품질 기록과 Twilio 의 통화 요약은 통화가
끝난 뒤 만들어진다. Sentry, Azure Application Insights, OpenTelemetry 는 실행 중에 몇십 초 단위로 묶어 보낸다. 실시간 수집은
진행 중인 통화를 운영자가 보는 기능으로 따로 둔다. 이 프로젝트의 목적은 사후 분석이다.

## 결정

저장소 소유자가 자리마다 아래를 골랐다.

| 자리 | 고른 것 |
|------|---------|
| 보내는 때 | 시도마다 수립이 끝날 때 한 번, `CONNECTED` 동안 60초마다, 세션이 끝날 때 한 번. 로비에서는 보내지 않는다 |
| 주기 레코드의 값 | 그 구간의 값만 싣는다. RTT 는 구간의 표본 그대로, 손실과 전송량은 구간의 차이다. 누적값을 매번 보내는 안은 버렸다 |
| 세션 끝 레코드 | 마지막 구간의 값과 세션 전체 합계를 싣는다 |
| 보내는 쪽 | 호스트와 플레이어 둘 다 보낸다. 호스트는 플레이어마다 세션이 따로라 레코드도 따로다 |
| 재시도 | 하지 않는다. 지금 계약(NFR-3)을 그대로 둔다 |
| 종료 때의 마지막 업로드 | 지금 join 상한(2초) 안에서만 기다린다. 상한을 늘리지 않는다 |
| 레코드 묶음 키 | 프로세스가 기동할 때 만든 무작위 값, 시도 번호, 전송 순번. 서버는 받은 것을 더하기만 한다 |
| 지터 | RFC 3550 의 평활 지터 식을 연속 RTT 표본의 차에 적용한다. 원래 식은 단방향 지연의 차에 쓰는 것이라 변형이다 |
| 주소와 망 정보 | 올리지 않는다. 공인 주소, 후보, 망 지문, 망 종류 모두다. ADR 0001 따라야 할 조치 2번의 "되돌릴 수 없는 가명" 대신 "올리지 않음" 을 택했다 |
| 표시 이름 | 올리지 않는다. 사람과 기기는 `peer_id` 와 프로세스 값으로 가른다 |
| 기기 식별자 | 두지 않는다. 프로세스를 다시 켜면 새 값이다 |
| NAT 관측값 | 로컬 주소와 공인 주소가 다른가, 두 STUN 서버가 같은 엔드포인트를 봤는가, 상대와 같은 공인 IP 인가. 셋 다 bool 이다 |
| 빌드 정보 | OS, GUI 인가 콘솔인가, 시험 빌드인가. 빌드 버전 문자열은 지금 클라이언트에 없어서 싣지 않는다 |
| 시행 환경 | 텔레메트리에 싣지 않는다. 실측한 사람이 묶음마다 UTC 시간 범위와 환경을 공개하지 않는 로컬 파일에 적고 분석 스크립트가 시간대로 가른다. [`experiments.md`](../experiments.md) 에는 ADR 0001 대로 날짜까지만 싣는다 |
| 동의 | 동의 창을 두지 않는다. 수집 항목을 README 와 배포물 안내에 적는다. 텔레메트리 서비스의 로그에는 출발지 IP 를 남기지 않는다 |
| 서비스 주소 | 기동 인자 `--telemetry` 와 빌드 기본값. 포트 8001 |
| 전송 형식 | 제어 평면의 HTTP 부분집합과 JSON 을 그대로 쓴다. 연산은 `report` 하나다 |
| 인증 | 두지 않는다. 입력 상한으로 막는다 |
| 입력 상한 | 헤더 2048 바이트, 본문 4096 바이트, 출발지 IP 마다 토큰 30개를 분당 30개로 채움, 서버 전체 초당 5건, 동시 연결 32, 읽기 5초 |
| 식별자 대조 | 받을 때 제어 평면 테이블의 `ROOM` 항목을 한 번 읽어 레코드에 결과를 붙인다. 거부하지 않는다 |
| 저장 | 테이블을 따로 둔다. 보고서를 낼 때까지 지우지 않는다 |
| 용량 | 계정의 무료 용량을 나눈다. 제어 평면 테이블을 RCU 20, WCU 20 으로 줄이고 텔레메트리 테이블을 RCU 5, WCU 5 로 둔다 |
| IAM | 같은 인스턴스 역할에 텔레메트리 권한을 더한다. 인스턴스에는 역할을 하나만 붙일 수 있다 |
| 자원 격리 | systemd 자원 제한(`MemoryMax=256M`, `CPUQuota=20%`, `IOWeight=50`), journald 전체 200MB, 위 입력 상한 |
| 배포 | 별도 systemd 유닛. `tools/cp-deploy` 를 넓혀 대상을 고르게 한다 |
| 집계와 그래프 | Amazon CloudWatch. 서비스가 커스텀 지표를 넣고 소유자가 대시보드에서 본다. 커스텀 지표는 무료 한도인 10개만 쓰고 차원을 두지 않는다 |
| 정확한 표 | 시도 수, Wilson 구간, 실패 코드별 개수, 매핑 거동별 비교는 `tools/` 의 분석 스크립트가 DynamoDB 에서 만든다 |

## 대안

**누적값을 매번 보내기.** Sentry 처럼 세션 상태 전체를 매번 보내면 업로드 하나를 잃어도 다음 것이 채운다. 버렸다. CloudWatch 에
넣으려면 서버가 직전 값을 읽어 차이를 내야 하고, RTT 를 히스토그램으로 줄이면 중앙값이 구간 폭만큼 거칠어진다. 구간 값은 잃은
구간만 잃고, 뒤에 온 레코드가 있으면 잃은 것이 전송 순번의 빈자리로 보인다.

**세션이 끝난 뒤 한 번만 보내기.** 버렸다. 프로세스가 갑자기 죽으면 그 세션이 통째로 빠진다.

**호스트만 보내기.** 버렸다. 플레이어 쪽의 수립 전 실패(`STUN_DISCOVERY_FAILED`, 참가 실패)는 호스트가 모른다. 손실은 받는 쪽이
세므로 한 방향만 남는다. 사용자가 기다린 수립 시간은 플레이어 쪽 값이다.

**환경을 코드로 알아내기.** 게이트웨이 MAC 해시로 망을 묶거나 출발지 IP 의 ASN 으로 통신사를 가르는 안을 버렸다. 소유자에게
어느 망인지는 중요하지 않다. 앞의 것은 해시해도 되돌릴 수 있고, 뒤의 것은 서버에 데이터 파일을 둬야 한다.

**식별자를 대조하지 않기.** 버렸다. 인증이 없으므로 아무나 레코드를 넣을 수 있다. 방이 살아 있거나 만료된 지 하루가 안 된 동안
레코드가 오므로 받을 때 확인할 수 있다.

**ADR 0003 대안 2 와의 관계.** 그 대안은 텔레메트리가 제어 평면에 묻는 것이고 버린 이유는 제어 평면이 텔레메트리의 부하와 장애를
떠안는 것이었다. 이번 결정은 제어 서버 프로세스를 거치지 않고 그 테이블을 읽는다. 제어 서버가 멈춰도 대조는 돈다. 테이블의 읽기
용량은 나눠 쓴다. 서버 전체 초당 5건이면 많아야 초당 2.5 RCU 다. 그래서 그 대안을 다시 여는 것이 아니라 분리 2·3 의 문구를
좁히는 것으로 본다.

**거부하기.** 대조에 실패한 레코드를 받지 않는 안을 버렸다. 방을 세우기 전에 끝난 실패에는 대조할 방이 없다. 거부하면 실패가
빠져 성공률이 부풀려진다.

**공유 키 인증.** 버렸다. 키는 배포한 실행 파일에서 꺼낼 수 있다.

**용량을 제어 평면과 같게.** 텔레메트리 테이블도 25/25 로 두는 안을 버렸다. 무료 용량은 계정 단위라 넘는 만큼 요금이 붙는다.
텔레메트리만 on-demand 로 두는 안도 버렸다. 적지만 요금이 0 이 아니다.

**마지막 업로드를 3초 기다리기.** join 상한을 3초로 늘리는 안을 버렸다. 콘솔 창 닫기와 로그오프에서는 Windows 가 정리 직후
프로세스를 끝내므로 늘려도 소용이 없고, 다른 경로만 종료가 늦어진다.

**그래프를 서비스가 그리기.** 그래프 라이브러리를 서비스에 넣는 안을 버렸다. NFR-5 의 교수 승인이 필요하고 t3.micro 의 CPU
크레딧을 쓴다.

**CloudWatch 에 차원 두기.** 매핑 거동이나 동일 LAN 여부를 차원으로 두는 안을 버렸다. 이름과 차원 값의 조합 하나가 지표
하나라 무료 한도 10개를 바로 넘는다. 환경은 대시보드의 시간 범위로 고른다.

## 결과

**얻는 것.**

- 클라이언트의 업로드 경로가 지금 격리 구조(`concurrency.md` 6장) 그대로 들어간다
- 서버는 더하기만 하므로 덮어쓰기와 순서 판정이 없다
- 그래프에 새 의존성이 없다. `boto3` 는 이미 승인됐다
- 수집 항목에 개인을 가리키는 값이 없다

**치르는 것.**

- 업로드 하나를 잃으면 그 구간의 값이 사라진다. 많아야 RTT 표본 열둘쯤이다
- 콘솔 창 닫기, 로그오프, 시스템 종료에서는 세션 끝 레코드가 자주 빠질 수 있다
- 인증이 없어 가짜 레코드가 들어올 수 있다. 대조는 방이 있는지만 본다. 살아 있는 방 코드를 아는 사람은 막지 못한다
- 같은 역할이라 제어 서버 프로세스도 텔레메트리 테이블에 쓸 수 있고 텔레메트리 서비스도 제어 평면 테이블을 읽는다
- 제어 평면 테이블의 용량이 25 에서 20 으로 준다. 실측 최대 읽기 7.1, 쓰기 2.6 보다는 크다
- CloudWatch 에서는 조건별로 나눠 보지 못한다. 정확한 표는 분석 스크립트를 돌려야 나온다
- CloudWatch 의 1분 데이터는 15일 뒤 5분 단위로, 63일 뒤 1시간 단위로 합쳐진다. 원본은 DynamoDB 에 남는다

**확인하지 못한 것.**

- t3.micro 에서 위 systemd 제한과 입력 상한이 두 서비스를 함께 버티는지. 배포 뒤 부하를 걸어 확인한다
- CloudWatch 대시보드의 백분위수가 `experiments.md` 에 실을 만큼 정확한지. 분석 스크립트의 값과 한 번 대조한다
