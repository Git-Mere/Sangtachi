# 0040. 목적지 의존 매핑을 에뮬레이션해 통제 조건으로 잰다

- 상태: 채택
- 날짜: 2026-11-18
- 관련: [`../roadmap.md`](../roadmap.md) Phase 9 테스트 환경, [`../architecture.md`](../architecture.md) 8장, [`../spec.md`](../spec.md) A-2·M-4, [ADR 0001](0001-직접-연결-대비책-미도입.md)

## 맥락

`roadmap.md` Phase 9 는 성공률을 관측된 매핑 거동별로 비교하라고 한다. 테스트 환경 표의 "가용한 다른 NAT 거동" 이 그 칸이다. 지금까지 잰 실제 환경은 모두 두 STUN 서버에 같은 공인 포트를 돌려줬다. 목적지에 따라 포트가 바뀌는 망은 하나도 없어 비교의 한쪽이 비었다. 저장소 소유자는 그런 실제 망을 구하기 어렵다고 했다.

ADR 0001 은 NAT 에뮬레이션 테스트베드(대안 A)를 기각했다. 그 안은 실제 환경 증거를 대신하는 것이었고, 그러려면 M-4 의 "지원 NAT 환경" 정의를 넓혀야 했다.

## 결정

**목적지 의존 매핑을 Linux NAT 으로 만들고, 그 결과를 통제 조건으로만 쓴다.**

| 자리 | 정한 것 |
|------|---------|
| 만드는 법 | `mere-galaxy` 안에 네트워크 네임스페이스를 두고, 밖으로 나가는 패킷에 `iptables` 의 `MASQUERADE --random-fully` 를 건다. 연결마다 공인 포트를 무작위로 고르므로 목적지마다 매핑이 바뀐다. 그 뒤에 집 공유기가 한 번 더 NAT 한다 |
| 시작 조건 | 시행 전에 네임스페이스 안 클라이언트의 두 STUN 결과 포트가 다른지 본다. 같으면 돌리지 않는다 |
| 역할 | 네임스페이스 안 클라이언트가 플레이어, 상대는 실제 망의 호스트다 |
| 집계 | `tools/tm-analysis` 묶음 파일의 종류를 `controlled` 로 적는다. 실제 환경의 성공률, 실제 환경을 합친 표, M-4 의 지원 범위 주장에 넣지 않는다 |
| 보고 | `experiments.md` 에 에뮬레이션이라고 밝히고 실제 환경 표와 나눠 싣는다 |
| 정리 | 시험이 끝나면 네임스페이스와 규칙을 지운다 |

ADR 0001 을 뒤집지 않는다. 그 ADR 이 기각한 것은 에뮬레이션을 실제 환경 증거로 쓰는 것이다. 이 결정은 에뮬레이션을 비교의 통제 조건으로만 쓴다.

## 대안

| 안 | 내용 | 기각 사유 |
|----|------|-----------|
| A | 실제 망을 찾을 때까지 기다린다 | 소유자가 구하기 어렵다고 했다. 비교의 한쪽이 끝까지 빌 수 있다 |
| B | 분석 도구에 에뮬레이션용 종류를 따로 더한다 | 한 묶음을 위해 도구와 시험을 바꾼다. `controlled` 가 이미 실제 환경과 따로 집계된다 |
| C | 에뮬레이션 결과를 실제 환경처럼 센다 | ADR 0001 대안 A 와 같은 이유로 안 된다 |

## 결과

**얻는 것.** 매핑 거동별 비교에 목적지 의존 쪽 사례가 생긴다. 실패하면 그 실패 코드가, 성공하면 어떤 경로로 붙었는지가 기록된다.

**받아들이는 한계.**

- 실제 장비가 아니다. 네임스페이스의 연결 추적은 응답이 정확히 같은 주소와 포트에서 올 때만 들여보낸다. 그래서 가장 엄격한 필터링을 함께 만든다. 어떤 실제 장비의 거동과 같다고 말하지 않는다
- 집 공유기 뒤의 이중 NAT 이다
- 한 기기, 한 상대, 같은 날의 반복 측정이다. 일반화하지 않는다
