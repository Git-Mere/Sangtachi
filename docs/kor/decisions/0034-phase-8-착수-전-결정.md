# 0034. Phase 8 착수 전 결정

- 상태: 채택
- 날짜: 2026-10-29
- 관련: [`../roadmap.md`](../roadmap.md) Phase 8, [`../concurrency.md`](../concurrency.md) 1장·7장, [`../architecture.md`](../architecture.md) 3.5, [`../control_plane.md`](../control_plane.md) 6.4, [`../windows-prereq.md`](../windows-prereq.md) 1절·4절·14절, [`../experiments.md`](../experiments.md), [ADR 0001](0001-직접-연결-대비책-미도입.md), [ADR 0007](0007-gui-핵심-범위-qt.md), [ADR 0030](0030-기동-입력과-콘솔-화면.md)

## 맥락

`roadmap.md` Phase 8 은 착수 전에 정할 것을 다섯 둔다. GUI 스레드 모델, GUI 가 쓰는 기동 입력 경로, GUI 조작과 제어 평면 속도
제한의 관계, 권한 승격과 잔존물 정리 시점, Qt 런타임의 배포 형태다. 문서를 읽으면서 빈칸이 더 나왔다.

- T-7 의 마지막 조건은 플레이어가 다른 플레이어의 상태를 보는 것이다. 그 정보는 호스트가 보내는 명부(`protocol.md` 5.7
  ROSTER)로만 온다. 그래서 기기가 세 대 필요하다. 한 기기에 두 프로세스를 띄울 수 없다. 어댑터 GUID 가 상수라 둘째가 기동에
  실패한다(ADR 0027)
- 플레이어가 끊기면 명부의 연결 비트가 먼저 0 이 되고, 호스트가 `host_report` 로 이탈을 알린 뒤 그 멤버가 명부에서 빠진다.
  화면이 그 두 단계를 어떻게 보이는지가 없다
- 측정 기준표는 게임 표시 지연을 화면에서 읽는다고만 한다. 바닐라 Minecraft 의 Tab 목록은 막대만 보이고 숫자가 없다
- Phase 8 결과를 싣는 `experiments.md` 가 Phase 9 산출물이라 아직 없다

저장소 소유자는 2026-10-28 에 `field-kit-p7b` 로 Minecraft 세션을 한 번 돌렸다. 결과는 `experiments.md` 3.1 에 있다.

## 결정

저장소 소유자가 자리마다 아래를 골랐다.

| 자리 | 고른 것 |
|------|---------|
| 작업 순서 | Minecraft 검증은 `field-kit-p7b` 로 먼저 한다. GUI 는 그 뒤다. GUI 시험과 T-7 은 새 키트 `field-kit-p8` 로 한다 |
| T-7 의 기기 | 세 대. 호스트 하나와 플레이어 둘 |
| 시연 망 | 호스트는 학교에서 소유자의 휴대폰 핫스팟, 플레이어는 집 Wi-Fi |
| GUI 스레드 | Qt 스레드가 프로세스 주 스레드다. `[loop]` 는 작업 스레드로 간다. GUI 스레드는 `[console]` 의 자리를 맡아 같은 명령 큐에 명령을 넣는다. `[loop]` 에서 GUI 로 가는 것은 새 큐 하나다 |
| 실행 파일 | GUI 는 별도 대상 `sangtachi_gui.exe` 다. Windows 서브시스템이라 콘솔 창이 없다. 콘솔 대상은 시험과 현장 키트에 남긴다. 배포물에는 콘솔 실행 파일을 넣지 않는다 |
| 서버 주소 | 빌드 기본값만 쓴다. 창에 칸을 두지 않는다. 기본값이 빈 채로 GUI 대상을 설정하면 설정이 멈춘다 |
| 이름 | 칸에 기본 이름을 미리 채운다. 사람이 고칠 수 있다 |
| 방 코드 | 표시하고 복사 버튼을 붙인다 |
| 실패 표시 | 창 안의 상태 줄에 코드, 상대, 문장을 보인다. 실물을 본 뒤 소유자가 다시 정할 수 있다 |
| 속도 제한 | 미결 제어 요청이 있는 동안 방 만들기와 참가 버튼을 끈다. 받은 실패는 그대로 보인다. 창 쪽 대기 시간을 따로 두지 않는다 |
| 승격 거부 | 관리자 권한 매니페스트를 유지한다. 거부하면 Windows 가 프로세스를 만들지 않으므로 창이 뜨지 않는다 |
| 잔존물 정리 시점 | 창을 먼저 띄운다. 준비가 끝날 때까지 `Loading...` 을 보이고 버튼을 끈다. 잔존물 정리와 어댑터 준비는 작업 스레드가 한다 |
| 기동 실패 | 대화 상자에 `ERROR` 줄과 로그 파일 이름을 보이고 닫으면 끝난다 |
| 창 닫기 | 확인 없이 종료한다. 정리가 끝날 때까지 `Closing...` 을 보인다 |
| Qt | Qt Widgets. 버전 6.12.0. 공식 온라인 설치기로 받는다. 동적 링크와 `windeployqt` 로 배포물을 만든다. 라이선스는 LGPLv3 다. 승인 범위에 이것이 들어간다고 소유자가 전했다 |
| 멤버 목록 | 명부를 그대로 보인다. 연결 비트로 두 상태를 보이고 명부에서 빠진 멤버는 줄을 지운다. 가상 IP 칸을 둔다 |
| GUI 시험 | 표시 로직은 Qt 없는 C++ 로 두고 Catch2 로 시험한다. 위젯은 사람이 손으로 확인한다 |
| Minecraft | Java Edition, 런처의 버전 표기 26.3 |
| 게임 표시 지연 | F3 디버그 화면의 네트워크 그래프에서 읽는다. 소유자가 26.3 에서 그래프가 뜨는 것을 봤다 |
| 결과 문서 | `experiments.md` 를 지금 만든다. Phase 8 결과부터 싣는다 |
| 시연 전 확인 | `tools/nat-probe` 재측정 대신 시연과 같은 망 쌍에서 클라이언트로 리허설한다. 며칠 전 한 번, 당일 한 번이다. 리허설이 실패하면 nat-probe 로 원인을 가른다. ADR 0001 의 Phase 8 준비와 시연 직전 재측정을 대신한다 |
| 시연 망의 매핑 수명 | 호스트의 휴대폰 핫스팟과 플레이어의 집 Wi-Fi 둘 다 잰다. 플레이어의 집은 이미 잰 두 집이 아니다 |
| Wi-Fi 끊김 | 플레이어 쪽 Wi-Fi 를 약 10초, 약 60초 끄고 거동을 기록한다. 판정하지 않는다 |
| 3초 측정 | 콘솔 빌드의 창 닫기와 GUI 빌드의 로그오프를 둘 다 잰다 |
| 스스로 끝날 때 | 사람이 닫지 않았는데 `[loop]` 가 끝나면 기동 실패와 같은 대화 상자를 보인다 |
| 블록과 채팅의 기준 | "20회씩 전부 2초 이내" 를 "눈에 띄는 지연이 없다" 로 바꾼다. 소유자가 직접 보고 판정한다 |
| 멤버 목록의 자기 줄 | 자기 줄에 `(you)` 를 붙인다 |
| 배포물 | 창에 쓰지 않는 Qt 구성요소는 넣지 않는다. VC++ 런타임은 설치 파일 대신 DLL 을 실행 파일 옆에 넣는다 |
| 배포 GUI 빌드 | 서버 주소를 넣어 만든다. 평소에 쓰는 GUI 빌드도 이것이다 |
| 화면 큐를 읽는 때 | `[loop]` 는 `[gui]` 를 깨우지 않는다. `[gui]` 가 100ms 마다 타이머로 읽는다 |

## 대안

**GUI 스레드.** 스레드 하나로 두고 `[loop]` 의 대기를 `MsgWaitForMultipleObjects` 로 바꿔 Qt 이벤트도 그 안에서 처리하는 안을
버렸다. 창을 끌거나 크기를 바꾸면 Windows 가 모달 루프에 들어가 그동안 `[loop]` 가 멈추고 keepalive 도 멈춘다. GUI 실행 파일이
지금 콘솔 클라이언트를 자식 프로세스로 띄우고 표준 입출력으로 대화하는 안도 버렸다. 코어를 건드리지 않는 장점이 있었다. 대가는
명부, 가상 IP, 로비 복귀를 새 표준 출력 줄로 내야 하고 두 프로세스의 종료를 맞춰야 하는 것이다.

**배포물.** `windeployqt` 의 기본 옵션 그대로 두는 안을 버렸다. 58개 파일 약 94MiB 가운데 60MB 넘게 창이 쓰지 않는 것이었다.
VC++ 런타임 설치 파일(`vc_redist.x64.exe`)을 넣는 안도 버렸다. 사용자가 따로 실행해야 하고, 실행하지 않으면 넣은 의미가 없다.

**화면 큐를 읽는 때.** `[loop]` 가 넣은 뒤 Qt 의 큐 호출로 `[gui]` 를 깨우는 안을 버렸다. Qt 가 그 호출 안에서 이벤트 큐 잠금을
잡아 `[loop]` 에 락이 들어온다(`concurrency.md` 6장). `[loop]` 가 Win32 `PostMessage` 로 창에 알리는 안도 버렸다. 즉시 반영되지만
창 핸들을 `[loop]` 쪽에 넘기고 `platform/` 에 이음새를 하나 더 둬야 한다. 대가는 화면 반영이 최대 100ms 늦는 것이다.

**실행 파일.** 실행 파일 하나에 모드를 두는 안을 버렸다. 콘솔 서브시스템과 Windows 서브시스템을 한 파일이 가질 수 없다.

**서버 주소.** 창에 칸을 두는 안을 버렸다. 제어 서버는 하나이고 주소가 고정이다(ADR 0030).

**이름.** 빈 칸으로 두고 반드시 입력하게 하는 안을 버렸다. 기본 이름이 이미 있다(ADR 0030).

**실패 표시.** 대화 상자를 버렸다. 창이 하나 더 생기고 닫아야 다음 조작을 할 수 있다.

**속도 제한.** 실패 뒤 창 쪽에서 몇 초 버튼을 막는 안을 버렸다. 문서에 없는 값을 하나 더 정해야 한다. 서버의 예산은 실패 응답만
세므로 정상 조작은 예산을 쓰지 않는다(`control_plane.md` 6.4).

**승격 거부.** 매니페스트 없이 띄우고 관리자가 아니면 다시 실행하는 버튼을 보이는 안을 버렸다. ADR 0030 대안 6 을 GUI 에만 다시
여는 것이고, 다시 실행하는 경로의 코드가 생긴다.

**잔존물 정리 시점.** 준비를 끝낸 뒤 창을 띄우는 안을 버렸다. 몇 초 동안 화면에 아무것도 없다.

**창 닫기.** 방에 있을 때 확인 창을 띄우는 안을 버렸다. FR-15 밖의 화면이다.

**Qt.** Qt Quick(QML)을 버렸다. QML 엔진과 Quick 모듈이 배포물에 더 붙는다. 정적 링크를 버렸다. Qt 를 직접 정적으로 빌드해야 하고
LGPLv3 의무가 무거워진다.

**멤버 목록.** 명부에서 빠진 멤버를 "나감" 으로 남기는 안을 버렸다. 창 쪽에 명부에 없는 상태가 생긴다. 명부는 표시 전용이고
화면은 그것을 그대로 보인다는 규칙(`protocol.md` 5.7)과 어긋난다.

**GUI 시험.** Qt Test 로 위젯까지 자동 시험하는 안을 버렸다. 판정이 필요한 것은 표시 로직이고 그것은 Qt 없이 시험한다.

**시연 전 확인.** nat-probe 재측정을 그대로 두는 안을 버렸다. 지금 클라이언트는 같은 소켓으로 STUN 서버 두 곳에 묻고 실제로
홀펀칭한다. 리허설은 그 위에 어댑터, 방화벽, 제어 서버, Minecraft 까지 같이 본다. nat-probe 만 보는 것은 필터링 시험과 실패
원인 구분이고, 그것은 리허설이 실패했을 때 쓰면 된다.

**블록과 채팅의 기준.** 20회씩 2초 안을 그대로 두는 안을 버렸다. 원격의 두 화면에서 2초를 재려면 녹화와 시계 맞추기가 필요하다.
이 시험이 보려는 것은 게임이 원활하게 진행되는지다.

**게임 표시 지연.** 멀티플레이 서버 목록의 막대에 마우스를 올려 읽는 ms 를 버렸다. 새로고침마다 표본 하나이고, 플레이 중의
같은 구간을 재는 것이 아니다.

## 결과

**얻는 것.**

- `[loop]` 의 단일 소유 규칙이 그대로 간다. GUI 스레드는 `[console]` 처럼 큐 한쪽 끝만 쥔다
- 콘솔 빌드의 표준 출력과 시험이 그대로 간다
- Minecraft 검증이 Phase 7 파일 전송과 같은 터널 빌드로 돈다. NFR-2 의 조건이다

**치르는 것.**

- GUI 빌드에서는 `[loop]` 가 주 스레드가 아니다. `concurrency.md` 1장이 빌드마다 다른 구성을 적는다
- GUI 빌드에는 콘솔 제어 신호가 없다. 창 닫기와 로그오프를 따로 받아야 한다
- 승격을 거부한 사람은 아무 안내도 보지 못한다
- T-7 에는 기기 세 대와 사람 셋이 필요하다
- 반영 시험은 숫자 기준이 없어 사람의 판단에 기댄다
- 배포물에 Qt 와 VC++ 런타임이 붙는다. 약 30MB 다(`windows-prereq.md` 4절 Qt 런타임)

**확인하지 못한 것.**

- Qt 와 VC++ 런타임을 설치하지 않은 PC 에서 배포물이 뜨는지. `windows-prereq.md` 4절 Qt 런타임의 통과 조건이다
- F3 네트워크 그래프 값의 표시 해상도. 측정 기준표의 허용 폭이 그 값을 쓴다. 첫 측정 때 적는다
